### T2: Ambient creation syscalls remain

*(area security, horizon long, risk M)*


#### Shortcut

**Ambient creation syscalls remain**: any process may `vmo_create`, `socket_create`, `channel_create`, `event_create` (bounded by its handle table and the global object cap) and `debug_write`; `process_create` is ambient but limited by the caller's job (a program's job allows no further process).

#### Why it was acceptable

Needed by every program; the dangerous ones (processes, threads, memory) are now job-limited.

#### Proper fix, and when

Gate object creation by the job's object quota (T1); restrict `debug_write` to a console capability.

### T3: Trusted programs (`ls`, `cat`) get a standing read-only root

*(area security, horizon long, risk M, fixed_by [S10-MANIFEST])*


#### Shortcut

**Trusted programs (`ls`, `cat`) get a standing read-only root** via `/etc/trusted` (S4 spec section 8). Contradicts least privilege in spirit, though allowed by OD20; and the list is baked into the read-only boot image at build time, so it is hardcoded in practice, not a user-editable config as OD20 intends (product owner accepted this for S4).

#### Why it was acceptable

Lets the S4 acceptance session use absolute paths without a powerbox protocol.

#### Proper fix, and when

**True powerbox**: the shell opens the path arguments itself and passes just those handles (argument syntax that references handles), no standing root; `/etc/trusted` goes away. With the manifest-driven shell (S10).

### T5: `MANAGE` is coarse

*(area security, horizon long, risk M)*


#### Shortcut

**`MANAGE` is coarse** (map, start, thread_create on a process). A kill-only right (`KILL`, S4a-1) now exists, but process rights are not otherwise split as OS-ARCHITECTURE section 9 wants (start, kill, read/write memory separate).

#### Why it was acceptable

Enough for S4.

#### Proper fix, and when

Split `MANAGE` (start / map / threads / debug-memory) when a second consumer needs it; at the latest before ported software.

### T29: `GetVmo` hands out the whole boot image

*(area security, horizon long, risk L)*


#### Shortcut

**`GetVmo` hands out the whole boot image** (read-only) plus the file's extent: any client allowed to read a boot-image file can read every other boot-image file.

#### Why it was acceptable

The image holds only public programs and fixtures.

#### Proper fix, and when

VMO slices/children (`vmo_create_child`) so a file's VMO is exactly that file.


#### Note (2026-11-24)

Checked against the code: `memfsd` still duplicates the whole boot image VMO for `GETVMO` (`init/src/bin/memfsd.rs`, "The whole boot image, read-only"). The proper fix is now buildable, because `vmo_create_child` exists (MM8), but nothing uses it for this yet.

### T58: The shared-memory rule of slice V is scoped to jobs (review of PR #102)

*(area security, horizon long, risk M)*


#### Shortcut

**The shared-memory rule of slice V is scoped to jobs (review of PR #102).**

- (1) A hostile peer in the *same* job, or a sibling job under a shared ancestor limit, can still hand over a lazily committed VMO whose touch kills the toucher, and the recipient has no COMMIT to defend itself
- (2) the page-table frames a first touch of a mapped committed VMO needs are taken at fault time (`process_map` charges the job for tables but reserves no frames), so a touch can still fail when frames run out
- (3) `vmo_write` commits pages with only WRITE, charging the creator, with no rollback on a partial failure
- (4) `rt::heap` now commits each 256 KiB chunk when it grows, so accounting moves from touched to mapped pages, and no test fails if the heap commit is removed
- (5) `COMMIT` is part of the default `Rights::VMO`, the wrong default (safe today only because every handle handed out is explicitly narrowed).

#### Why it was acceptable

Closes the cases the design review (D3) named: a client at its quota handing a server a VMO, and a server's VMO spent by a client, between different jobs.

#### Proper fix, and when

Build the tables and PTEs in `process_map` for foreign mappings; reject or commit-first in `vmo_write`'s partial failure; a QEMU test of an rt program in a tight job that must get a null from the heap, not a fault; take COMMIT out of the default VMO rights; move the V1 predicate into `kcore` so a host test can mutation-check it.

### T148: The independent review of the spawn, signal, terminal and attribute work (2026-11-17 night, fresh context): findings

*(area security, horizon long, risk M, blocked_by [Q-SIGINT])*


#### Shortcut

**The independent review of the spawn, signal, terminal and attribute work (2026-11-17 night, fresh context): findings.** *Fixed in PR 229:* `vfork` made every writable file of the parent append for good (now only the child's copy is, and the parent's offset moves past what the child wrote); an oversized or handle-carrying message on a program's signal channel kept the channel readable and the shell spinning, and the read loop was unbounded (now 8 per pass, 64 bytes and 8 handles, handles closed); `E2BIG` on a spawn leaked the three duplicated handles; `mmap` of a huge length wrapped; `memfsd` refused `chmod`/`chown`/`fsync` on a directory (now exempt from the file/directory gate as `fsd` is). *Open:*

- (1) **a program can hold Ctrl-C off for ever**: it sends `H,2,1` ("I handle SIGINT") and never waits, so `HoldForeground` leaves the console server nothing to kill and the signal is never delivered (the T31 guarantee and OD118's "Ctrl-C ends the chain" do not hold against a hostile program); a fix needs a policy (a second Ctrl-C within a second kills, or a deadline on the hold)
- (2) in non-canonical mode with ISIG `consoled` sends `Interrupt` but not `JobInterrupt` (both `kill` and `interrupt` are set), so a cbreak program with a SIGINT handler (`less`) never gets Ctrl-C
- (3) *fixed 2026-11-18 (OD120)*: the mount intersection with the asker was by mount *name*, not by volume: a policy mapping one name to different volumes for two programs, or a trust mount named `/tmp`, `/dev` or `/proc`, lets a child get what its asker did not hold (`parse_trust` bans only `/` and `.`)
- (4) the pipe-read, `poll_read` and write loops serve brokers but never the console control channel, so during a capture or pipe into the shell `JobInterrupt` is not read
- (5) SIGINT goes to the foreground roots only: a root that handles it (a shell waiting on a child) does not pass it down
- (6) a signal forwarded by an `exec` forwarder to a depth-5 program is dropped
- (7) a write-only connection's `FSTAT` now carries mode, owner and time, which `ATTR_GET` would need READ for (decided: POSIX `fstat` needs no access)
- (8) a message on a program's signal channel larger than 64 bytes or with more than 8 handles still cannot be read (the program is the only one hurt, but the shell polls it each pass); `memfsd` has no `ATTR_LIST`.

#### Why it was acceptable

The review found no kernel invariant broken; all of it is userland.

#### Proper fix, and when

The policy decisions (1),

- (3) and
- (5) are the owner's; the rest are small slices.

### T186: HD1 leftovers: the Zkr path is unexercised and its traps are unhandled; the original tree keeps the seeds; the key derivation leaves intermediates on the stack

*(area security, horizon long, refs [HD1])*


Left from the Fable review of HD1 (2026-11-20), after the fixes in the PR (the pool keyed in place and the key wiped, `seeded` needing 16 bytes of real seed, the hart matched by the last `reg` cell, `below` giving up when the source refuses, the seeds scrubbed in a heap copy before the single VMO write). (1) The `seed` CSR read is an illegal instruction in S-mode if M-mode has not set `mseccfg.SSEED` (or a virtual-instruction trap under a hypervisor), so a machine whose ISA string lists Zkr but whose firmware does not allow the read panics at boot instead of falling back; QEMU's `rva23s64` has no Zkr, so the path has never run. Proper fix: a trap-and-skip window around the read (the trap handler already decodes the faulting instruction) or a probe through SBI, and a pause in the retry loop. (2) The original device tree stays in memory with the seeds for the whole run (user space cannot reach it: RAM is cut from every device window, `kcore::devwin`); zero them in place once the kernel table maps the tree writable, or copy the tree. (3) `derive_key` leaves its SHA state and HKDF intermediates in dead stack; the generator's key is wiped, the intermediates are not. (4) The self-test `the_entropy_pool_is_seeded_as_the_tree_says` assumes a machine with no Zkr. Why acceptable: one target, QEMU, whose tree carries the seed and whose CPU has no Zkr; the stack is the boot stack of a kernel with no user code on it. Risk: a hardware port finds (1) first.

### T234: The runtime heap's base is derived from the randomised stack and image addresses, not drawn from the kernel's entropy

*(area security, horizon long, refs [HD2, HD1])*


**What.** `rt::heap::pick_base` hashes the stack and image addresses (both placed at random by the kernel) into a page of the 4 GiB window below the mapping arena. **Why acceptable.** A program has no entropy source before `rngd`, the kernel gives it no word at startup, and the hash makes the heap move on every launch (the acceptance asks for that). **Risk.** One leaked address (stack or image) plus the hash function determines the heap base: the heap is not an independent draw. **Proper fix.** The kernel puts one random 64-bit word in the first thread's startup registers (or a startup-message field the launcher cannot forge: the kernel-started process gets it in its bootstrap message), and `rt` seeds the heap base, the `thread_spawn` hint and any later placement from it. A syscall or startup ABI change: do it with the next flag day (see T213).

### T138: The boot image is held in several copies

*(area platform, horizon long, risk M)*


#### Shortcut

**The boot image is held in several copies** (2026-11-17): the kernel embeds it, and by the numbers about 3.7 copies of `/bin` sit in memory after boot (the memory file server keeps file data in its heap, T16, and other servers hold parts): with symbol tables the user programs were 24.6 MB on a laptop and 50.2 MB on CI's machine and the shell test's memory hog found 26 MiB of heap left on CI instead of 120. Stripping the symbol tables (`--strip-all`, was `--strip-debug`) took `/bin` to 5.3 MB and the copies to a size nobody notices, but a bigger image (a port such as `sqlite`, `tcc`) will bring the problem back.

#### Why it was acceptable

Found by running the shell test on CI for the first time.

#### Proper fix, and when

Serve `bin/` from VMOs shared with the loader (`GetVmo` for everything, T16) so a program is in memory once; show the boot "frames free" and the image size in every serial test's output (done).

### 2. Design, with the alternatives rejected

**T29 (and step 1 of T138): one VMO per file.**
1. `proto::bootimg`: file data starts on a 4096-byte boundary and the gap is zeros; the parser's alignment rule follows (`BadOffset` for anything else). The builder is `kernel/build.rs`; find every other reader with `grep -rn bootimg`.
2. `memfsd` `GETVMO`: on first use per node, `vmo_create_child(image, off, round_up(len, 4096), 0, PRIVATE)`, narrowed to `READ | MAP | DUPLICATE | TRANSFER` and cached in a map by node; later requests duplicate the cached handle. The reply keeps its shape: `a` is now the offset inside the child (0), the payload the length.
3. Clients are unchanged (`get_vmo` returns `(vmo, off, len)`); the suite's two checks keep passing with `off == 0`.
- Rejected: a fresh VMO filled by copy per request (one more copy of every program: against T138); a page-granular child with no format change (leaks neighbours' bytes); a SNAPSHOT child (must be in the source's job, which is the kernel's, and write-protects the source's translations for nothing); a child per request with no cache (a client can spend `memfsd`'s object quota).

**T138 step 2: a program is in memory once.** `rt::spawn` gets `spawn_from_vmo(file_vmo, len, ...)`: read the ELF header and program headers with `vmo_read`, make **one PRIVATE child of the file in the program's job** (`vmo_create_child(file_vmo, 0, pages, job, PRIVATE)`; the child carries full rights, EXECUTE included, so no kernel change), and `process_map` each `PT_LOAD` from it at its file offset: text and read-only data share the image's frames, a write to the data segment copies into the child (charged to the program's job, COW2). Zero the tail of the last file page of a segment with `memsz > filesz` (`vmo_write` of zeros into the child) and back the rest of `.bss` with an anonymous VMO as now. Fall back to today's copy when a segment's `p_offset` and `p_vaddr` disagree modulo 4096. The launcher calls it with the handle it is already sent.
- Rejected: mapping `memfsd`'s child directly (its job is neither the launcher's nor the program's and a PRIVATE child has no pages of its own, so V1 refuses the map: `ksys/src/proc.rs:943`); giving the image handle EXECUTE in the kernel (not needed); building the image VMO over the kernel image's own frames to save the kernel's second copy (M5: the kernel image is never reachable from a user mapping); waiting for `S11-MMAP` or `DL1` (they need exactly this primitive; build it here, they reuse it).

**T234: an independent draw without an ABI change.** `pick_base` maps a one-page lazy VMO with `ANYWHERE`, notes the address the kernel chose, unmaps it, and derives the heap page from that address alone (same mixer, same window). `place_anywhere` draws from the kernel's generator (`ksys/src/proc.rs:749-771`), so the base no longer follows from the stack or image address; `rt/src/spawn.rs:304` already uses this probe. Fixed-address programs keep `HEAP_BASE`; `aslr=off` stays deterministic because the placement is first-fit then. Seed the `thread_spawn` hint the same way only if it is still derived in `rt` (check). Rejected for now, and put to the owner (question 5): a random word in `a3` at start (KERNEL-V1-SPEC 3.7 lists the registers and 7.1 says the generator "serves address choices inside the kernel only").

**T58 (3): `vmo_write` is all or nothing.** In `Vmos::access`: count the pages the write would commit, refuse at once when the job's room or the free frames cannot cover them (as `commit` does), reserve the undo list before the first frame, and on a failure give back exactly the pages this call committed. Rejected: commit-first through `Vmos::commit` (it refuses pager VMOs' semantics and takes no write fault, so it would not break copy-on-write); leaving it and documenting it (V2's wording already promises all-or-nothing for the sibling call).

**T58 (2): a stranger's mapping needs no frame at touch time.** When `process_map` takes the V1 branch (VMO of a third job, range committed), build the leaf tables for the range in the same call (empty, no PTEs), all or nothing, before the region is recorded; the charge is the existing estimate. Rejected: installing every PTE at map time (a long call under `AS` and `VMO` for a large range; needs chunking and a restart protocol); a frame reservation per address space for tables (new accounting; KERNEL-V1-SPEC 4.7's reservation is for data pages).

**T186.** (1) A pure `rngcore::zkr::collect(read: impl FnMut() -> Option<u32>, pause: impl FnMut())` holds the retry loop (ES16, WAIT and BIST retried with a pause, DEAD or `None` ends it); the kernel's `seed_csr_read` becomes fallible: the trap handler, on an illegal-instruction or virtual-instruction trap from S-mode whose `sepc` is the one labelled `csrrw` instruction, sets a per-hart flag and steps over it. (2) After the pool is keyed, zero `rng-seed` and `kaslr-seed` in the tree in place and record in the pool what was there (lengths, non-zero or not, Zkr bytes read). (3) `Sha256` and the HKDF helper get a `wipe` called on every exit of `derive_key`. (4) The self-test compares `seeded()` with the pool's own record, Zkr included. Rejected: an SBI probe (no SBI call reports `mseccfg.SSEED`); copying the tree (the original still holds the seeds).

**T148 (2), (4), (6), (8) and `ATTR_LIST`.** (2) `after_input` sends `JobInterrupt` whenever a job is in the foreground and the input asked for a kill, cbreak or not. (4) `bind_served` binds the control channel and `serve` calls `poll_ctl`. (6) A forwarder passes a signal on whatever its depth, or the limit is raised to the depth limit of spawn itself. (8) A message too large to read is drained with a truncating read (or the channel is closed and the program told). `memfsd` answers `ATTR_LIST` from `memfs` as `fsd` does.

**T58 (4).** Mutation-check once: delete the `vmo_commit` at `rt/src/heap.rs:170`, one `make kquick` of `job_memory_limits_stop_a_hog_and_are_credited_back`. If it fails, strike (4) with the result. If it survives, add a suite test: an `rt` program in a job with a tight page limit that must print a refused allocation and exit normally.

### 5. Invariants, locks, and how each change can go wrong

Lock order in force (SCHED-SMP-SPEC amendment for L20; `klock::Class`): `OBJ` 1, `AS` 2, `PROCS` 3, `FUTEX` 4, `VMO` 5, `JOBS` 6, `PI` 7, `TT` 8, `RQ` 9, `KSTACK` 10, `FRAME` 11, `HEAP` 12, `ENTROPY` 13, `UART` 14.

| PR | Rows | Subtle failure |
|---|---|---|
| A | H3, COW1 to COW3, ML1, J5, M9 | The cached child lives in `memfsd`'s job: without the cache it is a quota drain; with it, a closed client must not close the cached handle. A PRIVATE child shows later writes of the source: harmless only because no handle to the image has WRITE (`kobjects.rs:238-245`); keep it so. Padding must be zeros or the last page leaks build-time bytes. The image format has several readers (`init`, `sessiond`, `memfsd`, the kernel's loader of the first process): one left on the old rule fails at boot, which no feature gate shows |
| A (heap) | KA1, spec 7.2 | The probe page must be unmapped on every path. The heap window lies below the mapping arena: derive only a page number from the probe, never use the address itself. A process at its region limit or with no memory gets no probe: fall back to today's hash, never to `HEAP_BASE` |
| A (console) | none in INVARIANTS; OD118, T31's guarantee | Sending `JobInterrupt` in cbreak mode must not also kill a job that handles SIGINT (`kill_jobs` runs first: check the order) or deliver the signal twice to a canonical-mode job |
| B (write) | V2, V3, J1, J2, J4, COW2, COW3 | The undo must give back only pages **this call** committed. A write that broke copy-on-write by taking a frame over (the "moves it" case, `aspace.rs:1034`) cannot be undone by freeing the frame: the family would lose data. Either undo before any takeover (pre-check, then commit copies only) or record the kind of each step. The page-index leaf charged to kernel bytes (T249) must be credited too. A pager VMO's `NeedPager` is not a failure to roll back twice |
| B (tables) | V1, J1, J2, M3, AS1, AS2, SMP5 | Tables are built under `AS` then `FRAME`: no `OBJ`, no allocation that takes `HEAP` out of order (K5). If the page-table code frees an empty leaf table when a neighbour is unmapped, the promise is lost silently: check `kcore/src/pagetable.rs` and pin it with the host test. The rollback of a failed `process_map` must free the tables it built and credit the charge exactly once |
| C | KA1, M5, D1, C2, lock class `ENTROPY` | The skip must match one `sepc` only, or it becomes a general "step over a kernel fault" hook (KERNEL-V1-SPEC 3.8 forbids test-only ones). **Zeroing the seeds can break later readers of the tree**: the early boot code derives the slide from `kaslr-seed` before paging (`kernel/src/arch/riscv64/boot.rs:106-231`); if a secondary hart's entry or the resume from suspend (PM3) runs that scan again, it would choose a different slide. Read both paths before zeroing; `kaslr_choice_follows_the_seed` (`selftest.rs:838`) probably reads the tree too. The tree may be mapped read-only in the kernel table: the write needs a mapping that M2 allows |
| D | M7, M9, COW1, COW2, V1, IC1, P3 | The loader is the trust boundary for a hostile ELF: every check `map_image` makes today (user half, no W+X, no overlap, in the file) must hold on the new path. A segment whose file page is shared with the next segment's first bytes must not expose them writable-and-executable. The program's startup code applies its own relocations (HD2): they land in the data segment and copy; a text relocation would fault, so refuse `DT_TEXTREL` at load. The first write charges the program's job: a program at its page limit now dies at a write to `.data` where it used to fail at spawn; decide whether to `vmo_commit` the data segment up front (the child's handle has COMMIT) |

## Decisions (2026-11-24, OD159)

Owner answers: (T5) split `MANAGE` now, additive bits; (T58 1) the job is the trust boundary, no recipient defence; (T58 5) `COMMIT` is opt-in at `vmo_create`; (T234) the ANYWHERE probe closes it; (T186 1) trap-and-skip accepted, `zkr=on` as a soak target; `/etc/trusted` frozen, T3 is the way out. Kernel PRs B and C may land before or after FZ1. Q-SIGINT (5) was not discussed and stays open. The plan's PR A (T29 as a per-file private child VMO, T234, T148 parts, T58 mutation check), PR B, PR C and PR D stand, with the `MANAGE` split and the `COMMIT` opt-in added as kernel work of their own (each its own PR with a Fable review, since both change rights).
