title: PL3: the user Rust build names three features the stable toolchain calls unstable (v, zfa, zvbb); the warning says it will become an error
refs: [PL3, OD127]
---

PL3 builds the user Rust programs with `-C target-feature=+v,+zvbb,+zba,+zbb,+zbs,+zicond,+zcb,+zfa,+zicbom,+zicboz,+zihintpause,+zkt,+zimop,+zcmop,+zawrs` (`init/.cargo/config.toml`). On the stable toolchain `rust-toolchain.toml` names, rustc prints "unstable feature specified for `-Ctarget-feature`: `v`" (and `zfa`, `zvbb`) at every build and says this "will become a hard error in a future release" (rust-lang/rust#162235). Why acceptable now: it is a warning, the pinned toolchain still accepts it, and the generated code is what the profile calls for. Risk: a toolchain update turns the build red. Proper fix, when it is due: either a nightly toolchain with `-Zallow-features`/a target specification for the user target (`build-std` is not needed for a tier 2 target), or a `-C target-cpu` that names the profile once LLVM and rustc have `rva23u64` as a CPU, or, if the features become stable, nothing. Also: the user Rust code is now free to use vector registers, so any program that is slow to start or large in vector state shows it in `thread_spawn` cost (the vector state is allocated at the first vector instruction, uncharged: T57).
