## Shortcut

**Gaps in the block-driver tests (S6b).** (The harness now checks the whole image from the host after QEMU exits, `check_disk`: it catches an address bug the guest's read-back cannot; mutation-checked. Flush is still unverifiable: QEMU's raw file writes land in the host page cache either way.) ReadOnly, Timeout (the driver exits 10), IoError and a client that never reads replies are untested; the leak checks cover the driver's own job (processes, pages) but not the DMA VMO, channels or interrupt object; the in-flight-kill test kills a driver with a queued write but cannot know the device was mid-request; acceptance 8's `blk_bad_requests` is folded into `blk_round_trip`.

## Why it was acceptable

The round trip, bad requests and restart all run on QEMU in both interrupt and polling mode.

## Proper fix, and when

A read-only device and a stalled device in the harness.
