## Shortcut

Shell job control (OD124) is the minimum that works: Ctrl-Z, `jobs`, `fg`, `bg`. Left out:

- (1) Ctrl-Z stops a program without running its SIGTSTP handler (the shell does not know which programs have one).
- (2) a background job that reads or writes the terminal is not stopped (SIGTTIN, SIGTTOU are not built): it competes with the shell for input and mixes its output with the prompt.
- (3) a background job that ended is reported by `jobs`, not at the next prompt, and stays unreaped until `jobs` is run or the session ends.
- (4) Ctrl-Z is honoured only while the shell waits for a program (`wait`); during the shell's drains and pumps (a pipeline whose output the shell captures or redirects) and while a shell function runs it is dropped.
- (5) `kill(pid, SIGSTOP)`, `SIGCONT` and `SIGTSTP` from a program, `waitpid` with `WUNTRACED` and `WCONTINUED`, and SIGCHLD for a stop are not built (the libc half of SIG2; the process object's `STOPPED` signal exists for it).

## Why it was acceptable

Each is a refinement; the interactive case (stop `spin`-like jobs, bring them back) works and is tested.

## Proper fix, and when

(5) next, as the libc half of SIG2; (1) with it; (3) with a prompt hook in the REPL; (2) when a program needs it; (4) when a real script needs it.
