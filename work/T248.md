**What.** Process teardown and kill (`request_kill`, the exit paths), exception delivery (`ksys/src/exception.rs`), the donation graph (`kcore::donate`), PI futexes (`kcore::pifutex`: four maps) and pager waits (`kcore::pager`) allocate with the infallible collections, inside `heap::nofail` (counted per file by `scripts/check_docs.py`, `NOFAIL`). None is in KT9's scenario list.
**Why acceptable.** Each runs for a thread or process that already exists and cannot be refused (a kill, a wake, a fault report); the allocator's reserve covers them (T247).
**Risk.** As T247: an estimate, defeated by fragmentation.
**Proper fix.** Prepay each from the thread record (`ksys::UThread`) or the process record at the R point that creates the thread, so that the later step allocates nothing; the `NOFAIL` row of the file then goes. When: with T247, or when one of them is opened.
