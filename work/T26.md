## Shortcut

**The user heap lock yields but is a spin lock held across several syscalls** while growing; one reserved range, no shrinking. (Since slice V the heap commits each chunk it grows, so frame or quota exhaustion is a failed allocation, not a fault on first touch; thread and main stacks and other lazily mapped memory still fault in their own job.)

## Why it was acceptable

One program thread today.

## Proper fix, and when

Per-thread arenas or a futex-style lock; account heap frames to a job (T1).
