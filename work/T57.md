## Shortcut

**FP state is uncharged kernel memory (slice A review).** A thread that uses floating point gets a 264-byte register box and a map node on its first FP instruction, allocated from the kernel heap without charge (running out is a kernel panic, not NO_MEMORY); it is bounded only by the thread limits (128 threads). `return_to_user` also takes the big lock and does a map lookup on every return to user mode, including light IPIs that took no lock before.

## Why it was acceptable

Bounded and small; the save and reload are correct.

## Proper fix, and when

Embed the FP state in the thread record and charge it to the job at `thread_create` (slice T, kernel memory charged to jobs); keep a per-thread flag so threads without FP state skip the lock and lookup; measure with the Lua benchmark.
