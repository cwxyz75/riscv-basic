## Shortcut

**`fsd` v0** (filesystem step 5c, part):

- (1) `fsd` is a copy of `memfsd`'s request handling on the other filesystem (about 500 lines twice): a generic file server over a small trait is the cleanup, deferred so the stable `memfsd` and its many tests stay untouched
- (2) inode times are wall time when `volmgr` gave a clock view, else nanoseconds since boot
- (3) one account tree, the same connection pool as `memfsd`, no per-client quota domain on the disk (FI5's rights half is the server's, and it is `memfsd`'s model)
- (4) `GetVmo` is refused (BAD_REQUEST), `ReadDir` reports a symlink as a file (T109 (2))
- (5) every 4 KiB block is one channel round trip to the driver (no cache, no batching: slow but simple; a cache is a later slice)
- (6) the commit interval (2 s after the first change) is a constant, and a block I/O error ends the request with `IO_ERROR` while the volume stays mounted (no read-only mode yet)
- (7) the QEMU test formats the disk itself with `fsfmt::mkfs` (test setup; the harness-built images and the host `fsck` are 5f)
- (8) only `-smp 1` has run it so far.

## Why it was acceptable

A working server with the crash-consistent core under it (steps 1 to 4); everything above is performance or plumbing.

## Proper fix, and when

- (1) before a third server needs it
- (2) with C1
- (4) with step 6 and the libc
- (5) when a program needs throughput
- (6) with `volmgr`
- (8) the next PR runs `-smp 2` and `-smp 4`.
