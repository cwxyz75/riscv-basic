## Shortcut

**DNS, `fetch` and `httpd` (S9 step 7b) leftovers**:

- (1) `fetch -o FILE` is not implemented (output is the structured line only)
- (2) `httpd` polls its connections every 2 ms when idle instead of waiting on a port: fine for a demo, a cost to a quiet machine
- (3) the resolver caches every positive answer for 60 s whatever its TTL (the TTL is not carried out of `dns::Step`)
- (4) DNS identifiers come from the clock and a counter, not the random service, and there is no TCP fallback for a truncated answer (S9-SPEC 11.3); the source port is the stack's keyed one
- (5) `getaddrinfo` returns one address per socket type, numeric services only, no `ai_canonname`
- (6) neither program is started by `init`; the tests start them
- (7) the host fixtures use fixed ports (47802 TCP server, 47803 DNS, 47804 HTTP) and report `NOTRUN` or skip with a message if a port is taken: two boot tests must not run at once on one machine
- (8) `httpd` has no keep-alive, ranges, conditional requests or compression (HTTP/1.0 semantics on purpose)
- (9) a real-name lookup through 10.0.2.3 (S9-SPEC 11.4's tier-2 check) is not written.

## Why it was acceptable

The pure parts are fuzzed and mutation-checked; the programs are checked against the host's own HTTP client and server and a scripted DNS server.

## Risk

(6) there is no web server in a normal boot.

## Proper fix, and when

Step 8 and whoever wires `init`.
