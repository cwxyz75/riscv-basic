## Shortcut

**Filesystem step 0 leftovers** (`fsd` serves the new operations since step 6; the items below that name `memfsd` still apply to it) (`memfs`, `proto::file`; FS-SPEC 9.1):

- (1) `memfsd` does not serve the new operations (`ATTR_*`, `MAKE_INDEX`, `QUERY`, `SYMLINK`, `READLINK`): it maps the new errors to their statuses and nothing else, so a client gets BAD_REQUEST for the unknown ops
- (2) `ReadDir` reports a symlink as a file (`DirEntry` has `is_dir` only, kind byte 1): a client cannot tell a link from a file without `READLINK`; fix: a kind byte 3 and a `link` flag, with the server step
- (3) the `INDEX` right of FS-SPEC section 4 is not defined (`MAKE_INDEX` is not yet gated; a server decides), and hostile indexing is limited only by the 16-index cap and the metadata quota
- (4) the reference `Fs::query` is a scan over every node: correct, not fast (the disk format has real indexes, the differential at step 3 compares results)
- (5) an attribute value is at most 1024 bytes and not charged to an account, only to the metadata quota
- (6) `mtime` has no resolution of its own (the server's clock decides) and a directory's `mtime` does not change when a file inside is written, only when an entry is added, removed or renamed.

## Why it was acceptable

A pure model fixes the semantics for `fsfmt` to match; none of this is reachable from a client yet.

## Proper fix, and when

- (1) and
- (2) with `memfsd` or `fsd`
- (3) when quotas on disk (step 3) define who may index
- (4) not needed
- (5) with F5.
