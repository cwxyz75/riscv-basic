### T189: AB3 leftovers: no boot reaches the u64 end of the thread-id, koid or object-generation counters, and the ff= run is not self-verifying

*(area kernel, horizon near, refs [AB3, CNT1])*


Left from the Fable review of AB3 (2026-11-21). (1) The only counter boot is `ff=...:0xfffffff0` (the 2^32 crossing); the end of the u64 range (`ff=tid:0xffff_ffff_ffff_f000` and the like) is covered by host tests only, and there is no kernel test for the purpose (create threads and objects across the boundary, ids distinct, joins work, user thread creation refused with NO_MEMORY at the end). (2) `dtb::ff_value` returns `None` on any parse failure and nothing prints the applied values, so a typo or a dropped `OS_BOOT_ARGS` gives a green, vacuous run: print the applied values and have the harness require the line. (3) The VMO store's generation is 32 bits and retires a slot at `u32::MAX` (`kcore/src/aspace.rs`): correct, but untested and with no `ff=` name; a retired slot stays in `slots` for ever. Why acceptable: the host tests cover the counters and the boundary boot shows no 32-bit assumption is left. Risk: an end-of-range path that panics in the kernel (user thread creation is guarded by a headroom check, kernel threads are not).

Progress (2026-11-21): part (2) is done: the kernel prints `##FF <name>=<value> ...` (or `##FF ... error ...`) for the `ff=` boot argument in a test build, and `scripts/os_boot_test.py` fails a run whose `OS_BOOT_ARGS` carry `ff=` when the line is missing or has an error (checked by hand with a good list, an unknown name and an unreadable value). Still open: (1) the end-of-range boots and a kernel test for the purpose, (3) the VMO store's 32-bit generation.

Experiment (2026-11-24): `ff=tid:0xffffffffffffff00,...` (256 ids left) runs the k shard into `thread.rs:592 valid priority: Exhausted`: a kernel thread cannot be created once the id space ends (user thread creation is refused earlier by the headroom check, as designed). So the end-of-range boot needs a dedicated test that stops creating threads at the headroom and checks the refusal, not the whole shard; that test is still to be written.

### T190: AB3 leftovers: the process id is not the process object's koid, the ASID is derived from the pid, and three counters saturate

*(area kernel, horizon long, refs [AB3, CNT1, T66])*


Left from the Fable review of AB3 (2026-11-21). (1) KERNEL-V1-SPEC 3.3 says the process id is the process object's koid; the code keeps a separate `next_pid` counter and loader-started processes have no process object. (2) The ASID is still `(pid & 0xffff)`: two live processes 65,536 pids apart share an ASID (L18/T66 own the ASID allocator; spec 3.3 forbids deriving it from the pid). (3) The koid counter, the FP/vector tokens (`kcore::fp::Tokens`) and the legacy scheduler's `next_tid` (`kcore/src/sched.rs`) saturate or add unchecked at the end of u64; saturation would repeat a value (a token match would let a thread run on another's registers). Unreachable in 2^64 events but the comments say "stop": make them refuse. (4) SYSCALLS.md `futex_lock_pi` puts the owner's tid in bits 0-29 of a 32-bit word, which cannot hold a u64 tid: amend it when the call is built (decision item then). Why acceptable: none is reachable in a boot's lifetime; the test-only `ff=` can reach (3).

### T205: L18 leftovers: shootdowns are whole-TLB on every other hart (no `ran_on`, no ASID or range batching), a process can run under two ASIDs, and the ASID-reuse control is unobservable on QEMU

*(area kernel, horizon long, refs [L18, T64, SC2])*


L18 part b removed every flush at an address-space switch: installing a user space (`activate_current`, `enter_user`) and leaving one for the kernel table (`use_kernel_table_if_needed`) write `satp` and nothing else (translations are tagged by ASID; ASIDs are unique per generation and a hart flushes at a generation change). Teardown, the kernel-table installs at boot and secondary-hart start keep their flush. What it did not build:

1. **`ran_on` and batched shootdowns** (KERNEL-V1-SPEC 5.4, SCHED-SMP-SPEC 3.10): `smp::shootdown` still asks every other online hart for a whole-TLB `sfence.vma` (every ASID), where the spec has an unmap collect up to 64 page ranges and flush only the harts the address space ran on, by ASID and range. Why acceptable: a whole flush on every other hart is a safe superset, TLB2 holds, and at four harts the cost is small. Risk: the cost grows with the harts (SC2 measures it at 16 and 32).
2. **The negative control** `fault-asid-reuse-no-flush` (a feature of the kernel) skips a hart's flush at a generation change and counts the ASID field as one bit, but QEMU drops its translations whenever `satp` is written, so no boot can show a stale translation under a reused ASID: the host model (`kcore/tests/asid_model.rs`, mutation-checked) is the oracle, and the control is not run by a soak target. Correctness on hardware is by review only (PL7 is in the same position).

Proper fix: 1 with SC2 (the `ran_on` mask is the per-address-space hart set, cleared when a hart goes offline: PM1); 2 on a machine that implements ASIDs in its TLB (real hardware, or an emulator that does).
3. **A process can run under two ASIDs at once.** A thread on hart B keeps running under its old token through the lock-free returns (`lock_free_syscall`, the quiet tick and IPI: none call `activate_current`) after another hart refreshed the process's tag. It is harmless now because shootdowns flush every ASID and hart B flushes everything at its next full-path install (its `asid_seen` is behind); the fault path flushes with the ASID in `satp`, not the tag. Any future shootdown **by** `tag.asid` (item 1) must also reach harts still running under an older ASID of that process (flush the old ASID too, or keep a per-process list of the ASIDs it ran under in this generation).
4. **ASIDLEN 0 hardware** (`asid_bits` clamps to 1; `satp` reads back 0 so `aspace_current() != token` is always true and every return reinstalls) is correct but slow, and the width is probed on one hart only: harts with different widths are not handled.

### T236: The system library's data page is a snapshot (`harts_online`, the cache-block sizes); the kernel still answers the old call shapes

*(area kernel, horizon long, refs [AB7, AB8])*


**What.** AB7 fills the library's data page once, when the first process starts: `harts_online` is the count at that moment (it is not rewritten when PM1 takes harts offline or back), and
`cbom_block` and `cboz_block` are 64, the size on QEMU `virt` and on the RVA23 machines in sight, not read from the device tree's `riscv,cbom-block-size` and
`riscv,cboz-block-size`. The kernel also still answers `clock_get` and the other calls the library will replace (the spec lists `port_wait` and `clock_get`). **Why acceptable.**
Nothing in the tree reads these words yet (`rt` reads the page only in a test), and the old numbers are what the kernel's own tests and AB8's shuffling need until the
numbers go private. **Risk.** A program that trusts `harts_online` after a hart goes offline reads a stale count; a machine with other block sizes gets a wrong
`cbom_block`. **Proper fix.** Read the block sizes from the tree at boot, rewrite `harts_online` in `hart_set_online` (write the page again), and remove the
kernel's `clock_get` when AB8 makes the numbers private.

### T237: A program that starts without a system library cannot make a call; the process record keeps the library's range, nothing enforces it yet

*(area kernel, horizon long, refs [AB7, AB8])*


**What.** `rt` stops the program (`unimp`) when a call is made and no library was found (`a2` was 0 or not the library), and the kernel does not yet refuse an `ecall` from outside the library's text range, which `Process::libsys` records.
**Why acceptable.** Every process is started by `process_start` or the loader, both of which map the library; the enforcement is AB8, which has the kernel refuse an `ecall` whose `sepc` is outside `libsys.text`. **Risk.** Until AB8 a program written with its own `ecall` still works. **Proper fix.** AB8.

### 2. Design per part

**A. Counters (T189 (1), (3); T190 (3)).**

1. `ff=vmogen:<n>`: add the name to `FF_NAMES` and call `vmos.set_first_generation` where the other `ff=` values are applied (`user/mod.rs:192-200`; the VMO store is under `kmem`, find where it is made). Leave retired slots in `slots`: that is what "retire" means in CNT1; compacting would renumber ids. Rejected: a 64-bit VMO generation (the id packs `gen << 32 | slot`, a format change through every VMO id for no reachable gain).
2. koid: the last value is never issued. Add the headroom to the admission check every creating call already makes (`reg.live() >= reg.cap()`, e.g. `ipc.rs:1685`; grep `\.cap()` for the others and put it behind one `Kobjs` method), so the call answers NO_MEMORY; `create_charged` stays infallible. Rejected: making `create_charged` return `Result` (dozens of callers, each already past its point of no return, KT9).
3. FP/vector tokens: at the end `next` must never hand out a value twice. Read how a hart compares the loaded token with the thread's before choosing: if 0 already means "matches nothing" ("never zero", `fp.rs:116`), return 0 for ever after the last token, so the registers are always reloaded (slow, never shared). Rejected: saturate (two states share a token: FP1/FP2/VS1 break), panic (KERNEL-V1-SPEC 7.4), refusing thread creation (line 257 issues a token on a state change of a live thread, which cannot be refused).
4. Legacy `next_tid`: `checked_add` and a `SchedError`, or delete with the stand-in if T259 has removed its last user.
5. The end-of-range kernel test `counters_stop_at_the_end` (in `kernel/src/sched_tests.rs` or a new section of `user_tests.rs`), run in a boot of its own with `ff=tid:0xffff_ffff_ffff_e000,koid:...,fptoken:...,vmogen:0xfffffff0,objgen,handlegen` near their ends: it creates kernel threads only while `tid_headroom(4096)` holds and joins them (ids distinct), creates user threads and processes until NO_MEMORY, checks the refusals leave nothing charged (job counters back to their start), creates and frees VMOs across the generation end, and finishes by reading the counters. The boot runs **only** this test (the k shard panics at `thread.rs:651`, see the item's experiment), so it needs a test selector: prefer a boot argument read like `ff=` (`dtb::boot_arg_value`) over a second kernel build. The harness already requires the `##FF` line.

**B. The data page and the entry check (T236; T237 residue).**

1. Block sizes: `kcore::fdt` reads `riscv,cbom-block-size` and `riscv,cboz-block-size` from each `/cpus/cpu@*` node (pure, host-tested); the kernel keeps the two values beside the other boot facts and `page_contents` uses them. All harts must agree (OD132 keeps heterogeneous harts out). What to do when a hart lacks the property or the harts differ is Q4.
2. `harts_online`: keep the direct-map address of the data page's word in `Lib` (found once in `ensure`, when the frame is written) and store the new count with one aligned atomic store from the place the hart changes its own `online` flag (`thread.rs:491,499`), after the flag. A reader in user mode sees the old or the new count, never a torn one; the word is advisory by nature. `ensure` must read the count **after** publishing the address (or re-store it) so that a change racing the first process start is not lost. Rejected: `vmos.write` from the offline path (it would take `VMO`/`FRAME` from a hart that is leaving the scheduler, a new lock edge for one word); a version or seqlock word (nothing reads two words together).
3. Update SYSCALLS.md / the AB7 text in place where they say the page is a snapshot; ABI version unchanged (same words, same meaning).
4. Removing the kernel's `clock_get` and `port_wait` shapes: **not planned until Q3 is answered.**
5. T237 residue (optional, same PR): drop the "no library range" exemption so a process without a library can make no call at all. First check who relies on it: `LibRange::default()` at `loader.rs:43` (overwritten at line 92 on success) and `ksys::NoMap` (host tests only). If kernel test worlds start processes with no library, leave the exemption and say so in ABI1.

**C. Process id is the process object's koid (T190 (1)).** Take the koid first: a `Kobjs::reserve_koid()` that consumes the next value (subject to A2's headroom; a koid consumed by a creation that then fails is simply never used), use it as the key of `procs` and pass it to `process_object_create_in`, which creates the object **with** that koid. The loader takes its pid from the same call (no object: the id space is still one). `next_pid` and the skip loop go; `create_calls`' pid-limit test moves to the koid end. Rejected: creating the object first (it is the last fallible step by KT9, and its failure path would have to undo more); giving loader processes a process object now (who would hold the handle is a design question, not a tidy). Do A2 first: the pid's refusal becomes the koid's.

**D. Shootdowns (T205 (1), (3), (4)).**

1. (4) first, small: every secondary probes `asid_bits()` at start and the boot stops with a structured line if it differs from the boot hart's (check that the probe runs before `Asids::new` can be reached, or compare afterwards). ASIDLEN 0 stays slow and correct.
2. Stage 1, **by hart, not by ASID**: an atomic `ran_on: AtomicU64` per address space (in the `AsCell`, so a quiet fault can reach it through `PerHart.cur_as`). A hart sets its bit, `SeqCst`, **before** every `satp` write that installs that space (`activate_current`, `enter_user`/`user_thread_main`, the quiet return that reinstalls); bits are never cleared while the space lives. `smp::shootdown_of(mask)` sends the same whole-TLB fence (every ASID) to `mask & online & !me`; `smp::shootdown()` (everyone) stays for callers with no single address space. Because the flush still covers every ASID, item (3) cannot bite and no ASID bookkeeping is needed. Classify the 13 call sites: one space under its `AS` lock (unmap, protect, the quiet fault, teardown) takes the mask; `vmo_decommit`, a shrinking `vmo_set_size`, `invalidate_copies`/`cow_sync` and the pager path touch every mapper of a VMO: take the union of the mappers' masks only if the list of mappings is already in hand, else everyone. Kernel-half flushes (`kstack.rs:150`, `heap.rs:572`, `kmem.rs:667`) and `icache_sync` are untouched.
3. Stage 2 (`remote_sfence_vma_asid`, ranges, the 64-page batch): **not planned** (Q1). If ever built it must first solve (3): flush every ASID the space ran under in this generation.
4. Rejected: clearing a bit when a hart switches away (the user entries stay cached under the ASID since L18, so the hart still needs the flush); clearing at a hart's generation flush (needs a walk of every space from the flushing hart); per-ASID flush in stage 1 (meets (3) for a gain QEMU cannot measure).

| D2 | TLB1, TLB2, SMP5 (its text changes: "every other online hart" becomes "every online hart in the space's `ran_on`"), M3b, M9, COW1, V4, HT1, K6/AS2 | mask written with no lock by the installing hart; read under `AS` (2) by the unmapper, before `VMO` (5)/`FRAME` (11) free anything | (a) The Dekker race: unmapper clears the PTE then reads the mask; installer sets the bit then lets the hart walk the table. Both sides need a full barrier between their write and their read (`SeqCst`, and the PTE store must not sit in a store buffer when the mask is read), or a hart caches the old PTE and is not fenced. (b) An install path that misses the bit (there are several: full path, first entry, quiet return, the fault path's reinstall on ASIDLEN 0). (c) A call site classified "one space" that in fact changes several (COW family, decommit). (d) A hart offline when the mask is read and online before the frame is freed: it starts with a full flush (`thread.rs:490-499`), keep that. (e) QEMU hides a missing flush for unmap (T193 in T264), so a green boot proves little: the host model and the review carry this PR |
| D1 | TLB1 | none | Probing on a secondary before its table is installed, or with interrupts on (`asid_bits`' safety contract) |

The lock order is unchanged by every step; no step adds a class or an edge. If an implementation finds it needs one (B2 through `VMO`, D2 taking `AS` from the install path), stop: that is a different design.
