## Shortcut

**`ish` in the OS (SH4) shortcuts** (2026-11-17):

- (1) the S4e compatibility profile (`Shell::legacy`: `sh:` messages, one `[exit N]` per failed stage and none for 141, `cd` printing its own errors and going on, parse errors without positions) exists so the existing shell test passes unchanged; the scripting behaviour is the standard one; retire it by updating the expected outputs with the owner's say-so
- (2) **mostly resolved 2026-11-17**: a program's stdin can come from a file and its stdout can go to one (`< f`, `> f`, `>> f`): the shell holds a socket for the program and drains or feeds it while it waits; **only `/tmp/...` can be written** by redirection (the shell's own scratch directory, the parent of the programs' private ones; the image is read-only and volumes belong to the programs the profile grants them to, so a redirection to a volume needs the powerbox decision of T33), and a failed store is reported after the command has run
- (3) **resolved 2026-11-17**: the OS host expands `*`, `?` and `[...]` per path component (a name starting with `.` only for a pattern that does; no match is an error)
- (4) a program's standard error is the terminal, not a copy of its stdout as before
- (5) a shell callee that loops is not interruptible by Ctrl-C (the console server only kills registered jobs; the interrupt event of UV4 is not read yet: SH5)
- (6) `ns` lists the table the shell holds (root, `.`, `/dev`, `/tmp`, `/svc`), not the volumes trusted programs are granted; a `confine` grant under `/mnt/<volume>` is opened from the registry (the shell can hand any volume to a program it starts: the shell is the powerbox), and a confined program gets no root even if `/etc/trusted` names it
- (7) `/etc/trusted` is still the source of the default grants
- (8) `ish` input must be UTF-8: a line that is not is refused. Fix: (5) as the shell and the libc need them; a `>` into a volume with T33.

(Migrated from the old TIDY-UP register, section "Concurrency and kernel structure", 2026-11-18.)

## Note (2026-11-18, T151)

Checked: (5) is resolved: the shell polls the console server's events inside callees and loops (`interrupted()`, every 4096 statements), so Ctrl-C ends a looping shell callee. The other items stand.
