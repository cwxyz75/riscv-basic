## L12a built (2026-11-19): the lock is released at a switch (G4)

`reschedule` releases the big lock completely before `context_switch` (`bkl::release_all`, the depth stays on the thread's stack) and the thread that resumes takes it back to that depth (`bkl::reacquire`); a new thread locks in its bootstrap. The lock no longer follows the thread (K3 rewritten; `KThread.bkl_depth` and `bkl::swap_depth` are gone). What the lock used to cover is now the scheduler's transit rule (TR1), widened: a thread that blocked, slept or exited is *in transit* on its hart (`Sched2::displaced` is called by `block_on`, `sleep_until_on` and `exit_on` with the thread they leave, whatever its state) until the incoming thread's `switch_done` (the scheduler half of `finish_switch`, run before it waits for the lock), so no other hart can wake-and-run it, pull it or reap it before its context is saved. A wake of a blocked thread that is still in transit queues it on the hart that is executing it (every other hart's own queue could be served before the switch is done); `switched` marks that hart when such a thread outranks what it runs next; `join` waits for an exited thread's transit to end; the audit's transit rule no longer requires state Runnable. Checked by: `kcore/tests/sched_transit_g4.rs` (deterministic: a blocked, slept or exited thread is not run or reaped before its switch is done; mutation, the old Runnable-only transit, is caught by two of three), the shuttle model's new G4 mode (`rq_concurrency`: the lock dropped before each switch is finished, with yields in the switch window; it passes but does not by itself catch the transit mutation: the window needs a wake, a placement and a settle inside it), the reference walks (they reap only after the switch is done), `os-repeat os-ktest-4` 8 of 8, and the k boots at 1, 2 and 4 harts and the release kernel. Left: **L12b** the timer tick and the reschedule IPI that interrupt user mode take no big lock when the hart need not switch (an *attention epoch* bumped at the kill and stop sites, a per-hart seen epoch, FP state not dirty, no heap service owed); **L12c** `thread_yield`, `clock_get` and pure sleeps without the lock; T163 (the dead list at safe points) and T164 (stack poison) with them.

Review of L12a (fresh-context Fable, 2026-11-19): one HIGH, fixed: `reap_prev` runs after the lock is taken again, which can wait, so `prev` can be stale; an exited detached thread could be reaped while it was in transit on another hart (use-after-free of its stack and context); `reap_if_dead` now skips a thread in transit (the thread that replaces it on its hart reaps it after that switch is done). Also fixed: the slept test was vacuous (now wakes the sleeper from the other hart), the audit again requires a Runnable thread in transit to be queued, stale comments. Not fixed (tidy T165): `sched2_kernel_walk` still models K3 (`bkl_barrier`), so big-lock operations never run inside a switch window there, and the shuttle G4 mode has no reacquire-then-reap-`prev` step.

## L12b built (2026-11-19): ticks and reschedule IPIs from user mode without the big lock

A timer tick or reschedule IPI that interrupts **user mode** takes the big kernel lock only when something needs it: the user's FP registers are dirty (saving them uses the FP tables), the hart must switch threads, a switch is flagged (`need_resched`), the heap is low, or the **attention epoch** moved. The epoch (`user::ATTENTION`, a global counter) is bumped under the big lock whenever a process is marked killed or stopped (`process_exit` of the whole process, the kill path, `process_suspend`), *after* the mark and before any IPI that tells a hart to look; `activate_current` stores the epoch each hart saw (before it reads the marks), and `user::user_return_is_quiet` compares. A kill therefore always reaches the full path (the kill IPI or the next tick sees the moved epoch, takes the lock, and the thread dies at its return to user mode as before). `commit_wake` is not run on the fast path: the dirty log is committed by whoever dirtied it, under the lock, before it leaves it. Checked by `user_mode_ticks_take_no_big_lock` (a secondary hart running a spinning user thread: at most 8 lock takes over 80 ticks; with the quiet check forced false it fails with "took the big kernel lock 79 times for 79 ticks"), `kill_a_spinner_on_another_hart` and the FP isolation tests (unchanged), `os-repeat os-ktest-4` 6 of 6, the k boots at 1, 2 and 4 harts and the release kernel. Left: L12c, `thread_yield`, `clock_get` and pure sleeps without the lock.

Review of L12b (fresh-context Fable, 2026-11-19): one HIGH, fixed: a new user thread's first entry (`user_thread_main`) read the kill and stop marks, then `preempt_point` could switch (and, since L12a, release the lock) so a kill could land and another thread on the hart could record the new epoch before the thread resumed and entered user mode: a spinning killed thread would then never be looked at again; the thread now zeroes its hart's seen epoch just before `enter_user`, so its first trap takes the full path. Also fixed: the new test could pass vacuously if the spinner left the hart (now fails on too few ticks or not in user mode). Tidy T166: threads that have used FP still take the lock in `fp::return_to_user`. Not covered by a test: the reschedule-IPI fast path alone, and a kill racing a thread's first entry (deterministic injection would be needed).

## L12c built (2026-11-19): `clock_get` and `thread_yield` from user mode without the big lock

`trap::lock_free_syscall`: an `ecall` for `clock_get` or `thread_yield` from user mode is handled before the trap takes the big lock when the return is quiet (the attention epoch of L12b is unchanged) and the user's FP registers are not dirty. `clock_get` just reads the tick counter. `thread_yield` runs `thread::yield_fast` (the scheduler's own locks make the designation); the big lock is taken only if the hart must switch (`switch_if_designated`, `commit_wake`, `activate_current`). Pure sleeps still take the lock (they block: they are not a quick path); the item's wording "pure sleeps" is left for a later peel with the wait paths. Checked by `user_clock_get_and_yield_take_no_big_lock` (new crash.rs programs 80 and 81 spin on `clock_get` and `thread_yield`; the hart running them takes at most 8 lock takes in 80 ticks; with `lock_free_syscall` disabled: "took the big kernel lock 19518 times for 80 ticks"), `os-repeat os-ktest-4` 6 of 6, the k boots at 1, 2 and 4 harts and the release kernel. Note: this test needs a quiet host; at two harts on a loaded machine a freshly started user thread was seen taking 0.7 to 2.4 s to start running (with the fast path forced off as well), which the test now simply waits out.
