## Shortcut

**Detach and reattach (UV7) shortcuts** (2026-11-17):

- (1) the terminal's "screen state" is the last 8 KiB of what it displayed, replayed as raw bytes to a backend that attaches: there is no screen model, so a full-screen program is not redrawn and the replay can start inside an escape sequence (the VT emulator server of section 9 item 5 is the proper answer)
- (2) the serial console itself is not detachable (its backend is the UART, which never closes): only a `Term::Backend` session is, and the only provider so far is the test in `init`; an `sshd` or a `detach` command for the console is not built
- (3) input typed while detached is not kept, and output beyond 8 KiB while detached is lost (the replay is the newest 8 KiB)
- (4) a hangup ends the terminal and kills the foreground job; the rest of the session goes when `init` sees the shell end, so a session's background jobs outlive the hangup only until then
- (5) the window size is not re-queried on attach (the new backend's size is not known to the terminal)
- (6) one backend at a time: attaching replaces the previous one, closing it.

## Why it was acceptable

Meets the acceptance in QEMU with a provider that can drive and read a socket.

## Proper fix, and when

- (1) with the VT server
- (2) with the ssh login (UV5a's remote login as a backend)
- (5) when a size report is part of attach.
