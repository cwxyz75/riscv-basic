## Shortcut

**Threads in the C library are a first cut (S7c-3b).** Stdio streams have no per-stream lock (a `FILE` shared by threads needs the caller's own locking; the fd table has one global lock), (a detached thread's stack and control block are freed since task 9, which moved the C library to `thread_spawn`), `pthread_key` destructors never run, there is no `pthread_cancel`, barrier, read-write lock or `pthread_attr_setstack`, thread stacks are one default size (256 KiB; `pthread_attr_setstacksize` up to 64 MiB), `pthread_exit` from the main thread ends the process (POSIX lets the other threads run on), a deleted-and-recreated key keeps stale values in other threads, `nanosleep` does not validate its argument, `rand`/`strtok`-style hidden state is not thread safe, and the launcher's 128-thread program limit (was 4) bounds a shell-started program.

## Why it was acceptable

Lua is single threaded; the tests under the suite's job cover the primitives.

## Proper fix, and when

Per-stream locks; a reaper for detached threads (a joiner thread or a deferred unmap); the rest as programs need them. The detached-thread leak is resolved (SCHED-SMP-SPEC task 9).
