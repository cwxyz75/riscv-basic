## Shortcut

**`doofs` step 3 leftovers**:

- (1) no inline data: every non-empty file takes at least one 4 KiB block (FS-SPEC section 3 says up to about 1 KiB inline)
- (2) extents are one data block each (no multi-block extents, so a file has one tree entry per 4 KiB)
- (3) a delete's transaction may fail with `NoSpace` only if the 64-block reserve is not enough (a very large file spread over many tree leaves)
- (4) no attributes, indexes, queries or `mtime` index yet (step 6); `Kind::Image` does not exist on disk
- (5) the node id counter never reuses ids and is 64-bit: no wrap handling
- (6) `rename` does not use the reserve (renaming over a file on a full volume can fail with `NoSpace`)
- (7) the `memfs` fixes of this step change its accounting for symlinks on rename (cost now keeps the target).

## Why it was acceptable

Correct against the oracle and the fsck; sizes small.

## Proper fix, and when

- (1) and
- (2) when file performance matters (the server, step 5c)
- (3) and
- (6) with the crash harness, which can fill a volume systematically.
