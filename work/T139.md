## Shortcut

**The compat shell (SH7): BusyBox `hush`, a spike** (2026-11-17): `ash` cannot be built here (its source refuses to without `fork`, which the libc does not have: `BB_MMU`; there is an MMU, there is no copy-on-write `fork` yet, S11); `hush` has a mode that starts a copy of itself with `vfork` and `exec` instead, and runs as `busybox hush` (not `/bin/sh`: the system shell is `ish`). The shell test runs 17 scripts through it and compares each with the host's `sh` (pipelines, `$()`, loops, functions, subshells, `case`, `trap`, `wait`, arithmetic, globs). **Redirection to and from files works** (a started program can get a connection to an open file as a standard stream: the starter's environment says `STDOUT=file:<mode>:<offset>` and the library of the new program installs it; `dup2` of a file makes a connection of its own; a `vfork` child's table holds connections to the starter's files; a writable file shared this way is appended to by both sides, because a position is not shared (a read position is not either: a program that reads a shared file starts at the offset the starter had)); a program started by a program shares its chain's private `/tmp` directory. **Not done:**

- (1) here-documents were not tried (a script with a newline cannot be typed through `ish` in the test)
- (2) interactive mode and job control (`HUSH_INTERACTIVE`, `HUSH_JOB` are off: `termios` for programs is T124)
- (3) `hush` is not installed as `sh` (no `/bin/sh` file: `system()` and `popen()` run `busybox hush -c` by name, a program with no spawn grant still gets `ENOSYS`, and a script's `#!/bin/sh` line has nothing to run)
- (4) no `configure` script has been tried
- (5) each subshell, command substitution and pipeline stage is a spawn (about 20 ms in the debug build under QEMU), so scripts are slow.

## Why it was acceptable

The spike shows the NOMMU shell can carry real scripts on the spawn grant and the signals subset.

## Proper fix, and when

- (1) a here-document test (a script file)
- (3) a `/bin/sh` name that resolves to it
- (4) a corpus of real scripts.
