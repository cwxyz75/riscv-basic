## Shortcut

**(mostly resolved 2026-11-17: a program of the foreground job has `tcgetattr`, `tcsetattr`, `ioctl(TIOCGWINSZ)` and `VMIN`/`VTIME` through the shell, which asks the console server and puts the mode back when the job ends; `proto::spawn` op 3; left: `SIGWINCH`/`SIGHUP`/`SIGTSTP` mapped from the events, a program that is not the foreground job cannot read the terminal's size, only the three mode flags exist (no `ECHOE`, `OPOST` and the rest, which are always the cooked answer), `tcsetattr` actions (`TCSADRAIN`, `TCSAFLUSH`) act as `TCSANOW`, `tcflush` does nothing) UV4b: the terminal for programs** (2026-11-17): UV4 gave the terminal modes, a size and events to its *owner* (the shell or stand-in on the control channel). Programs do not see them yet: no `tcgetattr`/`tcsetattr`/`ioctl(TIOCGWINSZ)`/`isatty` against a real terminal, no `VMIN`/`VTIME` emulation in the libc, no per-program control channel or subscribe, and Ctrl-C always kills the whole foreground set (the interrupt event to a raw-mode owner is not mapped to SIGINT/SIGWINCH/SIGHUP/SIGTSTP). Also: the hangup event is only host-tested for encoding, not exercised in QEMU (closing the serial line ends the run); the size query is opt-in, so a client that never asks sees 80x24 whatever the host terminal is. Acceptable: the shell and the BASIC and Lua ports work without them. Risk: a curses-style port gets a wrong size and no raw mode. Fix: the libc termios layer over a per-program terminal channel, when a port needs it (UV8).
