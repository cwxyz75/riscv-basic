## Shortcut

**`sessiond` shortcuts** (2026-11-17):

- (1) `sessiond` still runs with the root job and the root resource that `init` hands it (duplicates with every right): a session manager needs to make jobs, but a handle that can only make children of one "sessions" job, and a resource handle narrowed to the devices the device manager claims, would be less
- (2) the code is shared by `include` (`init/src/session.rs` is compiled into `sessiond` and into `init`, whose `repl` test aids build sessions themselves), so `init`'s binary still contains it
- (3) **resolved**: its log lines say `sessiond:`
- (4) `init` ends the system when `sessiond` exits 0 and returns its code otherwise: it does not restart a crashed `sessiond`
- (5) the supervisor loop inside `sessiond` is unchanged: a `halt` ends it.

## Why it was acceptable

Separates the manager's authority and memory from `init`'s; no behaviour change.

## Proper fix, and when

- (1) with the S10 manifest
- (2) when the test aids move into their own program
- (4) a restart policy with the manager's state in `init`'s hands.
