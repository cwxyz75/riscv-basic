## Shortcut

**A shell exit rebuilds the whole stack** (memfsd, launcher, consoled, sh), so `/tmp` contents and the shell's directory are lost on `exit`/Ctrl-D. The launcher serves one client (T30) and has no way to hand over.

## Why it was acceptable

Simple and matches the death policy; nothing in S4 keeps state across shells.

## Proper fix, and when

A multi-client launcher (T30) lets init restart only `sh`.

(Migrated from the old TIDY-UP register, section "Test aids, runtime and format debts", 2026-11-18.)

## Note (2026-11-18, T151)

Checked against the code: production boots through `sessiond` (init.rs `run_sessiond`), one stack per session, so a shell exit ends that session's stack only. The whole-stack rebuild remains for the test console path (`console_session` in init.rs), which is the only place `/tmp` is lost on `exit`. Left as is for the test path; the launcher stays one-client (T30).
