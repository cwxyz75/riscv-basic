## Shortcut

**The AIA path is minimal (slice I).** Interrupt objects run on the AIA (APLIC in MSI mode, one IMSIC supervisor file per hart); the PLIC path is gone, and a plain `virt` board has no interrupt controller the kernel drives (drivers poll). What is still a stand-in: the supervisor APLIC base (`0x0d00_0000`) is a constant, checked against the device tree rather than read from it before the direct map exists; the IMSIC hart index in a source's target is the hart id (right on QEMU, where ids run 0..n-1 in tree order); the sources are the eight virtio slots and the message id equals the source number; every source is level-high; a message still in flight to the old hart when an object is destroyed and re-created on another hart is taken there as a spurious interrupt (tolerated by drivers) and counts as misrouted, a possible flake of the boot-script check; only QEMU has run it, so a real APLIC's treatment of a still-asserted level after the message (the kernel re-pends with `setipnum` on unmask) and of a storm is unproven.

## Why it was acceptable

Enough for virtio-blk on QEMU, with delivery to the hart that asked proven by counters (`debug_stat` 3-5).

## Proper fix, and when

Map the APLIC from the device tree; map hart ids to IMSIC indices from the `interrupts-extended` order; sources and ids from `riscv,num-sources`/`riscv,num-ids`, edge sources, guest files and MSI-based devices (PCI) when a driver needs them.
