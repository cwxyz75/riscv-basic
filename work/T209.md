**What.** In the epic gate of PR 383 (smoke a, 2026-11-21) `volmgr_serves_volumes_by_the_table` failed with "unexpected status -100" at the end of `open_volume` (the 15 s retry of a view open after the volume manager restart), and passed on the next run of the same code plus two small fixes. No cause is known.

**Why it is not just re-run.** TESTING.md rule 11: an intermittent kernel-test failure is a defect until its cause is known. It may be a real race in the restart path, or an effect of the EX1/EX2 changes (the thread park, the exception channel reaping on handle close).

**Proper fix.** Reproduce it from the smoke-a log (the harness prints the volmgr lines around it), find whether the restarted volmgr never published or the open retried against a dead channel, and fix that. Do it when the epic's smoke shows it again or in the first slack between items; it does not block phase 9.

**Second occurrence (2026-11-22).** The same test failed the same way (`unexpected status -100 at suite.rs:11217`) in a full local boot of the latency-trace kernel at four harts with `bench=full` (`make os-latency`, the whole suite, 264 user tests passed). It is a different binary and a far heavier run than the gate's smoke a, so the cause is not the gate's load alone; the `open_volume` retry of 15 s ran out both times. That boot's log has the volmgr lines around it.
