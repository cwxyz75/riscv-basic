**What.** Miri covers the pure crates; the kernel binary's `unsafe` (context switch, trap entry, FP and vector save, page-table writes, per-hart records, MMIO) is checked only by the suite passing.

**How.** A fresh-context Fable review whose only subject is the `unsafe` in `kernel/` after the legacy lock is gone: for each block, does the `// SAFETY:` comment state a condition, is the condition true on every path to the block, and can it be made false from user mode or by another hart. The record goes to `docs/records/reviews/` with one row per block (file, line, condition, verdict). Where a block can move behind a safe interface in `kcore` that Miri or a model can exercise, it moves. A script (`scripts/unsafe_inventory.py`) lists the blocks with a hash of each; the docs check fails when a block's hash is not in the audited list, so a changed block is re-audited.

**Acceptance.** The inventory matches the record; the check fails on a planted new `unsafe` block.

**Review.** This item is a review. Part of the freeze (FZ1).

## Progress (2026-11-23)

**Built:** `scripts/unsafe_inventory.py` (162 blocks, hashed with their SAFETY comments), `docs/records/reviews/kt14-unsafe-audit.tsv` (a row per block), the check in the docs check (a new or changed block fails until it is audited), the self-test that plants one.
