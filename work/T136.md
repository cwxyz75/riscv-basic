## Shortcut

**Programs that start programs (UV8, OD118): shortcuts** (2026-11-17):

- (1) **the grant is on by default** (the owner's default); a profile can turn it off with `"spawn": false` (resolved 2026-11-17: the `profile` crate parses it, host-tested; the shell sets its grant from it in one line; **no QEMU session test denies a spawn yet**, so the shell half is not exercised by a running system)
- (2) a child's working directory is the asking program's *starting* one (a `chdir` is not followed: the request has no directory handle) and its `/tmp` is the chain's (shared since the compat shell spike, T139)
- (3) (resolved: the spawn path carries bytes) the argument vector and environment passed through the shell as lossy UTF-8
- (4) the pids `waitpid` returns are the C library's own counters, not the shell's (`getppid` is still 1), there are no process groups or sessions, and `kill` on a child ends it whatever the signal (S11 delivers real ones: `timeout` and `ash` need them)
- (5) `exec*` does not replace the process: it starts the program, waits and exits with its status (a `vfork` child returns to the caller instead); one `vfork` at a time per process
- (6) (`popen` and `system` work through `busybox hush -c` since the compat shell spike, T139; `ash` cannot be built without `fork`)
- (7) a descendant lives only as long as the program the shell started (no daemons, no `nohup`-style survival)
- (8) (resolved in review) the shell serves requests while it waits, reads a pipe or capture, writes a pipe, and sits at the prompt; a flooding program is read a few messages per pass and a protocol violation or a closed channel ends its grant, and a program's chain ends when it ends, reaped or not
- (9) (resolved 2026-11-17) the spawn rate is measured by the shell test (100 `xargs` spawns: about 2 s of guest time in the debug build under QEMU, about 20 ms each, most of it the shell's `start_with`); a first measurement of 12.9 s found a real bug: the shell's wait loops bound every spawn channel to a port under the same key (a key is unique in a port: only the first was watched), so a request from any other program waited for the 100 ms timeout
- (10) review leftovers: the child's environment is entirely the asker's (the shell does not re-impose `USER`/`UID`/`HOME`, and `getpwuid` identity is spoofable for a trusted child; harmless while nothing authorises from the environment), a `vfork` child shares the descriptor table (a `dup2` or `close` before `exec` changes the parent's), `VFORK_BUF` is process-wide (one `vfork` child, no other thread calling `exec*`/`_exit` meanwhile), a request that timed out (120 s) may still start its program later, `start_with` can block the shell 4 s per unavailable volume grant of a trusted asker, a transient error reading a broker channel revokes the program's grant, and each chain multiplies the per-program job caps by up to 33 (the session-level cap was not checked).

## Why it was acceptable

A program can run others (`xargs`, `env`, `find -exec`, `time`, `posix_spawn`) with no more authority than it has, which is what UV8 needed.

## Proper fix, and when

- (1) (field done; a QEMU test that denies a spawn is left)
- (2) a directory handle in the request
- (3) bytes in the shell's start path
- (4) S11
- (6) a `/bin/sh` that is a program (SH7)
- (8) serve the brokers while reading input
- (9) measure with a spawn loop.
