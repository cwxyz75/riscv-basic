title: MSI-X serves one vector per queue on one hart, and the older MSI capability is not driven
area: drivers
horizon: someday
risk: L
complexity: M
change_risk: M
refs: [IOMMU-SPEC, OD165, T42, X-BUS, IOMMU9, IOMMU12]
---

**What.** IOMMU9 built MSI-X in `devmgr` (`pcicore`'s capability walk and table writes, one vector per interrupt the class
needs, every vector granted on the function's domain) and IOMMU10 and IOMMU11 use it for `blkd` (one request queue),
`netdrv` (a receive and a transmit queue) and `rngd`. Two things are left. (1) **Multi-queue devices and per-queue
placement**: every driver asks for a fixed vector count per class and runs its queues from one thread, so each vector is
delivered to the hart that thread runs on (`interrupt_ack` moves a vector to the acknowledging hart, IOMMU-SPEC 8.5). A
multi-queue block or network device (`num-queues` above 1, as the harness passes `num-queues=1` today) has no way to ask for
a vector per queue or to place queues on harts, and the class table has no "as many as the device offers, up to N" form.
(2) **The older MSI capability** (capability id 5: one address and data pair, up to 32 vectors in a block, optional per-vector
masking): a function that offers MSI and not MSI-X is listed as `not-claimable no MSI-X capability`, as `iommu-testdev` and the
host bridge are. OD165 admits no INTx; MSI is not excluded by it, only not built.

**Why acceptable.** Every device of the reference machine that a driver claims offers MSI-X, with one queue per direction; the
drivers' throughput is not a goal of the IOMMU epic (IOMMU-SPEC 14).

**Risk.** A real board's devices (or a QEMU device without MSI-X, such as some emulated NICs) cannot be claimed at all; a
multi-queue device runs on one queue and one hart.

**Proper fix, and when.** In `pcicore`: the MSI capability (its address and data registers, the multiple-message field, the
mask bits when offered) with the same host tests as MSI-X, and a claim class that names a range of vectors; in `devmgr`: the
range granted whole or refused (no shared vector, as IOMMU9); in the drivers: a queue per vector, each served by a thread that
can be placed on a hart. Do it with the first device that offers only MSI, or the first driver that needs more than one queue
per direction.
