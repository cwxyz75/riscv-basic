## Shortcut

**Shared futexes, thread suspend and resume are reserved, not built**

## Why it was acceptable

Nothing needs them

## Proper fix, and when

When a shared-memory ring or a debugger does

How the private path works today (what a shared key must fit into): the wait translates the word under the caller's `AS` lock and
the memory locks (`kcore/src/usercopy.rs:89`, `resolve_user_word`), lets the memory locks go, then compares and enqueues under the
key's bucket lock (`ksys/src/wait.rs:233-256`, `FutexTable::wait_if`, `kcore/src/futex.rs:167`). The wake translates **nothing**
(the address need not be mapped) and takes only the bucket lock. Both have a no-big-lock quiet path (L14, L19, INVARIANTS K6).
`forget_process` and `forget_process_quiet` find a process's sleepers by `key.0 == pid` (`kcore/src/futex.rs:94-118`).

### 2. Design

Follow SCHED-SMP-SPEC 5.7: bit 0 of a flags argument (`futex_wait` `a3`, `futex_wake` `a2`) selects a **shared key
(VMO, byte offset in the VMO)**, found by looking up the region that contains the address under the caller's `AS` lock.

1. `kcore::futex::Key` becomes a tagged key: `Private { pid, addr }` or `Shared { vmo, offset }`. `vmo` must be an identity that is
   **never reused** (the koid, CNT1), not a registry slot: check what `Region.vmo` holds (`kcore/src/aspace.rs:69-83`,
   `Mapping::vmo_page()` already gives `(vmo, page)`) and convert if it is a slot id.
2. `sleeping_on` records the sleeper's pid beside its key, so `forget_process*` no longer reads the pid out of the key (a shared
   sleeper of a dying process must still be found).
3. `futex_wait` with the bit: resolve as today, plus the region lookup in the same `AS` critical section, giving the shared key and
   the physical address; compare and enqueue under the bucket of the **shared** key. Sleep, report and forget are unchanged.
4. `futex_wake` with the bit: take the caller's `AS` lock, look up the region (no fault, the page need not be resident; no region
   is INVALID_ARGS), let go, then wake on the shared key under its bucket lock.
5. First cut: **the shared bit always takes the full (big-lock) path**; `futex_wait_quiet`/`futex_wake_quiet` return "not quiet"
   when the bit is set. The private fast paths gain one flag test and nothing else. Any other flag bit: INVALID_ARGS.
6. PI futexes stay private only (5.7); `futex_lock_pi` has no flags.

Rejected:

| Alternative | Why not |
|---|---|
| Key by physical frame | The frame under a (VMO, offset) changes (decommit and recommit, a pager's page, copy-on-write); sleepers would be stranded. Also puts a frame number, reused freely, in a table that relies on keys not being inherited (F1) |
| Make every futex shared-keyed (no flag) | The private wake would need `AS` and a region lookup: it loses the lock-free wake of L14 and the measured pair benchmarks (T213, T264) |
| A futex kernel object (handle, rights) | Contradicts OD68's "no rights, naming one grants nothing"; an event object already is the handle-shaped doorbell |
| Do nothing, use events (status quo) | Valid until a user appears: see "When to start" |
| Shared quiet paths in the first PR | Doubles the lock-free surface (K6) for a feature with no measured need; add later only with a benchmark that asks |

### 5. Invariants, lock order, and how it goes wrong

Rows to preserve or reword (docs/reference/INVARIANTS.md): **F1** (bucket lock only, never two buckets; an entry never outlives its
thread), **F2** (compare and enqueue in one bucket-lock region; prepare before look), **F3** (must be reworded: a shared wake
reaches sleepers on the same (VMO, offset), in any process), **K6** (which ecalls are quiet), **AS1** (`AS` before the memory locks,
no sleep with one held), **CNT1** (koids are not reused), **EX1** and OD123 (a suspended or stopped sleeper parks, unchanged).
Lock classes in order (`klock/src/lib.rs:35-50`): `Obj`, `As`, `Procs`, `Futex`, `Vmo`, `Jobs`, `Pi`, `Tt`, `Rq`, ... . `Futex`
comes **after** `As` and **before** `Vmo`/`Jobs`/`Frame`: the key must be computed and the memory locks dropped before the bucket
lock is taken, exactly as the private wait does; never look up a VMO with a bucket held.

Ways to get it subtly wrong:

1. **Key by the wrong identity**: a registry slot or generation that is reused lets a new VMO inherit sleepers (breaks F1's
   "cannot inherit"); use the koid.
2. **Child VMOs** (`vmo_create_child`, MM8, `abi/src/lib.rs:214-251`): a waiter through a snapshot child reads the parent's frame
   until it is copied, but its region names the child, so a waker through the parent uses another key: a wake the waiter "saw"
   is lost. A slice-style child must normalise to the root VMO and offset. Needs a rule (Q3) and a test for each child kind.
3. **Frame lifetime on the read**: the word is read through the physical address after the memory locks are dropped; today that
   is safe because "every unmap and decommit takes the big lock / `AS`" (`ksys/src/wait.rs:188-190`, `kernel/src/user/trap.rs:641`).
   With a shared VMO, another process can decommit the page through **its own** handle without this process's `AS`. Full path:
   the big lock covers it. This is the reason shared stays off the quiet path; check whether the existing private quiet path has
   the same exposure for a private key on a shared VMO mapping, and file an item if so.
4. **`forget_process` misses shared sleepers** if it still filters on the key (step 2), leaving an entry for a dead thread.
5. **Namespace collision**: a tuple `(u64, u64)` reused for both kinds lets pid 7 address X meet VMO 7 offset X: a cross-process
   wake with no shared mapping at all. Hence the tagged key and its model property.
6. **Quiet/full disagreement**: the flag checked in one path only (the quiet path restarts calls on the full path, so results
   must be identical); put the check in `ksys`, not in `kernel`.
7. **Wake authority**: any process that maps the VMO, even read-only, can wake (spurious wakes are allowed, so this is a
   nuisance, not a breach), see Q2.
8. Bucket hashing (`bucket_of`, `kcore/src/futex.rs:140`) must mix the tag, or the two kinds pile into the same buckets.
