## Shortcut

**Attributes, indexes and queries on disk** (step 6):

- (1) every built-in index entry (size, mtime, name) is maintained on every change: a write costs two more tree updates, and `put_inode` reads the old inode to diff it
- (2) the wire's query ids are 64-bit now (`proto::file::QueryHit`, `Query::after`), `memfs` still returns 32-bit ids widened
- (3) at most 16 user indexes, numbered once and never freed (there is no `DropIndex`)
- (4) a query scans the index range and filters by walking each hit's parents, so a selective term over a huge volume is fast and a broad one below a small subtree is slow (no per-subtree index)
- (5) ties in `(key, id)` order are by disk id, which `memfs` cannot match (it reuses ids): the differential compares as sets and checks paging on the disk side alone
- (6) `MakeIndex` needs `WRITE` on the connection (the `INDEX` right is still undefined, T109 (3))
- (7) `MAX_KEY` is 600 so that an escaped 255-byte index value fits a tree key.

## Why it was acceptable

The semantics are those of `memfs`, differentially tested; costs are performance only.

## Proper fix, and when

- (1) and
- (4) with a cache and a measured workload; (3) never needed so far.
