## Shortcut

`tsearch`, `tfind`, `tdelete` and `twalk` (`libc/src/search.rs`) are a plain binary search tree. Keys inserted in sorted order make a list, so the cost is O(n) per call instead of glibc's O(log n); `twalk`'s pre-, post- and end-order visits follow this tree's shape, not glibc's red-black tree (the in-order sequence, the only part that does not depend on the shape, is identical and is checked against the host). `hsearch` is one fixed-size table of `nel` entries (never grows; ENOMEM when full), with its own hash; `hdestroy` frees the table, not the keys (glibc's behaviour; BSD's frees them, so the host oracle cannot call it).

## Why it was acceptable

Programs use these for small tables; the results are correct, only the shape and the speed differ.

## Proper fix, and when

A balanced tree (AVL or the red-black tree glibc uses, so that the pre- and post-order calls match) when a program that walks in those orders or inserts sorted data in bulk appears.
