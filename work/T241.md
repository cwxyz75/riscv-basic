**What.** (1) `user/trap.rs` `activate_current`: on the L20 syscall path `with_state` is outermost and can switch threads between computing `token` and installing it, so "refreshed and flushed just above" can be false; harmless only because the tail re-validates before `sret`. (2) `user/calls.rs` `general_of` reads a suspended thread's frame under a comment that says the big lock is held (false since L20); a thread whose wait ended writes its frame (`reply`, `sepc -= 4`) before parking: mixed old and new register values, not corruption. (3) The UART and `sifive,test` addresses from the device tree are bounded by `DIRECT_MAP_PHYS_LIMIT` but not checked against RAM, the image or reserved ranges (`aia::discover` does); `dtb_blob` assumes every tree frame was direct-mapped though `kmem::init` skips those outside `/memory`. (4) `heap::grow` and `kstack::make_slot` flush only the local TLB after making an invalid mapping valid: on hardware without Svvptc another hart may take a fatal kernel page fault (QEMU does not cache invalid entries).
**Why acceptable.** Each holds on QEMU `virt` and on every path traced; none is reachable by user mode except (1), which has no effect found.
**Done (2026-11-23):** (1) the token is computed and installed in one section of the object lock (`bkl::ensure`). Left: (2), whose comment now says what is true, (3), and (4).
**Proper fix.** (1) install the token under the lock or re-check after; (2) take the thread's lock or re-check the state; (3) check firmware addresses like the AIA's; (4) a remote fence or retry on a stale-invalid fault.
