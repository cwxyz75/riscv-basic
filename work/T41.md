## Shortcut

**Device authority stand-ins (S6a).** The DMA budget is one system-wide constant (`MAX_DMA_TOTAL_PAGES`), not a per-job quota; `DEVICE_WINDOWS` is a hard-coded QEMU `virt` constant (the device manager now reads the slots from the device tree, S6c, but the kernel still only lets a physical VMO name the fixed window; likewise `MAX_IRQ`, the PLIC base and RAM size); any number of physical VMOs may alias the same slot (no exclusivity, so two drivers could fight over a device); physical VMOs are pinned to the root job and counted as one object.

## Why it was acceptable

Only the privileged boot process holds the resource, and the test suite and (S6c) the device manager are its only users.

## Proper fix, and when

Per-job DMA quota; windows from the DTB; an exclusive-claim record per device slot.
