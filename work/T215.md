title: user copies (copy_from_user, copy_to_user in syscalls) still run under the big kernel lock; the chunked, lock-by-chunk shape of SCHED-SMP-SPEC 3.10 waits for L20
refs: [L17, L20]
blocked_by: [L20]
---

**What.** L17 parts b and c (PRs 404, 405) put each process's address space behind its `AS` lock and resolve user page faults without the big lock. The user copies that syscalls make (message bodies, thread state, debug writes, futex words) still run inside the syscall, which holds the big lock throughout, and hold the caller's `AS` lock plus the memory locks for the whole copy. SCHED-SMP-SPEC 3.10 asks for copies in chunks of at most 16 KiB with `AS` taken per chunk and a preemption point between chunks, and for the copy-in to finish before `OBJ` is taken.

**Why acceptable.** The copy and the object state it feeds are one critical section under the big lock today; splitting them needs the object domain (`OBJ`) as its own lock, which is L20. Doing the chunking before would only move the big lock's hold around.

**Proper fix.** With L20: copy-in to a kernel buffer holding only `AS` per chunk, then `OBJ` for the queue operation; copy-out as `AS { verify; OBJ { dequeue }; first chunk }` then the rest; `pair_scaling` for 64 KiB copies against the target.
