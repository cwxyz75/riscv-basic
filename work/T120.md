## Shortcut

**UV1 leftovers**:

- (1) `rename` does not follow links in either path (a link in a parent path is `NOT_DIRECTORY`): the protocol's rename takes both paths relative to one connection, so the libc cannot pre-resolve them separately
- (2) `memfsd` reports links but cannot create them, so only `fsd` volumes have links until UV2 gives the launcher's skeleton a server that does
- (3) lexical `..` differs from physical `..` across links (the documented deviation of USER-VIEW-SPEC section 5), and a cwd whose parent is renamed keeps its old name
- (4) `chdir` opens a new connection per call and closes the previous one (a descriptor opened relative to the old cwd keeps working)
- (5) an unannotated directory descriptor cannot be the base of a path that climbs (`EACCES`), and every directory the libc opens is annotated, so this is untested beyond the model
- (6) the shell's `cd` opens through its own root connection and does not follow links
- (7) no `lstat`, `readlink`, `symlink`, `fstatat`, `unlinkat` or `fchdir` yet.

## Why it was acceptable

Correct against the model and on QEMU for the cases above.

## Proper fix, and when

- (1) with the next protocol revision
- (2) UV2; (7) UV3.
