## Shortcut

**GNU gzip 1.13 is a port with shims** (2026-11-17): built unmodified from the fetched sources without `configure`, against `third_party/compat/` (a hand-written `config.h`, `getopt_long`, and stand-ins for the gnulib parts it uses: `xalloc`, `dirname`, `yesno`, `stat-time`, `savedir`). Stand-ins:

- (1) `fdutimens` does nothing and succeeds, because the file systems keep no settable times (`utimensat` is `ENOSYS`) and files in `/tmp` have modification time 0, so `gzip` without `-n` warns "file timestamp out of range" (exit status 2)
- (2) `HAVE_OPENAT` is 0, so `gzip` never opens a directory by descriptor (`fdopendir` and `unlinkat` exist only to link)
- (3) only the program `gzip` is installed: `gunzip` and `zcat` need the program name, and the `z*` scripts are not installed
- (4) the tests are the host's zlib reading our output and ours reading the host's (the oracle), plus a round trip, not gzip's own test suite (`tests/` is shell scripts for a `configure`d tree). `memfsd` now serves `ATTR_SET`/`ATTR_GET`/`ATTR_REMOVE`, so `chmod`/`chown` and `fchmod` work in `/tmp` (before, they were `EINVAL`).

## Why it was acceptable

A real compressor and decompressor with the host as the oracle, and no change to the kernel.

## Proper fix, and when

Settable times in the file protocol; `gunzip`/`zcat` names (links or a name table in the shell); run gzip's own tests with a shell that can (hush)).
