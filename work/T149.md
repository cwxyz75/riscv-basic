Today `libc/src/sig.rs` ignores 17 to 23 and 28 (SIGCHLD, SIGCONT, SIGSTOP, SIGTSTP, SIGTTIN, SIGTTOU, SIGURG and the non-POSIX SIGWINCH) and terminates on everything else, so only the stop and continue ones differ. Possible senders for the rest: SIGXCPU from a job's CPU quota, SIGXFSZ from a file-size or volume quota, SIGTRAP from `ebreak`, SIGBUS from a misaligned access, SIGFPE from nothing on RISC-V (division by zero does not trap, so only an explicit `raise`). Each has a host oracle where the host can run the same program (`libc/tests/c/signals.c` is the model, OD119).

## Risk

Until built, a program that holds Ctrl-C off can only be ended from another session, and programs that rely on SIGPIPE, SIGHUP or SIGCHLD behave differently from Unix.

## Proper fix, and when

Slice with the signals subset (OD119) and the job table; needs an OS decision-log entry for the keys, the stop/continue semantics and the fault-to-signal mapping.
