title: the AS lock's `held_mut` hands out `&mut` through `&self`; and a call that names a process locks every address space
refs: [L17, L20]
---

**What.** (1) `klock::aslock::AsCell::held_mut` gives `&mut AddressSpace` from `&self` after checking that this hart holds the lock: the cell is shared by `Arc`, so nothing stops safe code from keeping two references alive across each other. The kernel's discipline (one reference at a time) is the whole guard, as it is for `state()`. (2) `process_table_call`, `thread_spawn`, `process_start`, `pager_supply` and the copy-log sync take **every** address space's lock, ascending, before the memory locks, instead of the caller's and the target's.

**Why acceptable.** `ksys` is `forbid(unsafe_code)` and its functions take `&mut UserState`; making the access `unsafe` would put an `unsafe` block at sixty sites for no checking. Every site was traced in the L17 review (PR 404): none overlaps. Under the big lock, which still covers all of it, the take-all costs a few locks per call and blocks no one (a page fault on another hart waits on the big lock anyway). It starts to matter when part c lets faults run without the big lock.

**Proper fix.** Hand the reference out through the holder (`AsHold::get_mut(&mut self)`), so the borrow checker sees one holder per space, and resolve the target process of a call before the memory locks so that only the caller's and the target's are taken. Do it with L20, when the object lock is explicit and the call structure changes anyway.
