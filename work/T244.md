---
id: T244
kind: tidy
title: rt::start_arg is shared by all threads of a process
area: libc
horizon: long
refs: [T243]
---

**What.** `rt_start` stores the thread's `a0` in a process-wide `START_ARG`; every thread that enters through `rt_start` (a thread started at the program's entry, as the suite's child threads are) overwrites it, so `start_arg()` returns whichever thread stored last.
**Why acceptable.** Only the test programs start threads at the entry with different arguments, and the one test that does now waits for the first thread to read its argument (T243).
**Proper fix.** Keep the argument per thread: in `rt_start` hand it to `app_main` (or keep it in the thread's `tp` slot) instead of a global.
