title: Thread creation panics when the kernel is out of frames for a kernel stack
area: kernel
horizon: long
risk: H
---

**What:** `new_kthread` in `kernel/src/thread.rs` ends in `expect("memory for a kernel stack")`. A user program that starts threads until the frame pool is empty reaches it.

**Why acceptable for now:** found by the KT3 review (2026-11-18); thread counts are bounded by the job limits, and the suite does not drain frames.

**Risk:** H. A user-controlled path to a kernel panic.

**Proper fix:** `new_kthread` returns an error, `thread_spawn` and the process start path reply `NoMemory`, and a test exhausts frames with a job-less process. Tied to KT8 (the assert and allocation blind spots).
