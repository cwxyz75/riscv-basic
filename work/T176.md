title: The host fuzzer (KT8) does not yet reach full queues, port polling, frame exhaustion, and its fake memory is permissive
refs: [KT8, TS3]

Left over from the Fable review of the KT8 host fuzzer (2026-11-20), after the findings that were fixed in the PR (the reference-count, queued-bytes, peer and end-of-sequence audits; the kernel's own cleanup, sweep and wide-argument check around every call; the generator's transaction ids, partial rights, job pinning, job-charged VMOs and received handles). What remains, each with the change that fixes it: (1) **Full queues and bounded buffers**: messages are at most 64 bytes against a 128-message queue and sockets write at most 128 bytes against 64 KiB, so `ShouldWait` on a full queue, partial socket writes and the byte ceilings are not hit; add a size distribution with tails (0, 1, 4096, 32767) and a "repeat the last call k times" operator. (2) **Ports are never polled** (`port_wait` lives in `user.rs`, until TS3c): one-shot disarm, the `next` rotation and the fix-ups in `prune_port` and `port_unbind_in` are unreached; track `(port, key)` in the model and add a harness pseudo-call running `ipc::port_poll_in`. (3) **Frame exhaustion**: 400 frames and at most 4-page commits, so the partial-commit rollback and out-of-frames paths of usercopy never run; derive the frame count from the seed (some at 24 to 40) and allow commits up to the VMO size. (4) **`FakeMem` never complains**: a read of an unwritten frame returns a pattern and a write to any address creates it, so a wild physical write or a use after free is invisible; record the pfns written during a call and check each is managed with a positive count, and at the end of a sequence that allocated frames equal page-table frames plus committed VMO pages. (5) **The audit settles** the ledger after every call (`ipc::settle`), so a call that forgot to settle first would pass; audit without mutating (`used - pending == held`, with a read-only `Registry::pending_credits`). (6) **Dirty log**: the harness drains it, so the touch logic and `Faults.skip_forced_touch` are not checked; snapshot the signal words before a call and require every changed or destroyed object to be in `peek_dirty()`. (7) `Sched2::audit` and `WaitTable::audit` need threads and waits, which TS3c moves. Why acceptable: the planted-defect acceptance (a panic, an uncredited object charge, an uncredited queued-byte charge, a leaked reference) is met, and 2,500 seeds of 600 calls under the checked build find nothing. Risk: a defect in the paths listed passes the fuzzer. Proper fix: the six changes above, then re-run the plants.

Progress (2026-11-24): (1) done: message and socket sizes have tails (`Gen::size`: 0, 1, a page, 32767, anywhere below) and one call in twelve repeats the last one; (3) done: one seed in four runs with 24 to 43 managed frames (`world_with_frames`), so commits run out and roll back. 400 seeds of the default length pass. Still open: (2), (5), (7).

Progress (2026-11-24, later): (4) done in part: every frame the fake memory reads or writes must be one the frame database manages (a wild physical access fails the audit); the check of pfns against allocated frames at the end of a sequence is not built. (6) done: before each call the fuzzer snapshots the signal words, and after it every object that gained a signal bit or went must be in the dirty log (a port counts when something it binds is); with `touch` removed from `Kobjs::get_mut` every seed fails. Still open: (2), (5), (7), and the end-of-sequence frame count of (4).

Progress (2026-11-24, third): (2) done: every fifth call the harness polls a port the process holds (`port_poll_in`, `port_poll_many_in`, as `port_wait` does), and what comes back must carry a signal; (5) done: the ledger audit no longer settles first, it subtracts the credits still owed (`Kobjs::pending_credits`). Still open: (7), and the end-of-sequence frame count of (4).
