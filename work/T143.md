## Shortcut

**An intermittent CI failure in the alarm check of `signals.c`** (2026-11-17): `sleep(10)` interrupted by `alarm(1)` sometimes returned a time left outside 1 to 9 seconds on CI's machine (three times in six runs of the shell-test job on PRs 219 and 220; never locally, never in the first PR that ran it). The check allows any value from 1 to 9; the C file now prints `DEBUG sleep left N, handler H` before the expected line when it is out of range, so the next failure says which value it was. Suspects: the alarm firing at once or very late under load, or the guest clock stepping.

## Why it was acceptable

The rest of the shell test is stable; rerunning passes.

## Proper fix, and when

Read the value from the next failure; if it is 0 or 10, look at `sig::wait_any` and the alarm deadline against `clock_get` under a loaded host.
