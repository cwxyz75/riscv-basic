## Shortcut

**Service death policy = rebuild the whole stack** (S4): `init` still rebuilds `memfsd`, `launcher`, `consoled` and `sh` together and `memfsd` state is lost on restart. (The registry service exists since slice SD, and the network stack publishes through it; the old servers and the clients' reconnect-on-`UNAVAILABLE` are SD step 4, not done.)

## Why it was acceptable

Memory filesystem has nothing to keep; keeps S4 small.

## Proper fix, and when

A name/registry service with reconnect, and real state recovery with the disk filesystem (S6+).

(Migrated from the old TIDY-UP register, section "Services and userland", 2026-11-18.)

- **Still true.** The session's four watched processes are rebuilt together, and the old servers are wired by static role channels.

### 2. Proposed design

1. **A pure session-supervision table** in `supervise`: per child a class (`Restart` in place, `EndSession`, `Degrade` = log and go on without it), its dependencies (start order, and "restart these with it"), and the existing intensity rule. `sessiond` and `volmgr` both use it; `Policy::NET` stays as is.
2. **`sessiond` watches every process it starts**, keeps (and closes) every handle, and keeps its own `apps` job handle so a launcher can be started again.
3. **Old servers publish** (SD4): `launcher`, `devd`, `procd` and `memfsd` get a `ServiceRegistry` connection with `PUBLISH`, publish a listener and serve forwarded opens through `rt::service` (as `clockd.rs:223-230` does). The static role channels stay for one release (SD-SPEC section 3), then go for clients.
4. **Clients reconnect**: `rt::fs` namespace roots and `rt::launch` remember (registry view, name, rights) and reopen with `open_retry` on `PEER_CLOSED`/`UNAVAILABLE`, bounded by a deadline. An open file or a running request is **not** resurrected: it fails with the peer-closed error and the caller sees it. `/tmp` comes back empty.
5. **Restart in place** in `sessiond` for the `Restart` class; the session ends only for the `EndSession` class or when the intensity rule says `Down`.
6. **Publish retries** a refused live name for a bounded time (replaces `volmgr`'s fixed 200 ms wait).

Proposed classes (the owner decides, Q3): `sh` exit = session ends (as now); `consoled` = `EndSession` (it owns the terminal socket the shell reads; a second `consoled` on the serial line while the first drains would interleave bytes and break the `##TEST` framing); `launcher`, `devd`, `procd`, `clockd`, `volmgr`, `memfsd` = `Restart`; `devmgr` and `registryd` = `Restart` with their dependants (everything published must republish).

Rejected alternatives:

| Alternative | Why not |
|---|---|
| Keep "rebuild the whole stack" and close T15 as by design (one-for-all) | Legitimate and cheapest, but it is the owner's call (Q2); it leaves SD-SPEC section 1's reason for the directory unmet for the old servers |
| The registry queues opens while a service is down | OD78/SD-SPEC section 2: "queues nothing, the client retries" |
| Carry `memfsd`'s `/tmp` across a restart (a VMO handed to the successor, or a state server) | The item itself says the memory filesystem has nothing to keep; durable data is doofs's job and that is built |
| A kernel aid (a "restartable endpoint", re-pointing a dead channel) | The kernel is at its freeze; SD4 invariant "the registry holds no client endpoint" and H4 would both need new kernel semantics |
| Reconnect hidden inside every `Fs` handle (open files reopen themselves) | Silently changes file position, lock and unlinked-file semantics; ish design rule is loud errors |
| `init` supervises the services itself | T128 took that authority out of `init` on purpose |

### 5. Invariants, locks, and how this goes wrong

No kernel code changes, so **no lock class is touched** (`OBJ`, row 1 of the lock-order table, and the rest of INVARIANTS.md "Lock order" stay as they are). If the work seems to need a new syscall or signal, stop: that is a post-freeze ABI change and an owner decision.

| Row | Why it matters here |
|---|---|
| H3 (rights only shrink) | views and the no-`PUBLISH` clones; a reconnect must reopen with the rights first granted, never `ALL` |
| H4 (a message in flight owns its handles) | a client endpoint forwarded to a listener whose server just died must be closed, not leaked: the halt leak checks are the test |
| J2, J5 (charged once, credited once) | every restart makes channels, listeners and a process; a crash loop must not creep toward the session job's object limit (4000, `session.rs:124`) |
| J3 (no ambient job authority) | `sessiond` keeping `apps` widens what it holds; keep it `MANAGE\|TRANSFER` only, and see T133 (1) |
| N1, N2 | reopened namespace roots must be the same directory, not a wider one |
| SD1 to SD5 (SD-SPEC section 4) | the whole of PR 3; SD3 (every replaced listener is closed) on every republish |

Subtle failures to look for:
1. **Republish race**: the new server publishes before the registry has seen the old listener close, gets "live name", and gives up; or two instances both believe they hold the name.
2. **Reconnect storm or hang**: clients retrying without a deadline while `sessiond` is in back-off; `stop_stack` (`session.rs:427-441`) already calls `open_retry` with 1 s per volume and would stall shutdown if the registry is the dead one.
3. **Orphans of a dead launcher**: its programs live on in `apps` with nobody waiting on them; the new launcher has no record, so `jobs`/`kill` in the shell and `procd`'s control channel (`session.rs:248`) disagree with reality.
4. **Half-dead dependency chains**: `registryd` restarts and every published name is gone until each publisher notices (they hold a dead registry connection and are otherwise healthy: nothing tells them to republish).
5. **Private `/tmp` directories (UV2)** vanish under running programs when `memfsd` restarts; the shell's cwd connection dies with it.
6. **Masking real bugs**: restart in place turns a crash that today fails a test loudly into a log line. Every restart must print a structured line the boot scripts treat as a failure unless the scenario expects it.
7. **Test-budget creep**: the kill scenario with back-off delays can add tens of seconds to a job with a 7-minute limit.
