title: Thread ids are a u32 counter with no wrap rule
area: kernel
horizon: long
risk: L
---

**What:** a `Tid` counter gains one per thread start (`kernel/src/user.rs` near line 396, allowed under KT3 as "a u64 counter"). The width and the behaviour at wrap are not written down.

**Why acceptable for now:** a u64 counter cannot wrap in the life of a boot; it matters only if `Tid` is narrowed in the ABI.

**Risk:** L.

**Proper fix:** state the width in SYSCALLS.md, and when `Tid` is narrowed give it the same skip-live wrap as pids (done in KT3 review for pids).
