**What.** The owner decided on 2026-11-27 (OD175, IOMMU-SPEC amendment 2026-11-27 part 2) that no test machine carries QEMU's
`iommu-testdev`. The device verifies the word it wrote at a *physical* address, outside the IOMMU, and its BAR is in the admitted
PCI memory window. So the holder of the root resource could use it to probe physical memory, the kernel's included. Remove it,
and build what the amendment says in its place:

1. **The machines.** Drop it from `scripts/os_boot_test.py` (PCI_DEVICES slot 8 and the comments), from
   `.github/workflows/qemu.yml`, and from `.github/actions/install-qemu/check-qemu.sh` if it only checks for that device. The boot
   script **refuses** a command line that names `iommu-testdev`, with a test of that refusal (the same style as its other refusals).
2. **The suite.** Every check that used the test device uses a hand-driven virtio-pci function instead (the entropy function
   of the matrix's device rig, or the scratch disk), aimed at the same targets: the hostile-driver matrix's device rows (IOMMU12,
   `with_matrix`), `iodomain_maps_exactly_what_was_granted`'s access at the frames' physical addresses and at address 0, and any
   other user (`grep -n testdev init/src/bin/suite.rs`). A refusal is shown by the IOMMU fault record (the device's domain and the
   last-fault counters) and by the target's and bystanders' memory being intact, never by a read-back at a physical address. Each
   rig first checks its legitimate use, as now. `devmgr`'s bus-listing test expects the bus without the test device.
3. **Keep the oracles independent.** Where a row needs the frames' physical addresses as a target, take them from the test
   kernel's existing means (a `debug_stat` selector or the like, test kernels only), not from any call a release kernel has. If no
   such means exists, add one only to test kernels, and say so in `SYSCALLS.md`.
4. **References.** `INVARIANTS.md` D2 (its exception for the test device goes; D2 now holds without one), `TEST-TOOLS.md` and
   `TESTING.md` wherever the device is named, and the comments in `pcicore` and `iommucore` tests. Leave the `pcicore` host
   fixture `iommu-testdev.cfg` only if it still tests the parser on a non-virtio function. Otherwise remove it.

**Acceptance.** `grep -rn iommu-testdev` over the scripts, workflows and `init/` finds only the boot script's refusal and its
test. The hostile-driver matrix and `iodomain_maps_exactly_what_was_granted` pass in shard `k` at 1, 2 and 4 harts with the same
rows as before (none dropped), and each refusal row still fails under its negative control where one exists. Zero IOMMU faults in
every boot without a deliberate fault. Verified by the epic's smoke.

**Not in this item.** S6-SPEC's testing list (around line 146) still names `vmo_phys_addr` refusing a handle without DMA. The
2026-11-25 amendment supersedes the calls but not that line. The spec is the owner's to amend.
