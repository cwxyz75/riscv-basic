**How.** KERNEL-V1-SPEC 4.6; settles the open point of SCHED-SMP-SPEC 3.12 and section 10 (chosen: marking in slices with an epoch, on the calling thread, not a sweeper thread). `kcore::object::Registry`: a sweep is a state machine (`Idle`, `Marking { epoch, worklist }`, `Freeing { cursor }`); `sweep_step(budget = 256)` does one slice under the object lock; between slices the lock is dropped and `preempt_point()` runs. While a sweep is in progress, inserting a handle into a table or a message (`retain`, transfer) marks the object in the current epoch (a write barrier), so nothing reachable at the end is freed. The trigger (`needs_sweep`) is unchanged; object-creating calls run steps until the sweep finishes or their own budget of 4 slices is used, then proceed (a creation that still finds the cap reached returns NO_MEMORY as today).

**Acceptance, written first.** `kcore/tests/registry_model.rs` extended: random mutations interleaved between sweep steps against a full-graph reference (no reachable object freed; every unreachable cycle freed within two sweeps), mutation-checked (the barrier removed). The latency trace's worst interrupts-off section with 16,000 live objects and a cycle churn is under SCHED-SMP-SPEC's B1 restated value. Closes T76.

**Review.** Fable.
