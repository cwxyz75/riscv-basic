**What.** OD138 asked for a buddy frame allocator plus a slab allocator, with `linked_list_allocator` retired. The slab half is built. The last step (this item; it was T196, closed on 2026-11-23 on cost, see `docs/records/done.md` and WORK-PLAN line 267) is not: the allocator keeps its frame pool and the fallback first-fit heap, because an inline frame take would deadlock. `kmem::mem()` holds `VMO`, `JOBS` and `FRAME` together for a whole memory operation, the code under them allocates (`Vec`, `BTreeMap`), and `FRAME` is below `HEAP` in the lock order, so the allocator cannot take it.

**Why acceptable for now.** The pool serves every small object and the fallback is the proven path; nothing a test can see is wrong.

**Risk.** The pool and fallback keep the allocator coupled to the memory locks, which is the shape that makes class N (allocation that must not fail) hard and keeps the first-fit heap in the kernel.

**Proper fix (OD154).** (1) A physical frame allocator that is a leaf: its own small lock or per-hart caches, metadata allocated once at boot from RAM (OD138), no allocation of its own, callable under any other lock. (2) The frame database (ownership, reference counts) and job accounting split from it: the allocator hands frames out and takes them back, the caller charges the job. (3) The slab layer refills from (1) with no caller lock held, or from a reserve. (4) A reserve for paths that must not fail (T247/T248 class N, T255's kernel frame reserve). (5) `linked_list_allocator` and the fallback heap go. Making every `FRAME` section allocation-free is the main work and is the same restructuring of the memory paths that T255 (frames under pressure) and T204 (narrow the locks a call takes) each do part of: design those as stages toward this. Needs its own plan (a fresh Fable pass) after T255, and a spec amendment to KERNEL-V1-SPEC 4.2 if its text moves.

**Done when.** The kernel builds without `linked_list_allocator`, the frame allocator takes no lock held by its callers, a test boots with the fallback heap removed, and the allocation-failure sweep (KT9) still passes.
