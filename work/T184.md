title: PL6 leftovers: the optional interrupt in devmgr, the network driver and the block service's grant
refs: [PL6, PL5]
---

PL6 made the AIA a requirement and removed the block driver's polling mode (`blkd` now exits with code 3 without its `BlkIrq` handle). What remains of the "no interrupt" shapes: `devmgr`'s `Block.irq`/`Net.irq` are `Option<u32>` (an `interrupt_create` that fails, for example a source taken already, leaves the device without one and `blkd` then refuses to start), the network driver's `irq: Option<u32>` and the `NET_FLAG_IRQ` protocol flag (the driver's own safety poll, NET8, stays: it is a different thing). Why acceptable: the AIA machine always gives the interrupt, so the options are never `None` on the one target; the failure is loud for the disk. Proper fix: make the interrupt mandatory in `devmgr` (a device whose interrupt cannot be created is not started and the manager reports it), drop the flag from the protocol with its tests.
