## Shortcut

**BusyBox (UV8) and the libc growth behind it: shortcuts** (2026-11-17):

- (1) **no `ash` and no `timeout`** (`xargs`, `env`, `nohup`, `time` and `find -exec` work since OD118/T136: programs can start programs): BusyBox NOMMU's shell needs signals and to be the system `sh` (S11, SH7); `timeout` needs `sigaction` and `alarm`
- (2) **signals are recorded, not delivered**: `signal`, `sigaction`, `sigprocmask` and the `sig*set` calls are declared (header) but only partly implemented (a handler is stored); `kill` fails; `alarm` is not built
- (3) the libc functions written for this are tested only through BusyBox's own applets in the shell test (and `pregex` on the host against `grep`): (`fnmatch`, `getopt` (POSIX, no permutation: options end at the first non-option) and `strverscmp` now have pure cores in `cfmt` with differential tests against the host's libc, `cfmt/tests/portable.rs`: they found `FNM_CASEFOLD` ignored on an escaped character, fixed) `sscanf` (now `cfmt::scan`, differential-tested against the host's `sscanf` with 40000 generated format and input pairs; the signal table is `cfmt::sigtab`, tested against the host's `sigaction`/`sigprocmask` in nested handlers, with scenarios whose order between two ready signals is the system's left out, and `SA_RESETHAND` exercised on Linux only), `realpath` (lexical; symlinks are not resolved), `dup`/`dup2` (standard streams only), `opendir` (a snapshot taken at open), `mkstemp` names (clock and counter, not random), `getpwuid` and `getgrgid` (only the session's own identity from `USER`, `UID`, `GID`, `HOME`), `uname` (fixed strings), `ctime` (UTC), `ioctl` (always `ENOTTY`, so the window size is 80x24)
- (4) **not built (`ENOSYS`)**: `mmap`, `statvfs`, `utimes`/`utimensat`/`futimens` (the file protocol cannot set times, so `touch` fails), `mkfifo`, `mknod`, `strptime` (so `date -d` fails), `clock_settime`, mount tables (`df` shows nothing)
- (5) the configuration is a subset (about 90 applets and the features listed in `scripts/busybox_configure.sh`): no networking, init, mail, modules, `ps`/`top`/`free` (our `/proc` is not Linux's), `ar`/`tar`/`gzip`
- (6) (resolved 2026-11-17) the tests run only where the BusyBox sources have been fetched (`make fetch-third-party`); CI's `kernel (shell test)` job and the soak workflow now fetch them (`FETCH_ONLY=busybox`, pinned by sha256, cached), so the shell test runs there
- (7) `clang` puts an uninitialised `const` object in read-only data and BusyBox's `ptr_to_globals` is one, so the build defines `BB_GLOBAL_CONST` empty (the ELF loader does enforce read-only).

## Why it was acceptable

Gives the corpus real `wc`, `sort`, `grep`, `sed`, `awk`, `find` and friends over our files, without a process-spawning libc.
