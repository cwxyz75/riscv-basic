## Why it was acceptable

Every one of these reviews' high-severity findings is recorded as fixed; the gaps are medium and low findings and suspicions,
and most reviews say their unfixed findings were "fixed or recorded", which was not always itemised.

## Risk

A real bug among them stays unfixed with nobody looking for it.

## Proper fix, and when

Check each against the code (a fresh-context pass is the cheapest way; read only the finding and the code it names). For each:
close it in the dispositions record by appending a line (fixed in which commit, or accepted and why), or make it its own work
item. Close this item when the list is empty.

## Stability epic (2026-11-27)

**Why it is in the epic.** Several of these are suspected failure sources, not polish: the security review's suspicions 6
(infallible kernel allocations on user-driven paths), 7 (long holds at teardown and unmap) and 10 (frame overcommit), the
growable-heap review's open findings, the L11b scheduler review's 5 to 13 and the L12 step 1 review's. A finding that is a live
race or crash is exactly what the epic is hunting, found by reading instead of by waiting for a flake.

**Scope (one PR, documentation and work items, plus tests where a finding is shown).** A targeted review pass (Opus, fresh
context per review: read only the finding and the code it names today), one disposition line per finding appended to
`docs/records/review-dispositions-2026-11-18.md` (fixed in which commit; overtaken by which change; accepted and why). A finding
that is still live and is a crash, hang, race or leak is shown with a test first (host where it can be) and then either fixed in
this PR if it is small, or joins the stability ticket whose subject it is (a new ticket only under the CLAUDE.md exceptions).

**Acceptance.** Every finding in the list has a disposition line; each "still live" finding has a test that fails on today's
code; the list in this item is empty and the item closes. No boot is needed for the documentation half; a fix follows the epic's
rules. Each review run is a reading pass, well under the two-hour cap.
