**How.** (1) Console: the NS16550A named by `/chosen/stdout-path` (its `reg`), else the SBI debug console extension; the literal `0x1000_0000` goes. (2) AIA: APLIC base, `riscv,num-sources` and each hart's IMSIC file address from the tree; `APLIC_BASE` and `abi::layout::MAX_IRQ` go (`interrupt_create` checks against the discovered count). (3) Physical VMOs: the kernel builds the list of device windows at boot from every `reg` range of nodes outside `/memory` that are not the console UART, the APLIC, the IMSICs or the test finisher; `abi::layout::DEVICE_WINDOWS` and `in_device_window` become a kernel table with the same rule (D1 unchanged). (4) Power off and reset through SBI SRST; the test finisher is used only when the tree has `sifive,test1` and the build is a test build.

**Acceptance, written first.** Host tests of the window builder on QEMU's real `virt` tree (dumped once with `-machine dumpdtb`, checked in under `kcore/tests/data/`) and on a synthetic one with an extra device. QEMU: `device_caps_need_the_resource` and the block and network driver tests pass unchanged; a VMO over the UART's range is refused.

**Review.** Fable (the window rule is a security boundary: D1).

## Progress (2026-11-20): PL5a, the device windows

Part (3) of the item, cut as PL5a. `kcore::devwin::device_windows(nodes, excluded, ram)`: every `reg` range of every node that is a device (not `/`, `/cpus`, memory, `/reserved-memory`, `/chosen`, `/aliases`), widened outward to whole pages, minus the nodes the kernel or firmware drives (by `compatible`: `riscv,aplic`, `riscv,imsics`, the PLIC, the CLINT and ACLINT, `sifive,test0` and `test1`, the power and reset syscons), minus the ranges the caller names (the console UART, the test finisher and the AIA's pages: constants until the rest of PL5) and minus RAM, as sorted, merged page ranges; `in_window` is the old rule (page aligned, non-empty, a whole number of pages, inside one window; wrapping refused). `kmem::init` builds the table once from the tree and keeps it (`kmem::device_windows()`); `ksys::Ctx` carries it (`windows`), `vmo_create_physical` checks against it; `abi::layout::DEVICE_WINDOWS` and `in_device_window` are gone. Host: `kcore/tests/devwin.rs` (the real `virt` tree with expectations taken from `dtc`'s listing of it: the RTC page, the virtio-mmio slots as one range, fw-cfg, the two flash banks, the PCI ECAM window; synthetic trees with an extra device, an unaligned one, a node sitting on RAM, partial overlaps with the excluded ranges; two mutants caught: RAM not cut, the never-a-window list dropped); the tree builder moved to `kcore/tests/common`. Verified: the host tests of `kcore` and `ksys`; the kernel-only boot at four harts (239 tests) and shard `a` (304 tests, which includes the block and network driver tests that map device windows), both exit 0. **A consequence the reviewer should weigh:** the set is wider than the old two-entry table (virtio and the RTC): fw-cfg, the flash banks and the PCI ECAM window are windows now, as the item's rule says ("every `reg` range ... that is not the console UART, the APLIC, the IMSICs or the test finisher"; the interrupt controllers' timer and the CLINT are excluded as well). A physical VMO still needs the resource handle (MANAGE), which only the device manager holds. **Left in PL5:** (1) the console from `/chosen/stdout-path` (the literal `0x1000_0000` still in `console.rs`, `kmem.rs` and the exclusion list here), (2) the AIA's APLIC and IMSIC addresses and source count from the tree (`APLIC_BASE`, `MAX_IRQ`), (4) power off and reset through SBI SRST with the test finisher only for test builds. Not run: smoke, soak.

**PL5a review (2026-11-20), decision taken without the owner.** The Fable review argued that the item's rule (every `reg` range of a node that is not RAM and not driven by the kernel) fails open: a denylist lets every device nobody thought of be mapped by the holder of the resource handle, and on `virt` that meant fw-cfg (its DMA interface writes arbitrary guest RAM), both writable flash banks and the 256 MiB PCI ECAM window, where the old two-entry table failed closed. I took the stricter reading of D1, which is narrower than the item and the spec: a node is admitted only if its `compatible` is on an allowlist (`kcore::devwin::ALLOWED`: `virtio,mmio`, `google,goldfish-rtc`, the devices the device manager drives; adding one is a deliberate edit), its `status` is not disabled and every bus above it has an empty `ranges` (a translating bus is refused, not translated); the ranges still come from the tree, and the denylist (interrupt controllers, timers, the finisher, the power and reset syscons) stays as a cut applied to every window, so a device sharing a page with a controller does not expose it. Recorded in the decisions list of `WORK-PLAN.md` and as a dated amendment to `KERNEL-V1-SPEC.md` 2.3. Other review fixes: the cut loop stops at the first range past the window; `reserved` ranges are cut with RAM; the acceptance fixture is in `kcore/tests/fixtures/`, not `data/`; the suite probes the finisher, CLINT, both APLICs, both IMSIC files, fw-cfg, both flash banks and ECAM (refused) and the RTC page (allowed); four mutants (the cut loop, the bus translation, the status, the cut of controller nodes) are caught.
