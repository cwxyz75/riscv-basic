kind: tidy
title: A program that starts without a system library cannot make a call; the process record keeps the library's range, nothing enforces it yet
area: kernel
horizon: long
refs: [AB7, AB8]
---

**What.** `rt` stops the program (`unimp`) when a call is made and no library was found (`a2` was 0 or not the library), and the kernel does not yet refuse an `ecall` from outside the library's text range, which `Process::libsys` records.
**Why acceptable.** Every process is started by `process_start` or the loader, both of which map the library; the enforcement is AB8, which has the kernel refuse an `ecall` whose `sepc` is outside `libsys.text`. **Risk.** Until AB8 a program written with its own `ecall` still works. **Proper fix.** AB8.
