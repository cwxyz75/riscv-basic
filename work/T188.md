Left from the Fable review of PL3 (2026-11-20), after the fixes in the PR. (1) The per-hart claim protocol (`claim`, `light_save`, the lock-free early return in `fp::return_to_user`) lives only in `kernel/src/arch/riscv64/fp.rs`; `kcore::fp` has the token model and its tests but no model of claims, so the invariants (one claim per thread, on its holder hart; a token kept by a lock-free save never lets another hart skip a load; a takeover clears the claim and forgets the token) are checked only by the four-hart boot. Proper fix: move the claim bookkeeping into `kcore::fp` behind the same unit trait and extend `vec_model.rs`/`fp_model.rs` with lock-free saves, migration and a second thread, mutation-checked. (2) No debug assertion that a claim implies the hart holds the thread's state (`harts[h].holds(t)`) in the locked paths. (3) `scripts/check_vector_codegen.py` skips when no archive was built and sums over archives (the C-test archive holds hand-written vector asm); `newest()` can pick a stale archive under `target/`. (4) The C `cbo.zero` line in the transcript is memset where the compiler lacks `__riscv_zicboz`; only Rust mode 98 tests it for sure. (5) `senvcfg` bits stick whether or not M-mode enabled the extension on QEMU as far as I know; presence is established by `dtb::require_extensions` and mode 98, not by the read-back. Why acceptable: the boot exercises all of it at four harts on the one target. Risk: a change to the claim paths is caught late.

Progress (2026-11-24): (2) done: `claim` asserts, in a debug build, that the hart holds the thread's state (k shard at four harts passes). (3) done in part: `REQUIRE_C_ARCHIVES=1` makes a missing archive a failure (the stale `newest()` pick and the sum over archives remain). Still open: (1) the host model of the claim protocol, (4), (5).

**Precondition (2026-11-24, owner's decision):** before building the rest of this item, have Fable write a design plan and append it here (a section "Plan (Fable, date)"): the move of the claim bookkeeping into kcore::fp behind the unit trait, its model and mutation checks, and how the unsafe-adjacent refactor is kept safe.

### 1. The claim state machine as the code has it

One instance per unit (FP, vector). Variables: the thread's `state: Option<(Box<R>, token)>` and `holder: Option<hart>` (C:140-144); the hart's `owner` token (C:218); the per-hart cells `claim` (a tid, 0 none) and `buf` (address of the box, 0 none) (`kernel/src/percpu.rs:116-120`); the frame's two bits (Off, Initial, Clean, Dirty).

| Step | Where | Effect |
|---|---|---|
| E enable | K:551-599, C:191 | state = (zeros, new token); frame Initial; no claim |
| S locked save | K:389-437, C:243-260 | frame Dirty and LS refused: `save_into`, new token, `owner = token`, then `claim`; frame Clean |
| L locked load | K:477-516, C:264-277 | frame Initial, or `claim[h] != tid`: load unless `owner == token`, `owner = token`, then `claim` |
| `claim(t, h)` | K:298-331 | if `holder == old != h` and `claim[old] == tid`: `claim[old] = 0`, `buf[old] = 0` (that order), `harts[old].forget()`; then `holder = h`, `buf[h] = addr`, `claim[h] = tid` (that order). The thread that had `claim[h]` is evicted and its `holder` goes stale: hence the `== tid` guards at K:312, 646, 701 |
| Q quiet return | K:461-476 | each unit Off, or (Clean or Dirty) and `claim[h] == tid`: no lock, nothing changes. Initial never passes |
| LS light save | K:337-373 | frame Dirty: reads `buf` then `claim`; if `claim == tid` and `buf != 0`, `save_into(*buf)`, frame Clean. Token, owner, holder and claim are unchanged. Otherwise false, and the caller takes S |
| W debugger write | K:687-711, 717-788, C:203 | if `claim[holder] == tid`: clear both cells, forget; new box, new token, `holder = None`; the frame becomes Initial later (K:792-811) |
| G thread gone | K:632-656 | clear both cells if `claim[holder] == tid` (no forget: the token dies with the state) |

Every cell write is under the big lock. `claim[h]` is set only by hart `h` (all four `claim` calls pass `hart()`); other harts only clear it, and only for a thread not running on `h`. The lock-free reads (Q, LS) are of the hart's own cells, interrupts off.

### 2. What moves, what stays

New in `kcore::fp` (no unsafe, no atomics: the C5 count of `check_docs.py` does not move):

- `trait ClaimCells { fn claim(&self, hart) -> u64; fn buf(&self, hart) -> usize; fn set(&self, hart, tid, buf); fn clear(&self, hart); }`. Contract: `set` stores `buf` then `claim`, `clear` the reverse, with today's Acquire and Release.
- `UnitTable<R, const N: usize>`: `tokens`, `threads: BTreeMap<u64, UnitThread<R>>`, `harts: [FpHart; N]`. Methods, each given `&impl ClaimCells`: `enable_with(tid, zero)`, `save_locked(tid, h, unit) -> bool` (S), `load_locked(tid, h, unit) -> Fs` (L; both end in `claim` with the `holds` assertion of K:323), `replace_regs(tid, regs)` (W, drop first), `thread_gone(tid)` (G), `regs`, `enabled`, `len`. `claim` and `drop_claim` become private.
- Pure decisions used by the lock-free paths: `enum Lazy { Off, Initial, Clean, Dirty }`; `light_target(cells, h, tid) -> Option<usize>` (the two reads of K:352-353); `quiet_return(fs: Lazy, vs: Lazy, fp_cells, vec_cells, h, tid) -> bool` (K:461-474); `after_load(Fs, Lazy) -> Lazy` (K:517-534).
- `FpHart`, `UnitThread`, `StateUnit` keep their API: `fp_model.rs` and `vec_model.rs` pass unchanged.

Stays in the kernel file: `HartUnit` and `VecHartUnit` (K:113-288, no line touched; enabling and disabling a unit is inside their asm), `VLENB`, the `sstatus` masks and the frame-to-`Lazy` conversion, `STATE` and `state()`, the `ClaimCells` impl over `percpu` (one type per unit), the two dereferences of `buf` in `light_save`, the two `csrc`, the job charge, `fault-skip-fp-save`, the EX1 layouts, `hart()`, the cache-block enable.

### 3. Invariants the model asserts after every step, for every (hart, thread)

- I1 one claim: `claim[h] == tid` implies `holder(t) == Some(h)`, `t` is enabled and `buf[h]` is the address of `t`'s box (compared as a `usize`). So one hart at most claims a thread, and no claim outlives W or G.
- I2 a kept token never goes stale: `harts[h].holds(t)` implies `claim[h] == tid`. A light save changes the copy under an unchanged token, so the token may match on the claiming hart only.
- I3 reference: at every return to user mode the unit's registers equal `want[t]`; whenever the frame is not Dirty the saved copy equals `want[t]`.
- I4 a quiet decision is the locked path's no-op: `quiet_return` says yes only where `harts[h].holds(t)`; an address from `light_target` is `t`'s box.
- I5 migration: once `t` returns to user mode on `h2`, no other hart claims or holds it.
- I6 the kernel uses no register: the model unit's registers are compared across every kernel stretch (trap to return) and may differ only by a counted `load`. On the machine FP3 stays `fp_unit_is_off`.
- Generator preconditions: W and G only for a thread on no hart; S, L, Q, LS only for the hart's current thread.

### 4. The model tests

`kcore/tests/fp_claim_model.rs`, written first, generic over the unit and run for both (`VecRegs` at `vlenb` 16 and 32). A random walk (`common::Rng`, `SEEDS`, `STEPS`) over 1 to 4 harts and 1 to 6 threads; each hart has a current thread or none. Steps: schedule a thread onto a free hart (a migration when it last ran elsewhere; threads sharing a hart), user code (enable; write registers: frame Dirty), a light trap (interrupt or lock-free syscall: LS, then Q, or the fallback to S), a full trap (S, then L or Q), preemption, W on a parked thread, G, and the tick that light-saves and then takes the lock (`trap.rs:535-548`). Named scenarios too: a thread alone on its hart does no load and no locked return after the first; A, B, light save on B, back to A reloads; W on a claimed thread reloads; a stale `holder` clears nobody else's claim.

`kcore/tests/fp_claim_concurrency.rs` (loom and shuttle, on the Makefile's model-checker lines beside `latch_concurrency`): `ClaimCells` over the checker's atomics. Hart 0 runs T and loops over `light_target` and `quiet_return`; hart 1, under a mutex standing for the big lock, takes over U, which held hart 0's claim. Asserted: hart 0 gets T's own address or `None`, and no quiet yes without its claim.

### 5. Mutation checks

By hand, once (`TESTING.md` rule 9): edit `kcore/src/fp.rs`, run `cargo test -p kcore --test fp_claim_model`, see the named assertion fail, revert; the list goes in the test file's header (as `vec_model.rs:5`, `sweep_slices.rs:6`; `wait_model.rs` documents none) and in INVARIANTS VS1's evidence.

1. `claim` omits `forget()` on the old hart: I2, and I3 on A, B, light save, A.
2. `light_target` drops the `claim == tid` compare (any non-zero `buf`): I4 (another thread's box).
3. `quiet_return` accepts Initial: I3 after W and after E (the zero state is never loaded).
4. `thread_gone` or `replace_regs` leaves the cells: I1 (a claim for a thread with no state; a `buf` that is no live box).
5. `claim` drops the `== tid` guard on the old hart: the zero-loads scenario.
6. `set` stores `claim` before `buf`: loom.
