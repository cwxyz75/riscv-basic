## Shortcut

**`ish` grammar v2 (SH2b, SH4b) leftovers** (2026-11-17):

- (1) **resolved 2026-11-17**: the five new corpus goldens (95 to 99), the Python `json`/`csv`/`decimal` oracles and the `bash -o pipefail` oracle (`ish/tests/oracles.rs`; the pipeline status differs from bash by design, R3 names the first failing stage) and the v2 token fuzz (`robust.rs`) are written, with hand mutations caught
- (2) interpretations taken where the spec was silent: `set` finds the nearest enclosing binding, hexadecimal number literals are dropped, a spawned shell command (a function or builtin) runs to its end at the `spawn` (no threads in the shell yet), `--help` in `parse-args` prints the usage and ends the script with status 0, `run` passes standard output through unless asked to capture
- (3) the OS host has no wait-for-many call, so `wait-any` polls each process every 2 ms, and a `spawn`ed job is not registered as the foreground job (Ctrl-C reaches the shell, which ends the wait with `interrupted`; the job keeps running until killed or the script ends)
- (4) a killed job's status is -1 in the OS (the fake host says 137).

## Why it was acceptable

Fits what a script on the host and a session need; each item is behaviour the goldens and the QEMU steps pin as it stands.

## Proper fix, and when

(3) a `wait` over several handles in the kernel, and the job in the console's foreground registration; revisit (2) with the owner.
