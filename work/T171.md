title: channel_write copies user memory before checking the channel handle
refs: [TS3, SYSCALLS]
---

Found by the TS3a review (2026-11-19). `channel_write` copies the message and handle list from user memory before it looks at the channel handle, so a bad pointer with a bad handle gives INVALID_ARGS where SYSCALLS.md lists BAD_HANDLE first (and the section lists no pointer error). Unchanged by TS3a. Why acceptable: both are errors, and no state changes either way. Risk: a program that probes handles with a null buffer reads the wrong error. Proper fix: check the handles (the channel, then the list) before the copies, or amend SYSCALLS.md to list INVALID_ARGS first; pin it with a host twin in `ksys/tests`. With TS3c or when KT4 next touches the channel rows.
