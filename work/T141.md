## Shortcut

**UTF-8 filenames leave gaps** (F6, `FS-SPEC.md`, owner 2026-11-17; not built until step 0b): names are compared byte for byte with **no normalisation**, so the precomposed and the combining form of one letter are two different names and look alike, and look-alike letters from different scripts are not detected; **bidirectional-control and invisible characters** (U+202E, zero-width) are allowed, so a name can display misleadingly; names that are not UTF-8 (old archives, Latin-1) are refused, so a ported program that makes one gets `EILSEQ`; the superblock has no feature-flags field, so a later "names must be NFC" mode is a format change (a version bump: acceptable, there are no volumes to keep compatible).

## Why it was acceptable

Valid UTF-8 plus no control characters keeps names text and safe in line output at no cost in tables; normalisation needs Unicode data in a `no_std` crate and a pass on every create and lookup.

## Proper fix, and when

Preferred direction (owner discussion, 2026-11-17): **preserving and normalisation-insensitive** (as APFS and ext4's casefold do): store the name as given, compare and look up by its normalised form, and refuse a create whose normalised form already exists in the directory; not rewriting names on store (HFS+'s way, which broke round trips through `git`, `rsync` and `tar`). No feature-flags word is needed (owner, 2026-11-17: there are no volumes in the wild to stay compatible with; a format change is a version bump and regenerated test volumes, and the superblock's version check already makes mismatched code refuse a volume); then an optional NFC-only mode (tables in the pure crate, checked by `fsck`), a refusal list for bidirectional and invisible characters, and an escaping option in the libc for programs that need raw bytes.
