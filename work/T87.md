## Shortcut

**S8 deviations from NET-SPEC** (autonomous run, 2026-11-15; the owner decides which to keep):

- (1) the driver does not read packet bytes (N3), so the receive header is validated by `netd` (flags and GSO), and `num_buffers` is not checked
- (2) restarting the stack restarts the driver with it (the new stack gets a fresh control channel); restarting only the driver re-attaches the running stack, as the spec asks
- (3) deliberate faults are switched on by a `FAULT=name` environment entry that `netsup` passes to its children (the spec asked for cargo features and separate builds): the test code is in the shipped binaries, enabled only by an entry the starter of `netsup` writes
- (4) the flight recorder is reduced to one `##NETFR` line of the shared counters when a child dies (no event ring, no frame heads)
- (5) the benchmark is the ping round trip only (`net_ping_rtt_p50`, `p99`: first numbers 2.5 ms and 6.3 ms on the debug build at four harts); `net_udp_echo_pps` and `net_bkl_profile` are not written
- (6) Q9 (ARP and echo storms from a second host-side injector), Q18's tier-2 modes beyond what the soak workflow already boots, Q19 (the 200-round churn) and the `cargo-fuzz` targets are not written
- (7) `Info` is 28 bytes (the draft said 26)
- (8) the registry connection `netsup` gets is cloned per child
- (9) the identifier a stack gives an echo endpoint is the only ICMP matching (no source check)
- (10) `GetStats` returns the core's counters then seven ring counters by position
- (11) the `PUBLISH` connection a restarted stack gets republishes over stale entries and relies on the registry noticing the closed listener

## Why it was acceptable

Each is tested where it exists
