title: ports report ready bindings in rotation, not oldest-ready-first, and a poll still scans the bindings
refs: [L21, T60]
---

**What.** W-SPEC 3 and 2 call for a per-port first-come list of ready bindings, so that a poll reports the oldest ready binding and costs O(1). L21 built the wake-one baton, the binding lifetime and the exact reply registration, and the port watch that evaluates a port only when something it binds is touched, but not the ready list: `port_poll_in` still rotates through all bindings from a cursor and tests each (`binding_ready`), and a commit that evaluates a port (`object_signals` of a port) scans its bindings once.

**Why acceptable.** A touch of a bound object costs one scan of that port's bindings (tens for a server, thousands only in a stress test), not one per commit per port as before; the rotation is fair (no binding starves); the order W-SPEC accepted changing is the one that was already there.

**Proper fix.** Keep per port a first-come list of ready bindings, updated when a touched object's signals change (P1: the list equals the scan after every step, the scan kept as the test oracle), with the reverse index from a bound object to its bindings that L21c's `Slot::watchers` count stands in for; the poll takes the head, the commit reads the list's length. Then `channel_call`-style and port waiters cost O(1) per touch.
