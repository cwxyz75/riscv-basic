## Shortcut

**Per-job limits now cover processes, threads, memory pages, child jobs, objects and queued IPC bytes (S4.5, S4.5c).** Kernel stacks are charged since slice T (four pages per live thread, to the thread's job). Still not charged: the memory of kernel objects themselves, and page tables are an estimate. The global caps remain as backstops. Credits for destroyed objects are applied lazily (before the next charge, or when a ledger is read), so usage can read high for a moment.

## Why it was acceptable

The dangerous resources are all limited per job.

## Proper fix, and when

Charge object memory to the job; count page-table frames exactly.
