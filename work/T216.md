title: PI futex: the WAITERS bit is not cleared when the last waiter gives up, and a thread id above 2^30 cannot use a PI futex
refs: [L23]
---

**What.** (1) SCHED-SMP-SPEC 4.8 says the kernel clears `WAITERS` in the lock word when the last waiter leaves the queue (a timeout, a kill, an interrupt). The kernel does not touch the word on that path (L23): the page may be gone by the time the waiter wakes, and the kernel's own physical address of the word is only good under the big lock and the address-space lock held at the call. The bit stays set; the owner's next unlock (user mode: the compare-and-swap of its tid to 0 fails because of the bit) falls to the kernel once, which finds no queue and writes 0. (2) The lock word holds 30 bits of owner id and thread ids are 64 bits (AB3), so a thread whose id is 2^30 or more gets NOT_SUPPORTED from both PI calls.

**Why acceptable.** (1) Costs one system call per give-up, never a wrong answer. (2) A billion threads created by one boot; the ids are assigned in order, so a normal system never reaches it.

**Proper fix.** (1) Re-resolve the word under the `AS` lock when a waiter gives up and clear the bit with a compare-and-swap if the queue is empty (a failed resolve is fine: the word is gone). (2) A second word format, or ids that wrap within a process (a thread's id as the process sees it), if a program ever needs more.
