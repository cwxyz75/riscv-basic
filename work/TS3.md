## Note (2026-11-18, plan 4: the v1 kernel)

Scoped for plan 4 to the kernel part (the server-protocol harnesses of the original entry move to the follow-on work and are not needed to close this item).

**How.** A new crate `ksys` (`no_std` + `alloc`, `forbid(unsafe_code)`), holding what is now `kernel/src/user.rs` minus machine access: process, handle, channel, event, socket, port, VMO, mapping, job and thread-management calls and their state (`UserState`). Machine access goes through `trait Machine` (copy in and out of the current address space through `kcore::usercopy` over a `PhysMem`; the current thread and hart; the clock; block and wake through the scheduler interface; TLB flush and shootdown requests as recorded events; the console). The kernel implements it over the real machine; `ksys/tests/` implements it with `Vec`-backed physical memory, a simulated clock and a scripted scheduler. Move in three PRs, each leaving the kernel a thin caller: **TS3a** the trait, dispatch, handles, channels, events, sockets, ports; **TS3b** VMOs, mapping, processes, jobs; **TS3c** waits, `channel_call`, futexes and thread management. For each call the matching error-case tests of the suite get host twins (the suite keeps one end-to-end test per call).

**Acceptance, written first.** Per PR: the host tests cover every error row of `SYSCALLS.md` for the moved calls (KT4's table shows them), run under Miri in the soak tier, and the QEMU suite is unchanged at 1, 2 and 4 harts. `kernel/src/user.rs` ends under 600 lines.

**Review.** Fable for TS3a (the trait's shape decides everything after it); default for b and c; soak each.

## Progress (2026-11-19)

**TS3a** (PR pending): the crate `ksys` exists, with `UserMem` (copy in, verify-writable, copy-out-verified, the job ledger) as the machine seam, `wide_argument_error` (the 32-bit argument table) and `ipc_call` (handles, channels, sockets, events, ports, object info). `kernel/src/user.rs` calls it first in `dispatch`. Host tests in `ksys/tests/ipc_calls.rs` run the error rows of those calls against a fake machine. After the Fable review the seam is not a trait of its own: `Ctx` holds the real `kcore` address space, `Mm<M: PhysMem>` and `Vmos` (the ledger is `vmos.jobs`), so the host tests run the kernel's own usercopy and quota code over a `Vec`-backed `PhysMem`; a `Machine` trait is reserved for what is truly machine (clock, current thread, TLB records, scheduler requests) and arrives with TS3c, where a blocking call becomes an outcome the kernel executes after `Ctx` is dropped (no borrow lives across a block). `Faults` carries the negative-control switches. 23 host tests cover the error rows of the moved calls. Verified: kquick and the QEMU suite at `-smp 1`, `2`, `4`. Miri over `ksys` is in `os-miri` (soak tier; owed, in WORK-PLAN). Open from the review: KT4's table (`syscall-tests.tsv`) does not yet list the host twins; T171.

**TS3b part 1** (PR pending): the VMO calls (`vmo_create`, `_physical`, `_dma`, `vmo_phys_addr`, `vmo_commit`, `vmo_get_size`, `vmo_read`, `vmo_write`) move to `ksys::vmo_call` (`ksys/src/vmo.rs`), with five host tests in `ksys/tests/vmo_calls.rs` over the shared fake machine in `ksys/tests/common`. Verified: kquick, suite at `-smp 1`, `2`, `4`. Left for the rest of TS3b: mapping, processes and jobs (`process_*`, `job_*`, `thread_*` functions still in `user.rs`, which touch the process table and need the cross-process `Ctx` the review predicted).

**TS3b part 2** (PR pending): `job_create`, `job_set_limits` and `job_info` move to `ksys::job_call` (the processor count is a `Ctx` field, `harts_online`, since it is a machine fact); six host tests in `ksys/tests/job_calls.rs`. Left in `user.rs` for TS3b/c: the calls that act on processes and threads (`process_*`, `job_kill`, `job_set_sched`, `thread_*`, waits, futexes, `channel_call`), which need the process table (`UserState`) behind the seam; that move is the next design step (the review's point 3: a blocking call returns an outcome the kernel executes after `Ctx` is dropped). Verified: kquick, suite at `-smp 1`, `2`, `4`.

**TS3b part 3** (PR pending): the process record (`Process`, `ProcState`, `SpawnStack`) moves to `ksys::proc`, and with it `process_map`, `process_unmap`, `process_self`, `process_info`, `thread_info`, `job_root` and `resource_root`, as `ksys::proc_call` over a `PCtx` (the object table, the process table, the caller's pid, memory, the ledger) and a two-method `Machine` trait (`shootdown`, `flush_tlb`: the TLB work the kernel does and the host records). Ten host tests in `ksys/tests/proc_calls.rs` over two real address spaces; one mutation check (the shootdown and the committed-stranger-VMO rule removed in turn: both caught). Verified: kquick, suite at `-smp 1`, `2`, `4`. `user.rs` is 2824 lines. Left for TS3b/c: `process_create`, `process_start`, `process_kill`/`suspend`/`resume`, `job_kill`, `job_set_sched`, `thread_*`, waits, futexes and `channel_call`: each needs the scheduler (`Machine` grows: current thread, wake, block, priority) and the blocking-outcome design.

**TS3c part 1** (PR pending): the decision half of `process_kill`, `process_suspend`/`resume`, `job_kill`, `thread_set_sched`, `job_set_sched` and the thread-handle lookup (`thread_target`, used by `thread_interrupt` and `thread_get_sched` too) moves to `ksys::lifecycle`: each function resolves handles, checks rights and state, makes the table changes and returns what the kernel then does (wake, kick, tear down, set a priority). Four host tests in `ksys/tests/proc_calls.rs`; two mutation checks (the job-kill limit zeroing and the max-priority check, each caught after one test was made non-vacuous). Verified: kquick, suite at `-smp 1`, `2`, `4`. Still in `user.rs` for the rest of TS3c: `process_create`, `process_start`, `thread_create`/`spawn`, `thread_interrupt`/`get_sched` effects, waits, futexes, `channel_call` and the trap/start code (`user_thread_main`, `start_locked`, `teardown`), which are the machine.

**TS3c parts 2 to 5 and the split** (PRs 294, 295, 296 and the one that follows): `UserState` and `ThreadStart` move to `ksys`; `thread_create`, `thread_spawn`, `process_create` and `process_start` become `ksys` functions with host tests (`ksys/tests/{thread,spawn,create,start}_calls.rs`; the kernel passes the machine facts and spawns the thread the function describes); `teardown` is three non-inlined functions and `procs` holds `Box<Process>` (the optimised kernel's stack budget moved with each step: `T173`). `kernel/src/user.rs` is now the directory `kernel/src/user/`: `mod.rs` (143 lines: the state slot, the accessors, the module list) and seven files of at most 507 lines (`loader`, `lifecycle`, `trap`, `wake`, `waits`, `kobjects`, `calls`), so the "under 600 lines" target is met by the module, with the machine-dependent code staying in the kernel. **Left for TS3 to close:** the decision halves of `object_wait`, `port_wait`, `futex_wait`/`wake`, `channel_call` (`waits.rs`: they need an outcome type for a blocking call, executed by the kernel after the `ksys` borrows end), and the effect halves in `calls.rs` (`thread_interrupt`, `job_kill`, `job_set_sched`, kill and stop). `make preflight` and `make preflight-full` run what CI has failed these PRs for.
