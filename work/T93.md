## Shortcut

**Filesystem durability has no intent log** (F4, `FS-SPEC.md`): `fsync` is a full copy-on-write commit, so a program that syncs after every small write pays a root-path rewrite each time.

## Why it was acceptable

Keeps one recovery mechanism (flip a checksummed root, no replay) and a trivially checkable format; no real workload yet.

## Proper fix, and when

Reconsider once a real workload (a database, a log writer) measures the cost: a btrfs-style tree log (data and size changes of existing files only, a full commit for namespace changes), with its replay path crash-tested exhaustively. Decide before the format is frozen if the superblock needs a log-root field.
