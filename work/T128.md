## Shortcut

**UV5 shortcuts** (2026-11-17):

- (1) **resolved 2026-11-17 (OD116)**: the session manager is `sessiond`, a process of its own; `init` keeps the kernel's first-process authority and holds no profile, password or verifier
- (2) a session's isolation is one `memfsd` per session whose root leaves out `homes/` and `etc/profiles/` (a copy of the image tree per session, no union server): fine for fixtures, to be replaced by home volumes and the manifest's tables (S10)
- (3) `/home` is a boot-image directory, so it is read-only and the profile's quota does not cover it
- (4) `/etc/trusted` stays in the image because the shell test reads it: the shell uses the profile's grants when it has a profile and the file only without one
- (5) identity is `USER`, `HOME`, `UID`, `GID` in the environment and a `passwd_line` helper: the libc does not synthesize `getpwuid` from it yet and `/etc/passwd` is still the static file
- (6) a session cannot start another (no login, no `su`): the authority-UX topic
- (7) the test checks that the job is empty after a close, not that `job_kill` alone did it (the session's processes are also killed one by one first)
- (8) profile quota only lowers the programs' job limits (`processes` and `memory_mib`), nothing else. Fix: (1) first.

(Migrated from the old TIDY-UP register, section "Concurrency and kernel structure", 2026-11-18.)

## Note (2026-11-18, T151)

Checked: (5) is narrower: the libc's `getpwuid` and `getpwnam` answer from the session's identity (`session_passwd`, built from `USER`, `UID`, `HOME`); only the `/etc/passwd` file is still the static one.
