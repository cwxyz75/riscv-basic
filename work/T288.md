*(area testing, horizon someday, risk M)*

## Stability epic (2026-11-27)

**Scope (one PR).** From T259's plan (section 2.C item 2): generate the kernel's order probes from `klock::Class` (every ordered
pair, expected = the pure table) instead of the 16 written by hand (14 classes today); make `Held::release` strict for every class
but `Uart` (a panic breaks it), now that the big lock's hand-overs ended (L20). T85 (4) (`Machine::hart` is `u32`) and (6) (the
park model has one waiter and one wait round) are checked and struck or done: (6) wants a second waiter and a second wait round
in `kcore/tests/park_concurrency.rs`. T135: find what shuttle's panic at `execution.rs:203` means in shuttle 0.8.1 (read the
source: a step bound, a deadlock report or an internal assertion), then either fix the test's bounds or the lock.

**How to investigate.**
- T135: run `klock`'s `spin_concurrency::the_lock_excludes` under shuttle with many random schedules and with the PCT scheduler
  (`shuttle::check_pct`), seeds printed, bounded to one hour; shuttle prints a replayable schedule on failure
  (`shuttle::replay`): keep it in the item. Run the same test under loom if it fits loom's bounds, and under Miri (`make os-miri`
  runs `klock` there: a targeted `cargo +nightly miri test -p klock` is an experiment, not the soak).
- Strict release: turn it on and read what the suite says (one targeted kernel-only boot at four harts); every report is a real
  double release or a release on the wrong hart (TESTING.md rule 11 applies to anything that appears).
- **Kani** fits the pure order table: a bounded proof that the table is a strict total order on the classes that the kernel
  nests, and that `Held`'s push/pop never accepts a descending acquisition (needs an OD, `STAB0`).

**Acceptance (each run under two hours).** `klock/tests/order.rs` gains "every ordered pair matches the table" and "a release of an
unheld non-reentrant class panics" (mutation: make the release lenient again, the test fails); the in-kernel order test probes
every pair of the table (one targeted boot shows the count); T135's cause is named from the source and the schedule (or, if the
bounded hunt finds nothing, the item records the seeds and schedules tried and stays open, OD160). Review by Opus.
