## Shortcut

**(resolved 2026-11-17 for programs that use the C library: Ctrl-C is SIGINT when they handle or ignore it; programs outside it, and the shell's own `^C` at a prompt, are as before) Ctrl-C always kills the foreground job**, so an interactive `basic` program in an endless loop can only be stopped by losing it (BASIC's own BREAK key cannot be delivered).

## Why it was acceptable

S4 console design: Ctrl-C is a kill, not a signal.

## Proper fix, and when

A console "raw break" mode where Ctrl-C is delivered as an in-band byte to a program that asks for it.
