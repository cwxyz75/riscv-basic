### T159: Syscall errors that SYSCALLS.md lists and no test of the suite exercises (31 pairs)

*(area testing, horizon long, risk M)*


#### Shortcut

`scripts/syscall_tests.py` (KT4) maps every (call, status) pair of `docs/reference/SYSCALLS.md` to a test of the suite whose body calls the
syscall and mentions the status; 31 of 217 pairs have none (`UNTESTED` rows of `docs/reference/syscall-tests.tsv`, the list):

- `channel_call`: BUFFER_TOO_SMALL, NOT_SUPPORTED, NO_MEMORY, PEER_CLOSED, SHOULD_WAIT
- `channel_create`: NO_MEMORY
- `channel_read`: NO_MEMORY
- `futex_lock_pi`: ACCESS_DENIED, BAD_STATE, INTERRUPTED, INVALID_ARGS, NOT_SUPPORTED, TIMED_OUT
- `interrupt_create`: ACCESS_DENIED, NO_MEMORY
- `port_bind`: NO_MEMORY
- `port_rearm`: ACCESS_DENIED, BAD_HANDLE, WRONG_TYPE
- `process_create`: ACCESS_DENIED, BAD_HANDLE, NO_MEMORY, WRONG_TYPE
- `thread_get_sched`: BAD_STATE
- `thread_interrupt`: INTERRUPTED
- `thread_set_sched`: BAD_STATE
- `vmo_commit`: BAD_HANDLE, TOO_BIG, WRONG_TYPE
- `vmo_create`: NO_MEMORY
- `vmo_create_physical`: NO_MEMORY

#### Why it was acceptable

The kernel-only boot (KT1) and the host syscall layer (Phase 3, TS items) will test errors by table; this item is the list they work from. An untested error is not necessarily wrong, only unproved.

#### Risk

A documented error that the kernel does not return, or returns for the wrong reason, goes unnoticed.

#### Proper fix, and when

A test per pair (most are one assertion in an existing test); the table check shrinks the list by itself (a row marked `UNTESTED` that a test now covers fails the check until it is regenerated). With the syscall layer on the host (TS3), where error paths are cheap to drive.

### T175: Two files are below 80 % line coverage on the host (KT11): abi/src/lib.rs and ksys/src/vmo.rs

*(area testing, horizon long, refs [KT11, TS3])*


KT11's first coverage run (2026-11-20) found two files under 80 %. `abi/src/lib.rs` (55.7 %): the `Rights` helpers `contains`, `union`, `is_subset_of` and `is_valid`, `Status::code` and `Status::from_code`, and `layout::in_device_window`, which no test inside `abi` calls (other crates call them, and the OS tests exercise them in QEMU, but a host test in `abi` should pin each: a round trip of every status code, the subset and union laws, the window's edges). `ksys/src/vmo.rs` (59.1 %): the success paths of `vmo_create_physical`, `vmo_create_dma` and `vmo_phys_addr` (the fake machine in `ksys/tests/common` has no resource handle or DMA window yet). Why acceptable: the helpers are one-line and used everywhere, so a defect shows at once; the VMO paths are exercised in QEMU by `device_caps_need_the_resource`. Proper fix: add the tests above, then re-run `make os-coverage`; both files should pass 90 %.

### T198: The first mutation run over `kcore` (partial): 19 survivors still to kill or accept, and the run takes about 18 hours on a laptop

*(area testing, horizon long, refs [T193])*


`make os-mutants PKG=kcore` was started by hand on 2026-11-21 (a Mac, nine host threads busy with other work) and stopped after 44 minutes: 145 of 3,686 mutants tested, 108 caught, 13 unviable, 22 missed and 2 timed out, at about 18 seconds a mutant, so the whole crate would take about 18 hours there (CI's `overnight.yml` splits it into shards: `make os-mutants PKG=kcore SHARD=k/8`). A miss rate of 15 percent in the first fifth of the file order says the full run will list a few hundred survivors. Killed in the same pass with new tests (checked with a targeted `cargo mutants`): `Sched2::reap`, `Changes::is_empty`, `Depth::get`, both `device_windows` boundaries (`kcore/tests/devwin.rs`), and `room() < 1` in `vmo_object_create_with` and `thread_object_create_in` (`kcore/tests/object_room.rs`). Still alive from the partial run, each to be killed by a test or listed in `mutants-accepted.txt` with the reason it cannot be observed:

- `object.rs:560` `- with +` in `Registry::sweep` (the sweep threshold's cap, reached only when more than half of the object table is live)
- `sched_smp.rs:654` `> with >=` in `pull_work` (an equal-priority thread is pulled to a hart running one of its own priority: a fairness, not a safety, difference)
- `aiatree.rs:112` `/ with *` in `discover` (a trailing odd cell of `interrupts-extended` is ignored by the original, rejects the tree in the mutant: needs a synthetic tree with an odd cell count)
- `sched.rs:56` `pick_next with None`, `sched.rs:481` `+= with *=` in `dispatch`, `sched2.rs:1129` the match guard in `HartRq::cur_eff`, `sched2.rs:306` `> with >=` in `FixedPrio::preempts`, `sched_smp.rs:826` `>= with <` in `after_enqueue`
- `usercopy.rs:155` and `usercopy.rs:177` (`- with +` in `verify_writable`, `< with <=` in `copy_to_user_verified`: range arithmetic at a page boundary)
- `pagetable.rs:180` (`| with ^` in `is_leaf`), `pagetable.rs:561` (`> with >=` in `for_each_leaf`), `pagetable.rs:440` (`- with /` in `map_large`)
- `fp.rs:181` `UnitThread::enabled with true`, `elf.rs:217` `< with <=` in `parse`, `wait.rs:133` `WaitTable::audit with Ok(())`, `ipc.rs:960` `-= with +=` in `prune_port`, `fdt.rs:169` `&& with ||` in `component_is`

What to do: run the full sharded job on CI (the owner starts it), kill the survivors it lists in the same way (a test per survivor, mutation-checked with `cargo mutants -F`), and read `scripts/mutants.py`'s accepted list for what may stay. Why acceptable: the survivors show where a test is missing, not a bug; the host models and the boots pass. Risk: a defect in one of these paths is not caught by the host tests.

### T6: User-printed `##TEST` names are trusted

*(area testing, horizon long, risk M)*


#### Shortcut

**User-printed `##TEST` names are trusted** by the kernel's output parser; the serial bridge escapes `##` at line start (S4) but `debug_write` by test programs does not.

#### Why it was acceptable

Test harness only.

#### Proper fix, and when

With T2: `debug_write` only from the harness; structured results over a dedicated channel instead of the serial line.

### T25: `init` still has test-aid commands

*(area testing, horizon long, risk L)*


#### Shortcut

**`init` still has test-aid commands** (compiled into every build; only the `repl` kernel starts `init` in the mode that reads them) (`raw`, `desync`, `big`, `rights`, `quitx`, `run`) that exist so the serial test can probe the bridge.

#### Why it was acceptable

v0 supervisor with no shell yet.

#### Proper fix, and when

Remove or gate them behind a test build when `init` stops reading the serial socket (S4d/S4e).

### T35: Gaps in the S4d/S4e tests

*(area testing, horizon long, risk L)*


#### Shortcut

**Gaps in the S4d/S4e tests**: no program exits early on a closed pipe (exit 141 untested); whole-stack restart after a service death and a bad halt message are untested; consoled's NoMemory retry and delivery cap are untested.

#### Why it was acceptable

Needs fault injection (a service that dies on cue, an exhausted IPC budget) that does not exist yet.

#### Proper fix, and when

A `die` hook in a test build of memfsd and a budget-hog program.
