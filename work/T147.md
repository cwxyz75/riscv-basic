## Shortcut

**The libc batch of 2026-11-17 (LIBC-GAPS.md): shortcuts.**

- (1) the `*at` calls resolve a relative name against the path the directory descriptor was opened by (as `openat` does), so a descriptor without one (a pipe end, a descriptor the file server did not name) is `EACCES`; `linkat` is `EPERM`, `mkfifoat` and `mknodat` `ENOSYS`; `symlinkat` and `readlinkat` work only where the file server has symlinks (the volume, not `/tmp`: `memfsd` has none)
- (2) `flock` always succeeds and `__fpurge` does nothing; `mkostemp` ignores its flags; `tzset` does nothing; `strxfrm` is a copy
- (3) `error` prints `program: message[: strerror]` on standard error and `error_at_line` prints `program:file:line: message`, as glibc does; `error_print_progname` is not used
- (4) `getopt_long` has no `getopt_long_only`, treats a leading `-` in the option string as plain, and differs from the host only in where `optind` stops after a missing or unwanted argument and in Apple's return value for a missing long argument at the end (the test leaves those runs out)
- (5) wide characters are UTF-8 only and not locale-sensitive; the classes are `std`'s Unicode ones (`iswdigit` ASCII only, `iswspace` without no-break spaces); `wcwidth` is a table of the common combining and wide ranges, not all of UAX 11; there is no `mbsrtowcs`/`wcsrtombs`, `wcsstr`, `wcstol`, `swprintf` or wide stdio
- (6) `fscanf` scans the stream's buffered input and reads on to the next white space when a field may continue past the end of the buffer; a token longer than the buffer that the format does not fully take loses its tail (the stream can give back only what its buffer and one pushed-back byte hold); `sigwait` polls every 10 ms
- (7) not built: `strtold`, `crypt`, `utmpx`, `dlopen`, `histedit.h`, `fscanf` for wide characters.

## Why it was acceptable

The two programs still blocked (GNU tar, coreutils) need only these and gnulib's own configuration; every other gap the survey found is closed.

## Proper fix, and when

`strtold` with soft-float quad conversion; a stream that can give back more than one byte; wide stdio and `wcs*` when a program asks.
