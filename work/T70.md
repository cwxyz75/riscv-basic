## Shortcut

**The object domain is one lock** (`OBJ`: registry, handle tables, wait table, ports) in the final design

## Why it was acceptable

Held for O(1) work once copies and faults are out; keeps the sweep and the commit simple

## Proper fix, and when

Split per SCHED-SMP-SPEC 3.13 if its trigger fires (channel pair scaling below 2.5 at four harts with over 30% of time waiting for `OBJ`)

(Migrated from the old TIDY-UP register, section "Concurrency and kernel structure", 2026-11-18.)

### 2. Design (only if the trigger fires)

Take the smallest split the measurement asks for, in this order, stopping when the ratio passes:

1. **Per-process handle-table lock `HT`** (new class, per process, after `OBJ`, before `AS`): handle lookup, insert,
   close for one process. Lookup takes `HT` only and returns a counted reference to the object, so the object cannot
   be freed under the caller.
2. **Per-object lock** (class `OBJ` becomes many instances, two in ascending `ObjId`, as 3.13 says): a channel pair is
   one instance (both ends and the pending-call records), a port with its bound index is one.
3. **What stays global, under a residual `OBJ0`**: object create and free, the registry's slot map, the sweep (SW1),
   the process table, pagers, interrupt objects. The sweep takes `OBJ0` and visits tables and objects under their
   own locks in slices (it is already sliced; `shade` on insert stays under `HT` plus an atomic mark).
4. **The commit (W1')**: the dirty log becomes per guard (the objects this section touched), committed when the last
   per-object guard drops; the wait table gets its own leaf lock `WAIT` between `OBJ` and `FUTEX`.

Rejected:

| Alternative | Why not |
|---|---|
| Lock-free (RCU or epoch) handle lookup, 3.13's wording | Needs deferred reclamation the kernel does not have, and unsafe code outside the `forbid(unsafe_code)` crates; a per-process spin lock is uncontended for independent pairs, which is what the trigger measures. Revisit only if `HT` itself is convicted |
| Stop-the-world epoch for the sweep | An IPI to every hart per sweep slice costs latency (budget of 3.12); slicing under `OBJ0` already exists |
| Reader-writer `OBJ` | `channel_call` writes both ends and the dirty log: every hot section is a writer |
| Shard `OBJ` by hash of `ObjId` | Two-end and port-binding operations cross shards constantly; same ordering work as per-object locks with less benefit |
| Shorten hold times only (no split) | That is T267's PRs 2 to 5 and must be tried first; it is not this item |

### 5. Invariants, lock classes, and how it goes wrong

Rows touched: **C1** and the lock-order list (new classes go in with a reason), **K5**, planned-order rows 1 (`OBJ`)
and 3 (`PROCS`, unused), **W1'** (rewritten: empty when the last object guard drops), **G1**, **PK1** (a wake after
registration is never lost), **SW1** (every new handle shades its object), **X3** and **X7** (no lock across a switch;
`irq::window()` with nothing held), **DC1** and **DN1-DN3** (donation made when a request is read), **AS1** (`AS`
ascending, before the memory locks), the handle rows (unforgeability, rights monotonicity). Classes: `OBJ`, new `HT`,
new `WAIT`, then `AS`, `FUTEX`, `VMO`, `JOBS`, `PI`, `TT`, `RQ` unchanged below them.

Subtle failures to design against:

1. Lost wake: a waiter registers under `WAIT` while a writer on another hart commits from its own log; needs the PK1
   prepare/check/register order per object, not per machine.
2. Use after free: lookup under `HT` races a close plus the sweep; the reference count and generation check must be
   taken under `HT`, and free only under `OBJ0` with the count at zero.
3. Handle transfer (`remove_for_transfer`, messages carrying handles) touches two tables and a channel: order is
   `OBJ0`-free, `HT` ascending pid, then the object; a sweep passing between the remove and the insert must still see
   the object (born-marked or shaded, SW1).
4. Teardown and `process_kill` walk another process's table; `end_bindings_made_through` crosses many objects: keep
   these under `OBJ0` (global, slow path) rather than ordering N locks.
5. The T239 debug guard (one `&mut UserState`) no longer means anything once the state is split; replace it per
   domain or aliasing bugs go silent.
6. `release_all`/`reacquire` at a switch assume one lock and a depth: with several object locks, X3 must hold by
   construction (no object guard alive at `schedule()`), checked by `klock`'s held stack.
7. The lock-free probes that read `n_suspended`, `n_interrupts`, `ATTENTION` (K6) were written against one lock.

## Decision (2026-11-24, OD149)

The owner settled the direction: the object domain moves to a lock per object, and the single `OBJ` lock is interim. The item's old framing (split only if a trigger fires: scaling below 2.5 at four harts and over 30% of syscall time waiting for `OBJ`) is dropped as a gate. No optimisation around `OBJ` is wanted now: the weak futex scaling, which mostly skips `OBJ`, suggests a different cause (T252 in bundle T267), and this work will replace `OBJ`'s use anyway. The plan above (the refactor to a single `resolve`, `ObjId`-ordered signatures, per-process handle tables, per-object locks for channels and ports) stands as the sketch for when the item is taken up; "when" stays open, to be revisited, and SCHED-SMP-SPEC 3.13 gets an amendment then. The plan's questions about the hart count, the accepting figure and the denominator of the 30% are void.
