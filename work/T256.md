### T199: L16 part b's stand-ins: one `VMO` lock for the whole store, and `&'static mut` fields on the lock bundles

*(area kernel, horizon long, refs [L16, T253])*


L16 part b (PR 350) made the VMO store, the job ledger and the frame database three real locks. Two things differ from the end state.

1. **One `VMO` lock for the store, not one per family** (KERNEL-V1-SPEC 4.3, the L16 entry in `docs/records/done.md`). Before MM8 a family is one VMO, so a store lock is the same thing in effect; the store/family split belongs with MM8 or L17, whichever needs two VMOs locked at once. Why acceptable: the big lock still serialises every taker. Risk: none until the big lock is peeled.
2. **`kmem::Kmem`, `Frames` and `JobsRef` have public `&'static mut` fields** (found by the review of PR 350): safe code can move a reference out past its guard (`kmem::jobs().jobs` returned from a function). No site does it; every site is a statement temporary or a named guard. Proper fix: a newtype `Ref<T>` that derefs with the lifetime of the bundle, or private fields and a `parts(&mut self)` accessor, with the call sites (about 100) rewritten. Due now (L20 landed 2026-11-24); T253 item 3 holds the same fields from the KT14 review, so do both once.

### T225: The last unchecked accessors: the FP tables' `state()` and the `&'static mut` fields of `Kmem`

*(area kernel, horizon long, refs [L20, KT14])*


L20's accessor step (2026-11-23): the user state is reached only through `user::with_state(|s| ...)` (the object lock, a closure, no reference that outlives it); 97 sections were converted by script and the rest by hand. What is left of "no function returns a `&'static mut` to shared state" (KERNEL-V1-SPEC 6):
- ~~`user::state_locked()`~~ (done 2026-11-24: the accessor is gone; `dispatch` is a `with_state` around `dispatch_in(s, ..)`, the loader's three sections and `take_interrupt_held` and the register-token section are closures, the fault path clones the address space's `Arc` out of the section; k shard at one and four harts passes).
- `arch/riscv64/fp.rs`'s `state()` (the floating-point tables, under the big lock at the trap's first act): its own lock or per-hart ownership (T166 has the claim protocol).
- `kmem::Kmem`, `Mem`, `Frames`, `JobsRef`: structs of `&'static mut` fields next to the guards they come from (`inside`), the reference never outliving the struct; the type-level fix is closures (`with_mem(|m| ...)`) as for the user state.
- the `static mut` list of KT14's audit.
Why acceptable: every use is behind a lock that the accessor asserts or the guard holds; nothing relies on a human reading it, and KT14 audits each. Proper fix: with KT14.

**Narrowed (2026-11-24).** `state_locked` is gone (struck above) and KT14 is closed, so its audit list is history. What stays: the FP tables' `state()` (the claim protocol is T166) and the `Kmem`, `Mem`, `Frames` and `JobsRef` fields, which are the same defect as T199 item 2 and T253 item 3: fix them once, there. Keep this item only for the FP `state()`, or fold it into T166 when that is next touched.

### T241: KT14: firmware addresses (the UART and `sifive,test` bases) are bounded by the direct-map limit but not checked against RAM, the image or reserved ranges

*(area kernel, horizon long, refs [KT14, L20])*


**What.** (1) `user/trap.rs` `activate_current`: on the L20 syscall path `with_state` is outermost and can switch threads between computing `token` and installing it, so "refreshed and flushed just above" can be false; harmless only because the tail re-validates before `sret`. (2) `user/calls.rs` `general_of` reads a suspended thread's frame under a comment that says the big lock is held (false since L20); a thread whose wait ended writes its frame (`reply`, `sepc -= 4`) before parking: mixed old and new register values, not corruption. (3) The UART and `sifive,test` addresses from the device tree are bounded by `DIRECT_MAP_PHYS_LIMIT` but not checked against RAM, the image or reserved ranges (`aia::discover` does); `dtb_blob` assumes every tree frame was direct-mapped though `kmem::init` skips those outside `/memory`. (4) `heap::grow` and `kstack::make_slot` flush only the local TLB after making an invalid mapping valid: on hardware without Svvptc another hart may take a fatal kernel page fault (QEMU does not cache invalid entries).
**Why acceptable.** Each holds on QEMU `virt` and on every path traced; none is reachable by user mode except (1), which has no effect found.
**Done (2026-11-23):** (1) the token is computed and installed in one section of the object lock (`bkl::ensure`). (4) the kernel's page-fault handler flushes the page and retries when the kernel table maps it with the right permission (a stale invalid entry); not testable on QEMU, which never caches invalid entries. (2)'s comment says what is true. Left: (3) (the UART and finisher addresses are bounded by the direct-map limit but not checked against RAM and reserved ranges).
**Proper fix.** (1) install the token under the lock or re-check after; (2) take the thread's lock or re-check the state; (3) check firmware addresses like the AIA's; (4) a remote fence or retry on a stale-invalid fault.

**Narrowed (2026-11-24).** (1), (2) and (4) are done (see above; (2)'s remaining race is a diagnostic-level one that its comment states, and the weak SAFETY note on `general_of` is recorded in the KT14 audit). Only (3) is open: check the UART and finisher addresses like `aia::discover` does, and make `dtb_blob` not assume every tree frame was direct-mapped. The `kstack` Deref aliasing that T242 named is T253 item 1.

### T253: KT14 second review: the weak points that stay (kernel stack slice, firmware window fallback, public guard fields, a release check of the FP lock)

*(area testing, horizon long, refs [KT14, T239, T241, T242])*


**What.** The second independent review of KT14 (2026-11-24, `docs/records/reviews/2026-11-24-kt14-second-review.md`) found no memory-safety path reachable from user mode. What it left, with the change that fixes each: (1) `kstack.rs` `Deref` forms a slice over a kernel stack a thread may be running on (a read of guard and dead words, aliasing by the letter of the rules): use volatile or atomic reads in `guard_intact` and `stack_used`; (2) `aia.rs` `reg()` falls back to base 0 when `info()` is none (every caller is gated by `irq_allowed` today): a `debug_assert!(info().is_some())`; (3) the `kmem` guard structs (`Kmem`, `KmemAs`, `Mem`, `Frames`, `JobsRef`) have public reference fields, so safe code could move one past the guard's drop: make the fields private and expose methods; (4) the FP tables' `state()` and `user::state()` assert the lock in debug builds only: a hard assert at the first `state()` call or the claim in the comment kept honest; (5) `calls.rs` `general_of` can read a thread's frame while the thread writes its reply on another hart (T241 holds the race; diagnostic only); (6) not traced by the reviewers: whether `cow_sync_held` is ever reached with an `AsLocks` live (a nested take of the same address-space locks), whether the entry-frame jump is always at big-lock depth 1, whether `heap::service` can run on a parked hart through a device interrupt, whether thread ids are never reused (`light_save` relies on it).
**Why acceptable.** Each is a debug-checked or caller-held condition that holds on every path found; none is reachable from user mode.
**Risk.** A future caller breaks one of the conditions and a release build does not notice.
**Proper fix.** The six changes above, in one pass, then audit the changed blocks again (the hash check lists them).

### T188: PL3 leftovers: the claim protocol of the FP and vector units has no host model, and a few checks are weaker than they look

*(area kernel, horizon near, refs [PL3, T166])*


Left from the Fable review of PL3 (2026-11-20), after the fixes in the PR. (1) The per-hart claim protocol (`claim`, `light_save`, the lock-free early return in `fp::return_to_user`) lives only in `kernel/src/arch/riscv64/fp.rs`; `kcore::fp` has the token model and its tests but no model of claims, so the invariants (one claim per thread, on its holder hart; a token kept by a lock-free save never lets another hart skip a load; a takeover clears the claim and forgets the token) are checked only by the four-hart boot. Proper fix: move the claim bookkeeping into `kcore::fp` behind the same unit trait and extend `vec_model.rs`/`fp_model.rs` with lock-free saves, migration and a second thread, mutation-checked. (2) No debug assertion that a claim implies the hart holds the thread's state (`harts[h].holds(t)`) in the locked paths. (3) `scripts/check_vector_codegen.py` skips when no archive was built and sums over archives (the C-test archive holds hand-written vector asm); `newest()` can pick a stale archive under `target/`. (4) The C `cbo.zero` line in the transcript is memset where the compiler lacks `__riscv_zicboz`; only Rust mode 98 tests it for sure. (5) `senvcfg` bits stick whether or not M-mode enabled the extension on QEMU as far as I know; presence is established by `dtb::require_extensions` and mode 98, not by the read-back. Why acceptable: the boot exercises all of it at four harts on the one target. Risk: a change to the claim paths is caught late.

Progress (2026-11-24): (2) done: `claim` asserts, in a debug build, that the hart holds the thread's state (k shard at four harts passes). (3) done in part: `REQUIRE_C_ARCHIVES=1` makes a missing archive a failure (the stale `newest()` pick and the sum over archives remain). Still open: (1) the host model of the claim protocol, (4), (5).

##### 1. The claim state machine as the code has it

One instance per unit (FP, vector). Variables: the thread's `state: Option<(Box<R>, token)>` and `holder: Option<hart>` (C:140-144); the hart's `owner` token (C:218); the per-hart cells `claim` (a tid, 0 none) and `buf` (address of the box, 0 none) (`kernel/src/percpu.rs:116-120`); the frame's two bits (Off, Initial, Clean, Dirty).

| Step | Where | Effect |
|---|---|---|
| E enable | K:551-599, C:191 | state = (zeros, new token); frame Initial; no claim |
| S locked save | K:389-437, C:243-260 | frame Dirty and LS refused: `save_into`, new token, `owner = token`, then `claim`; frame Clean |
| L locked load | K:477-516, C:264-277 | frame Initial, or `claim[h] != tid`: load unless `owner == token`, `owner = token`, then `claim` |
| `claim(t, h)` | K:298-331 | if `holder == old != h` and `claim[old] == tid`: `claim[old] = 0`, `buf[old] = 0` (that order), `harts[old].forget()`; then `holder = h`, `buf[h] = addr`, `claim[h] = tid` (that order). The thread that had `claim[h]` is evicted and its `holder` goes stale: hence the `== tid` guards at K:312, 646, 701 |
| Q quiet return | K:461-476 | each unit Off, or (Clean or Dirty) and `claim[h] == tid`: no lock, nothing changes. Initial never passes |
| LS light save | K:337-373 | frame Dirty: reads `buf` then `claim`; if `claim == tid` and `buf != 0`, `save_into(*buf)`, frame Clean. Token, owner, holder and claim are unchanged. Otherwise false, and the caller takes S |
| W debugger write | K:687-711, 717-788, C:203 | if `claim[holder] == tid`: clear both cells, forget; new box, new token, `holder = None`; the frame becomes Initial later (K:792-811) |
| G thread gone | K:632-656 | clear both cells if `claim[holder] == tid` (no forget: the token dies with the state) |

Every cell write is under the big lock. `claim[h]` is set only by hart `h` (all four `claim` calls pass `hart()`); other harts only clear it, and only for a thread not running on `h`. The lock-free reads (Q, LS) are of the hart's own cells, interrupts off.

##### 2. What moves, what stays

New in `kcore::fp` (no unsafe, no atomics: the C5 count of `check_docs.py` does not move):

- `trait ClaimCells { fn claim(&self, hart) -> u64; fn buf(&self, hart) -> usize; fn set(&self, hart, tid, buf); fn clear(&self, hart); }`. Contract: `set` stores `buf` then `claim`, `clear` the reverse, with today's Acquire and Release.
- `UnitTable<R, const N: usize>`: `tokens`, `threads: BTreeMap<u64, UnitThread<R>>`, `harts: [FpHart; N]`. Methods, each given `&impl ClaimCells`: `enable_with(tid, zero)`, `save_locked(tid, h, unit) -> bool` (S), `load_locked(tid, h, unit) -> Fs` (L; both end in `claim` with the `holds` assertion of K:323), `replace_regs(tid, regs)` (W, drop first), `thread_gone(tid)` (G), `regs`, `enabled`, `len`. `claim` and `drop_claim` become private.
- Pure decisions used by the lock-free paths: `enum Lazy { Off, Initial, Clean, Dirty }`; `light_target(cells, h, tid) -> Option<usize>` (the two reads of K:352-353); `quiet_return(fs: Lazy, vs: Lazy, fp_cells, vec_cells, h, tid) -> bool` (K:461-474); `after_load(Fs, Lazy) -> Lazy` (K:517-534).
- `FpHart`, `UnitThread`, `StateUnit` keep their API: `fp_model.rs` and `vec_model.rs` pass unchanged.

Stays in the kernel file: `HartUnit` and `VecHartUnit` (K:113-288, no line touched; enabling and disabling a unit is inside their asm), `VLENB`, the `sstatus` masks and the frame-to-`Lazy` conversion, `STATE` and `state()`, the `ClaimCells` impl over `percpu` (one type per unit), the two dereferences of `buf` in `light_save`, the two `csrc`, the job charge, `fault-skip-fp-save`, the EX1 layouts, `hart()`, the cache-block enable.

##### 3. Invariants the model asserts after every step, for every (hart, thread)

- I1 one claim: `claim[h] == tid` implies `holder(t) == Some(h)`, `t` is enabled and `buf[h]` is the address of `t`'s box (compared as a `usize`). So one hart at most claims a thread, and no claim outlives W or G.
- I2 a kept token never goes stale: `harts[h].holds(t)` implies `claim[h] == tid`. A light save changes the copy under an unchanged token, so the token may match on the claiming hart only.
- I3 reference: at every return to user mode the unit's registers equal `want[t]`; whenever the frame is not Dirty the saved copy equals `want[t]`.
- I4 a quiet decision is the locked path's no-op: `quiet_return` says yes only where `harts[h].holds(t)`; an address from `light_target` is `t`'s box.
- I5 migration: once `t` returns to user mode on `h2`, no other hart claims or holds it.
- I6 the kernel uses no register: the model unit's registers are compared across every kernel stretch (trap to return) and may differ only by a counted `load`. On the machine FP3 stays `fp_unit_is_off`.
- Generator preconditions: W and G only for a thread on no hart; S, L, Q, LS only for the hart's current thread.

##### 4. The model tests

`kcore/tests/fp_claim_model.rs`, written first, generic over the unit and run for both (`VecRegs` at `vlenb` 16 and 32). A random walk (`common::Rng`, `SEEDS`, `STEPS`) over 1 to 4 harts and 1 to 6 threads; each hart has a current thread or none. Steps: schedule a thread onto a free hart (a migration when it last ran elsewhere; threads sharing a hart), user code (enable; write registers: frame Dirty), a light trap (interrupt or lock-free syscall: LS, then Q, or the fallback to S), a full trap (S, then L or Q), preemption, W on a parked thread, G, and the tick that light-saves and then takes the lock (`trap.rs:535-548`). Named scenarios too: a thread alone on its hart does no load and no locked return after the first; A, B, light save on B, back to A reloads; W on a claimed thread reloads; a stale `holder` clears nobody else's claim.

Asserted: hart 0 gets T's own address or `None`, and no quiet yes without its claim.

### T214: the AS lock's `held_mut` hands out `&mut` through `&self`; and a call that names a process locks every address space

*(area sched, horizon long, refs [L17, L20])*


**What.** (1) `klock::aslock::AsCell::held_mut` gives `&mut AddressSpace` from `&self` after checking that this hart holds the lock: the cell is shared by `Arc`, so nothing stops safe code from keeping two references alive across each other. The kernel's discipline (one reference at a time) is the whole guard, as it is for `state()`. (2) `process_table_call`, `thread_spawn`, `process_start`, `pager_supply` and the copy-log sync take **every** address space's lock, ascending, before the memory locks, instead of the caller's and the target's.

**Why acceptable.** `ksys` is `forbid(unsafe_code)` and its functions take `&mut UserState`; making the access `unsafe` would put an `unsafe` block at sixty sites for no checking. Every site was traced in the L17 review (PR 404): none overlaps. Under the big lock, which still covers all of it, the take-all costs a few locks per call and blocks no one (a page fault on another hart waits on the big lock anyway). It starts to matter when part c lets faults run without the big lock.

**Proper fix.** Hand the reference out through the holder (`AsHold::get_mut(&mut self)`), so the borrow checker sees one holder per space, and resolve the target process of a call before the memory locks so that only the caller's and the target's are taken. Do it with L20, when the object lock is explicit and the call structure changes anyway.

**Also (L17 part c).** (3) `AS2` has no negative control: a fault runs under the memory locks (`VMO`, `JOBS`, `FRAME`) as well as `AS`, and every call that changes a space holds the same memory locks for its whole run, so a fault that skipped `AS` could not be told apart from one that took it (the first control, `fault-skip-as-lock`, was removed in the review for that reason). A discriminating control needs a reach of the space outside the memory locks (`take_replaced` in `cow_sync`, `futex_wait`'s enqueue) or a loom model of the region map; it is also when the global memory locks stop serialising faults that the lock starts to matter. Do it with L20.

**2026-11-22 (PL8 part a):** the process backstop is held to 64 (`kcore::limits::AS_HELD_MOST`) because `AsLocks::all` takes every process's address space and the order checker holds 64 at most (`Class::As::most_at_once`, `MAX_HELD` 72); more live processes would overflow it. Taking this item's fix (no call that locks every address space) lifts that hold: the table's RAM / 1 MiB applies.
