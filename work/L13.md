## L13a built (2026-11-19): the timer queue with slack (pure)

`HartRq` keeps a second ordered set of its sleepers by **hard** expiry (deadline plus the thread's `timer_slack`: 50 µs in the normal band, 0 in the real-time band whatever was asked, at most 1 ms; `Sched2::set_timer_slack`), and `HartRq::next_event` / `Sched2::next_event_on(h)` say when the hart's one-shot timer must fire: the earliest hard expiry, or the running thread's slice end **only when an equal or better peer waits** (the classes' `next_event` now return `None` otherwise); `None` is "never": a hart with one runnable thread and no deadline has no event. Expiry is unchanged: an interrupt expires every entry whose soft expiry has passed, so nearby wakes share one interrupt and nothing fires early. Checked by `kcore/tests/timer_queue.rs` (random entries and slacks: never early, at or before the hard expiry when served on time, interrupts at most the distinct hard expiries, coalescing, RT has no slack, no event for a lone thread, none for an idle hart; negative control: a timer at the soft expiry of the first entry raises the count; mutation of `next_event` to soft expiries is caught). The kernel still ticks: **L13b** replaces the periodic tick with `stimecmp` programmed from `next_event_on` (Sstc probed at boot, SBI timer deleted), reprogramming at the points where the answer can change (after a timer interrupt, after a switch, after an enqueue on a hart that runs something with an equal-priority peer waiting), idle harts and lone runners taking no interrupts, `ticks()` derived from the clock; **L13c** the watchdog as a timer entry while a hart has queued work, and the tick-time `balance` as a slice-end action.

## L13b built (2026-11-19): no tick

There is no periodic interrupt on any hart. `timer.rs` drives Sstc `stimecmp` one-shot (`timer::program(event)`); the boot probe writes a pattern to `stimecmp` and panics if it does not read back (OD127: no SBI fallback; the SBI `set_timer` path is deleted). Each hart's timer is armed by `thread::program_timer` to `Sched2::next_event_on(h)` (the earliest hard expiry of a sleeper, or a slice end only when an equal peer waits), and in debug builds also to the next starvation-watchdog sample while the hart has queued work (the watchdog is a timer entry now: an idle hart with nothing queued arms nothing). `program_timer` runs wherever the answer can change: after a timer interrupt, at the end of every switch (`switch_done`), after a wake or enqueue here (`note_resched`), in the fast reschedule and yield paths, and before idling. A thread queued behind an equal one on another busy hart marks that hart (`after_enqueue`), so it arms its slice timer. The scheduler charges the running thread at every settle from a clock source (`Sched2::with_clock`, `HartRq::charge`): between two interrupts a switch no longer loses or misattributes time. `thread::ticks()` is the clock in milliseconds. A secondary hart parked before the scheduler exists polls for it once a millisecond (a one-shot, not a tick). A whole-process exit now kicks the harts running siblings (it relied on the next tick before: found by `unmap_while_siblings_touch` hanging). The timer tests are rewritten: an idle hart takes no timer interrupt in a second (`idle_harts_take_no_big_lock_for_their_ticks`), a hart running one user thread takes at most three in 80 ms (`user_mode_ticks_take_no_big_lock`, `user_clock_get_and_yield_take_no_big_lock`), the latency probes are in nanoseconds with bounds that allow the emulator's timer jitter (up to about 2 ms seen). The three scheduler negative controls still end in `starved thread` (run by hand). Checked by `make kquick`, `os-ktest-small`, `os-ktest-release` and `make smoke`. **Left (tidy T169):** `balance` of equal-priority queues now runs only at timer events (it ran every tick); the slack is not settable from user mode (`thread_set_sched` reserved flags); the RT window boundary entry does not exist yet (RT budgets are not enforced); closing L28 and T78 is deferred to the end of L13.
