## Shortcut

**DMA frames outlive a killed driver only by policy.** The kernel frees a DMA VMO like any other; a device mid-request could write into freed frames. S6b's answer is ownership: the *supervisor* keeps its own handle to the DMA buffer and the MMIO slot across driver lifetimes, so killing a driver frees nothing, and resets the device (`STATUS = 0`) before the buffer goes to the next driver, which also clears the queue memory itself. Implemented and tested in the suite's `BlkRig` (`blk_driver_restart`); `blkd` zeroes the queue at start. Nothing in the kernel enforces it: a supervisor that closes its handle while a driver is alive, or that dies, can still lose the frames to the device.

## Why it was acceptable

Only trusted boot code supervises drivers; no IOMMU (OD14).

## Proper fix, and when

The S6c device manager follows the same rule and is the only holder of DMA VMOs; a kernel-side quarantine until a device-reset acknowledgement if drivers ever stop being trusted.
