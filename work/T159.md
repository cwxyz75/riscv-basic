## Shortcut

`scripts/syscall_tests.py` (KT4) maps every (call, status) pair of `docs/reference/SYSCALLS.md` to a test of the suite whose body calls the
syscall and mentions the status; 31 of 217 pairs have none (`UNTESTED` rows of `docs/reference/syscall-tests.tsv`, the list):

- `channel_call`: BUFFER_TOO_SMALL, NOT_SUPPORTED, NO_MEMORY, PEER_CLOSED, SHOULD_WAIT
- `channel_create`: NO_MEMORY
- `channel_read`: NO_MEMORY
- `futex_lock_pi`: ACCESS_DENIED, BAD_STATE, INTERRUPTED, INVALID_ARGS, NOT_SUPPORTED, TIMED_OUT
- `interrupt_create`: ACCESS_DENIED, NO_MEMORY
- `port_bind`: NO_MEMORY
- `port_rearm`: ACCESS_DENIED, BAD_HANDLE, WRONG_TYPE
- `process_create`: ACCESS_DENIED, BAD_HANDLE, NO_MEMORY, WRONG_TYPE
- `thread_get_sched`: BAD_STATE
- `thread_interrupt`: INTERRUPTED
- `thread_set_sched`: BAD_STATE
- `vmo_commit`: BAD_HANDLE, TOO_BIG, WRONG_TYPE
- `vmo_create`: NO_MEMORY
- `vmo_create_physical`: NO_MEMORY

## Why it was acceptable

The kernel-only boot (KT1) and the host syscall layer (Phase 3, TS items) will test errors by table; this item is the list they work from. An untested error is not necessarily wrong, only unproved.

## Risk

A documented error that the kernel does not return, or returns for the wrong reason, goes unnoticed.

## Proper fix, and when

A test per pair (most are one assertion in an existing test); the table check shrinks the list by itself (a row marked `UNTESTED` that a test now covers fails the check until it is regenerated). With the syscall layer on the host (TS3), where error paths are cheap to drive.
