## Shortcut

**Signals (S11 first part, OD119): shortcuts** (2026-11-17):

- (1) **delivery only where a program waits or calls the library**: a program in a CPU loop is not interrupted, so `alarm` cannot stop one (a real `timeout` needs the kernel's `thread_interrupt`, T56, or a timer thread)
- (2) the mask is process-wide, handlers run on whichever thread reaches a wait first, and the blocked mask is saved and restored around a handler (a handler that changes it is overridden)
- (3) `poll` and `select` are interruptible now (resolved); the socket calls, futex waits (`pthread_cond_wait`) and the file-protocol calls are not
- (4) no `SIGCHLD`, `SIGPIPE` (a write to a closed stream is `EPIPE`), `SIGTSTP`, process groups, sessions or job control (`kill(0, ...)`, `kill(-1, ...)`: `ESRCH`; `setsid` fails); stop and continue signals are ignored; `SA_SIGINFO` is not honoured
- (5) (resolved 2026-11-17) Ctrl-C is the signal SIGINT for a foreground program that has a handler for it or ignores it: the program tells the shell when its disposition changes, the shell keeps it off the console server's kill list and passes the signal on when the server reports the Ctrl-C (`Event::JobInterrupt`); a program that never says (no libc, or the default) is ended as before
- (6) `SIGKILL` to a program that is not the caller's child goes through the shell, which holds every process handle of its chains; it is tested only by the child path
- (7) the signal channel holds at most the kernel's queue of undelivered numbers: a full queue drops a signal (as coalescing does)
- (8) the exit code `-2000 - signal` and the host's numbering: the numbers are Linux riscv64's, the test prints booleans because the host's differ
- (9) `getsid` and `setsid` fail
- (10) (a `vfork` child's changes to the signal table and mask are undone when it ends: resolved) a handler that does not return (`longjmp`, `_exit` in a `vfork` child) leaves its signal blocked (there is no `sigsetjmp`)
- (11) the program's end of its signal channel is a full channel end (it can write messages the shell never reads: bounded by the kernel's queue, freed with the broker; a read-only duplicate would close it)
- (12) pseudo pids for children that ended before they began count from 1,000,000 and share `CHILDREN` with the shell's pids; a program can fake "killed by signal N" by exiting with `-2000 - N` (nothing authorises from it)
- (13) a signal to a held child that the shell has no channel to (depth five) ends it if it would be fatal and is otherwise dropped.

## Why it was acceptable

A real subset (handlers, masks, `EINTR`, `alarm`, `kill` between a program and what it started) with the host as the oracle, and no kernel change.

## Proper fix, and when

- (1) `thread_interrupt` (task 26) and a delivery check on return from user-mode waits, or a signal thread
- (3) the rest of the blocking calls
- (5) tell the foreground program: T47; (4) with job control (SH, S11).
