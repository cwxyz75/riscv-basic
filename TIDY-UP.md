# Tidy-up register (OS track)

Every shortcut, stand-in and "good enough for now" that we have knowingly taken, so that none
of them is forgotten and none quietly becomes the design. An entry says what the shortcut is,
why it was acceptable when taken, what it risks, and what the proper fix is and roughly when.

Rules:
- When you take a shortcut, add an entry here in the same PR. If a milestone's review or audit
  finds a deferred issue, it goes here (and in the decision log if it is a decision).
- When an entry is fixed, move it to "Resolved" with the PR number; do not delete it.
- Severity: **H** can hurt the system or its security once untrusted code runs; **M** weakens a
  design property or will cost real rework later; **L** convenience or polish.
- The decision log (`OS-ARCHITECTURE.md` section 17) records *decisions*; this file records
  *debts*. An item can be both; the decision log points here.

## Open

### Security and isolation

| ID | Sev | Shortcut | Why it was acceptable | Proper fix, and when |
|---|---|---|---|---|
| T1 | L | **Per-job limits now cover processes, threads, memory pages, child jobs, objects and queued IPC bytes (S4.5, S4.5c).** Still not charged: kernel stacks (bounded by the global thread cap), the memory of kernel objects themselves, and page tables are an estimate. The global caps remain as backstops. Credits for destroyed objects are applied lazily (before the next charge, or when a ledger is read), so usage can read high for a moment. | The dangerous resources are all limited per job. | Charge kernel stack and object memory to the job; count page-table frames exactly. |
| T2 | M | **Ambient creation syscalls remain**: any process may `vmo_create`, `socket_create`, `channel_create`, `event_create` (bounded by its handle table and the global object cap) and `debug_write`; `process_create` is ambient but limited by the caller's job (a program's job allows no further process). | Needed by every program; the dangerous ones (processes, threads, memory) are now job-limited. | Gate object creation by the job's object quota (T1); restrict `debug_write` to a console capability. |
| T3 | M | **Trusted programs (`ls`, `cat`) get a standing read-only root** via `/etc/trusted` (S4 spec section 8). Contradicts least privilege in spirit, though allowed by OD20; and the list is baked into the read-only boot image at build time, so it is hardcoded in practice, not a user-editable config as OD20 intends (product owner accepted this for S4). | Lets the S4 acceptance session use absolute paths without a powerbox protocol. | **True powerbox**: the shell opens the path arguments itself and passes just those handles (argument syntax that references handles), no standing root; `/etc/trusted` goes away. With the manifest-driven shell (S10). |
| T5 | M | **`MANAGE` is coarse** (map, start, thread_create on a process). A kill-only right (`KILL`, S4a-1) now exists, but process rights are not otherwise split as OS-ARCHITECTURE section 9 wants (start, kill, read/write memory separate). | Enough for S4. | Split `MANAGE` (start / map / threads / debug-memory) when a second consumer needs it; at the latest before ported software. |
| T6 | M | **User-printed `##TEST` names are trusted** by the kernel's output parser; the serial bridge escapes `##` at line start (S4) but `debug_write` by test programs does not. | Test harness only. | With T2: `debug_write` only from the harness; structured results over a dedicated channel instead of the serial line. |
| T8 | L | **Handle tables are sized for the worst case** (4096 entries per process, about 4.6 MiB over 64 processes), allocated up front. | Fits the 8 MiB heap today. | Grow on demand with a hard cap; fits better once quotas exist (T1). |

### Test aids, runtime and format debts

| ID | Sev | Shortcut | Why it was acceptable | Proper fix, and when |
|---|---|---|---|---|
| T25 | L | **`init` still has test-aid commands** (compiled into every build; only the `repl` kernel starts `init` in the mode that reads them) (`raw`, `desync`, `big`, `rights`, `quitx`, `run`) that exist so the serial test can probe the bridge. | v0 supervisor with no shell yet. | Remove or gate them behind a test build when `init` stops reading the serial socket (S4d/S4e). |
| T26 | L | **The user heap lock yields but is a spin lock held across several syscalls** while growing; one reserved range, no shrinking, lazy growth means frame exhaustion shows up as a fault on first touch, not a failed allocation. | One program thread today. | Per-thread arenas or a futex-style lock; account heap frames to a job (T1). |
| T28 | M | **A channel's WRITABLE signal means "room for some message"**, not "room for this one": a 32 KiB reply to a client whose queue holds 230 KiB is refused with SHOULD_WAIT while WRITABLE is set. Servers must not wait on WRITABLE for backpressure (memfsd polls). | Simple signal model (S3a). | Make WRITABLE precise for a stated message size, or add a "space available" wait with a size, before more servers are written. |
| T29 | L | **`GetVmo` hands out the whole boot image** (read-only) plus the file's extent: any client allowed to read a boot-image file can read every other boot-image file. | The image holds only public programs and fixtures. | VMO slices/children (`vmo_create_child`) so a file's VMO is exactly that file. |
| T30 | M | **The launcher serves exactly one client and exits on any protocol violation** from it (an oversized message, a client that never reads a reply): with `sh` as the only client that takes the whole stack down (init rebuilds it). | One client in S4; the spec's "close that client connection" is the same thing with one client. | Multi-client launcher on a port, as memfsd does, once a second client exists. |
| T37 | M | **Some S5 spec items are deferred.** (The UART lock, the heap lock notes, the BKL and the lock-order checker now exist, S5b.) Parked secondary harts take no BKL for their timer or IPI traps (S5c changes that). Secondary harts park in `secondary_main` rather than in pinned idle threads (the scheduler does not run on them until S5c1). Harts that fail to start or are found running are logged and skipped. | Secondaries touch no shared state in S5a. | S5b adds the BKL, the lock-order checker and the debug asserts; S5c1 gives each hart an idle thread. |
| T38 | M | **The wake/IPI/idle race has no loom/shuttle model.** The BKL's protocol (ticket order, reentrancy, `try_lock`, the K3 depth hand-over) now lives in `kcore::ticket` and runs under loom and shuttle (tests: exclusion, `try_lock`, hand-over); loom found a real Relaxed-load ordering bug in `try_lock`, fixed. The multi-hart scheduler core has a per-class random model suite, but the wake/IPI/idle race (a wake between a hart's last look at the run queue and its `wfi`) is only covered by the QEMU suites. The S1 self-tests run before the lock is enforced (harmless: the secondaries are parked). | Randomised hart-count model tests and the QEMU suites stand in for the wake race. | A shuttle model of the idle/wake race. |
| T31 | L | **No start gate for pipeline stages; the Ctrl-C race is closed another way.** A stage runs at once and `sh` registers the job right after. A Ctrl-C before the acknowledgement reaches `consoled` with no job, but its 0x03 byte waits on the terminal and `sh` reads it after the acknowledgement and kills the stages itself (tested with `spin` and Ctrl-C in one write). What remains: a program can use the few milliseconds to do harm (nothing more than any program can); and the 0x03 is only seen if `consoled` could deliver it (not under an exhausted IPC budget, T2). | Simple, and no `rt` startup change. | The specified start channel, once programs need a gate for other reasons. |
| T34 | L | **Ctrl-D typed while a job runs is delivered to the shell later** (the job does not read it) and then ends the shell; `cat` on the terminal consumes it as data. Terminal type-ahead of 0x03/0x04 during a job is not discarded. | Matches the documented "no end of stream on the terminal"; harmless. | Discard lone 0x04 delivered while a foreground job is registered, once the console knows whether the job reads the terminal. |
| T35 | L | **Gaps in the S4d/S4e tests**: no program exits early on a closed pipe (exit 141 untested); whole-stack restart after a service death and a bad halt message are untested; consoled's NoMemory retry and delivery cap are untested. | Needs fault injection (a service that dies on cue, an exhausted IPC budget) that does not exist yet. | A `die` hook in a test build of memfsd and a budget-hog program. |
| T32 | L | **A shell exit rebuilds the whole stack** (memfsd, launcher, consoled, sh), so `/tmp` contents and the shell's directory are lost on `exit`/Ctrl-D. The launcher serves one client (T30) and has no way to hand over. | Simple and matches the death policy; nothing in S4 keeps state across shells. | A multi-client launcher (T30) lets init restart only `sh`. |
| T33 | L | **Programs cannot write files**: `sh` has no redirection and no write program, and the shell's root connection is read-only. | S4's acceptance only reads; `/tmp` is reachable only through test commands. | A `write`/redirection slice with a per-program writable-`/tmp` powerbox entry. |
| T27 | L | **Wire formats beyond the startup message** (console control, `ReadDir` entry packing, file framing) were defined in `proto` and its goldens, not first in the spec; the spec now points at those goldens as normative. | The spec stayed at the level of operations. | Spec appendix with the byte layouts when memfs and consoled land (S4c/S4d). |

### Concurrency and kernel structure

| ID | Sev | Shortcut | Why it was acceptable | Proper fix, and when |
|---|---|---|---|---|
| T11 | M | **Syscalls are non-preemptible and now also serialise every hart** through the big kernel lock: a long syscall (64 KiB copies, object sweeps that are O(live objects), `reap_vmos`) stalls every other hart's kernel entries, and the lock is held across the whole of each. Latency of a high-priority thread's kernel entry now depends on the longest region on any hart. | Short in practice; user code runs in parallel. | Per-object locks on the hot paths (scheduler, channels, handle tables) with the lock order extended (rung 3 of OS-ARCHITECTURE section 7), or bound the work per call; measure with the S2 latency test under `-smp 4`. |
| T12 | L | **Single global wait queue** (OD43): every signal change wakes every waiter, so wake cost is O(waiters) per syscall; a missing notify can be masked by any other (found by the wake-up audit). | Simple, easy to get right. | Per-object wait queues once there are many waiters (S5/S6); keep the audit probes as regression tests. |
| T40 | L | **S5 test gaps.** The churn stress has no process or job churn (it churns channels, VMO mappings, sockets, events, ports, threads and yields) and the unmap test uses a different-contents VMO rather than a refilled canary; the SMP suites run in debug builds only for K1; only hart 0 advances the scheduler's tick time, so tick-based bounds loosen when hart 0 spins on the lock. (The frame oracles are now exact, no slack.) | Adequate to catch the bugs the negative controls target. | Process/job churn and a wake-protocol shuttle model with T38. |
| T41 | M | **Device authority stand-ins (S6a).** The DMA budget is one system-wide constant (`MAX_DMA_TOTAL_PAGES`), not a per-job quota; `DEVICE_WINDOWS` is a hard-coded QEMU `virt` constant (the device manager now reads the slots from the device tree, S6c, but the kernel still only lets a physical VMO name the fixed window; likewise `MAX_IRQ`, the PLIC base and RAM size); any number of physical VMOs may alias the same slot (no exclusivity, so two drivers could fight over a device); physical VMOs are pinned to the root job and counted as one object. | Only the privileged boot process holds the resource, and the test suite and (S6c) the device manager are its only users. | Per-job DMA quota; windows from the DTB; an exclusive-claim record per device slot. |
| T42 | H | **DMA frames outlive a killed driver only by policy.** The kernel frees a DMA VMO like any other; a device mid-request could write into freed frames. S6b's answer is ownership: the *supervisor* keeps its own handle to the DMA buffer and the MMIO slot across driver lifetimes, so killing a driver frees nothing, and resets the device (`STATUS = 0`) before the buffer goes to the next driver, which also clears the queue memory itself. Implemented and tested in the suite's `BlkRig` (`blk_driver_restart`); `blkd` zeroes the queue at start. Nothing in the kernel enforces it: a supervisor that closes its handle while a driver is alive, or that dies, can still lose the frames to the device. | Only trusted boot code supervises drivers; no IOMMU (OD14). | The S6c device manager follows the same rule and is the only holder of DMA VMOs; a kernel-side quarantine until a device-reset acknowledgement if drivers ever stop being trusted. |
| T43 | M | **Interrupt objects are minimal (S6a-2).** PLIC only (detected by scanning the device tree for `riscv,plic0`; AIA machines get NOT_SUPPORTED and drivers poll), the boot hart's context only (every device interrupt is taken on hart 0), the source range is the eight virtio slots, and the PLIC base (`0x0c00_0000`) is a constant. QEMU's PLIC raises on a level *change*, so the test cannot show that a still-asserted line re-fires after the ack, nor that masking prevents a storm (real hardware: both; the claim is held open until the ack for exactly that reason, but only QEMU has run it). A source can be pending from before the object existed, so a driver must tolerate one spurious interrupt after `interrupt_create`. | Enough for virtio-blk on QEMU; the polling fallback covers AIA. | Read the PLIC base and source count from the device tree (the device manager reads the tree now, the kernel still uses constants); route to the hart that owns the driver; an APLIC/IMSIC backend; a hardware-level storm test. |
| T47 | L | **Ctrl-C always kills the foreground job**, so an interactive `basic` program in an endless loop can only be stopped by losing it (BASIC's own BREAK key cannot be delivered). | S4 console design: Ctrl-C is a kill, not a signal. | A console "raw break" mode where Ctrl-C is delivered as an in-band byte to a program that asks for it. |
| T56 | M | **No thread cancellation and no interruptible waits** (design review D9; wanted, deliberately deferred). A thread blocked in a wait or a `channel_call` cannot be told to stop short of killing its whole process, and the C library has no `pthread_cancel` (T52). | The cheap-threads work (slice T, OD79) reserves the places (an `INTERRUPTED` status waits may return, a per-thread interrupt flag, a reserved `thread_interrupt` call returning `NOT_SUPPORTED`) so nothing built meanwhile assumes a wait cannot be interrupted. | Implement `thread_interrupt`, make every blocking call return `INTERRUPTED` when the flag is set, then `pthread_cancel` in the C library (deferred or asynchronous per POSIX), and cancellation in the service runtime's request handling. |
| T49 | L | **Timing-sensitive tests that flake under host load.** (Also fixed: `threads_created_but_not_run_when_the_process_ends` raced on SMP, its second thread could end before the first thread left, making the first the last; the second now waits 20 ticks.) `bkl_is_released_on_user_entry_and_idle` (its threshold "lock found held < 1/4 of takes" failed twice at `-smp 4`, with 22% and 47% held, while the host was busy; relaxed to "free at least as often as held", which still fails for a lock held across user mode) and the sleeper-arrival naps in the S7b futex tests (`nap_ticks(15)` to let a thread reach the kernel's table) assume the host keeps up. (`futex_wake` used to wake every blocked thread in the system when it woke a sleeper; since slice W step 2 it wakes exactly the sleepers it removed, by id.) | The gate passes on an unloaded machine; a rerun settles a flake. | Observe instead of waiting (a readiness signal or a kernel-side sleeper count a test can read); a per-futex wake instead of the global queue wake (T12). |
| T57 | M | **FP state is uncharged kernel memory (slice A review).** A thread that uses floating point gets a 264-byte register box and a map node on its first FP instruction, allocated from the kernel heap without charge (running out is a kernel panic, not NO_MEMORY); it is bounded only by the thread limits (128 threads). `return_to_user` also takes the big lock and does a map lookup on every return to user mode, including light IPIs that took no lock before. | Bounded and small; the save and reload are correct. | Embed the FP state in the thread record and charge it to the job at `thread_create` (slice T, kernel memory charged to jobs); keep a per-thread flag so threads without FP state skip the lock and lookup; measure with the Lua benchmark. |
| T50 | M | **The C library is a first cut (S7c-2).** (`FILE`, files and the fd table arrived with S7c-3a.) `errno` is one global per process (per-thread storage comes with pthreads); `qsort` is a heapsort (unstable, fine for C, slower than introsort); `malloc` rides the runtime's first-fit heap (about 15 MiB per program, T26) (small blocks now come from size-class free lists, S7d: the first-fit walk was quadratic for Lua's pattern, measured); `rand` is our own LCG (not glibc's sequence); the C transcript compares only what the C standard defines (no `strerror` text, no `%p`, no last-digit libm). Building the boot image now needs a RISC-V-capable clang (or `ctest` is a stub and its test fails): CI installs `clang llvm`, locally `brew install llvm` or `CC_RISCV`. | The slice's purpose was the ABI, the asm stubs and the C build path. | S7c-3 (FILE, fds, time, pthreads); measure malloc under Lua. |
| T51 | L | **Files in the C library are limited (S7c-3a).** There is no ambient `/tmp`: absolute paths resolve against the `/` namespace entry (the shell gives only a read-only one to trusted programs), `tmpfile`/`tmpnam` make scratch files in the working directory, and a shell-started program has no writable place at all (T33); the fd table and `FILE` table hold 64 each; one global lock covers every fd operation including blocking file-protocol calls (a slow server stalls all of a program's threads' file I/O); `ungetc` keeps one character; `struct stat` is `{size, mode}`; the stream functions are not thread-safe per stream beyond that lock. | Enough for Lua's `io` library on a granted directory. | A writable per-program scratch directory from the launcher; per-fd locks; `sscanf`/`fscanf` if a program needs them. |
| T52 | M | **Threads in the C library are a first cut (S7c-3b).** Stdio streams have no per-stream lock (a `FILE` shared by threads needs the caller's own locking; the fd table has one global lock), a detached thread's stack, control block, thread handle and slot are leaked until the process ends (a thread cannot unmap its own stack; after 64 detached threads `pthread_create` fails with EAGAIN), `pthread_key` destructors never run, there is no `pthread_cancel`, barrier, read-write lock or `pthread_attr_setstack`, thread stacks are one fixed size (256 KiB, 64 slots; a larger `pthread_attr_setstacksize` is EINVAL), `pthread_exit` from the main thread ends the process (POSIX lets the other threads run on), a deleted-and-recreated key keeps stale values in other threads, `nanosleep` does not validate its argument, `rand`/`strtok`-style hidden state is not thread safe, and the launcher's 4-thread program limit means a shell-started C program can run main plus three threads. | Lua is single threaded; the tests under the suite's job cover the primitives. | Per-stream locks; a reaper for detached threads (a joiner thread or a deferred unmap); the rest as programs need them. |
| T44 | L | **Gaps in the block-driver tests (S6b).** (The harness now checks the whole image from the host after QEMU exits, `check_disk`: it catches an address bug the guest's read-back cannot; mutation-checked. Flush is still unverifiable: QEMU's raw file writes land in the host page cache either way.) ReadOnly, Timeout (the driver exits 10), IoError and a client that never reads replies are untested; the leak checks cover the driver's own job (processes, pages) but not the DMA VMO, channels or interrupt object; the in-flight-kill test kills a driver with a queued write but cannot know the device was mid-request; acceptance 8's `blk_bad_requests` is folded into `blk_round_trip`. | The round trip, bad requests and restart all run on QEMU in both interrupt and polling mode. | A read-only device and a stalled device in the harness. |
| T39 | L | **TLB shootdowns flush everything on every other hart** (SBI `remote_sfence_vma` with no range or ASID) on each unmap and teardown, and run synchronously under the big kernel lock. Correct but coarse. | Few harts, short regions. | Range/ASID shootdowns, tracking which harts ran a given address space, batching (S5 rung 3 or later). |
| T13 | L | **Fixed 8 MiB kernel heap and hand-tuned caps** that must jointly fit it (OD50). | Works; audited. | Size caps from the heap or let the heap grow from the frame allocator; revisit with T1. |
