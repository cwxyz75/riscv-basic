# Invariants (OS track)

Rules every change to the OS track must preserve. Reviewers (and the independent
review pass at the end of each milestone) attack code against this file and
`SYSCALLS.md`. A rule is only listed here if a test, a checker or a debug assertion
can fail when it is broken; the "How checked" column says which, and "S?" says the
milestone that makes the check real. Rules without a check yet are marked **TODO**
and are the first things S-milestones add.

Skeleton created in S0 from `OS-ARCHITECTURE.md` (sections 5 to 7, 10); the details
get filled in as each area is built.

## Handles and rights

| # | Invariant | How checked |
|---|---|---|
| H1 | A handle value cannot be forged: only the kernel mints values, and a value names an entry in the caller's own table | `kcore/tests/handle_model.rs`: random and adversarial values never resolve unless live (S3a) |
| H2 | Stale values fail: a closed or reused slot's old value is rejected (a 40-bit generation counter in bits 24 to 63 of the 64-bit value); value 0 is never valid | `handle_model` (S3a, extended for AB1: 100,000 live handles, slot numbers above 8191); a slot that has used all 2^40 generations is retired, never reused, so no stale value comes back by wrap-around (the retirement tests, with the generation fast-forwarded to 2^40 - 2) |
| H3 | Rights only shrink: duplicate, replace, transfer and open never produce a handle with a right its source lacked | `handle_model`, `channel_model` (a model of every handle's rights), `rights_escalation_is_refused` (S3a) |
| H4 | A message in flight owns its handles: if the channel dies they are closed, never leaked, and never duplicated | `channel_model`, `registry_model`, `cycles_are_swept` with `Registry::live()` as the leak counter (S3a) |
| H5 | Authority is holding a handle: no syscall consults identity, a path or ambient state to grant access | Review against `SYSCALLS.md` (S3) |
| H6 | Process death releases every object it held | Table drain + reachability sweep tested on the host (S3a); QEMU `process_exit_releases_all_objects` and `process_teardown_returns_every_frame` for a single process (S3b); S3c-2a: children launched, killed (running, blocked, never started) and abandoned by their parent leak nothing (`no_process_or_vmo_survives_init`, `many_children_do_not_leak`); a VMO lives while a handle or a mapping does; threads in S3c-2b: a process is torn down only after its last thread has left (`many_threaded_children_do_not_leak`) |

| M3 | Frame reference counts are conserved: after any map/unmap/fault/teardown sequence the counts return to baseline | Model tests end with a baseline check (the buddy models also require a full merge back to the initial free lists); QEMU `balanced()` wraps every lazy-memory test, plus `churn_does_not_leak` (S1) and `dma_runs_are_allocated_and_freed_repeatedly` (MM2) |
| M3b | A page fault maps the faulting page and, in the same region and 64 KiB aligned window, the pages its VMO has **already committed** (fault-around, MM1); it never commits a page for a neighbour, and the neighbours take their mapping reference like any mapping, so M3 holds. | M4 | All memory operations go through the VMO interface, never directly to frames | Review; the only frame-granting path to a mapping is `AddressSpace::handle_fault` via `Vmos::page_for` (S1) |

## Concurrency

| # | Invariant | How checked |
|---|---|---|
| C1 | **Lock ordering is global and fixed**, listed below; a lock is only taken while holding locks earlier in the order. Not negotiable | Debug-build lock-order checker (S5); loom/shuttle on extracted logic |
| C2 | Interrupts are disabled while a spinlock is held | Debug assertion (S5) |
| C3 | One block/wake path: no lost wakeups and no double wakeups. Since task 10 this is the park protocol (PK1): a thread prepares before it registers, a wake counts only for a prepared or blocked thread and is never remembered; the wake token and the pure `WaitQueue` are gone | loom/shuttle on `kcore::park` (`park_concurrency.rs`, three negative controls); `kcore/tests/sched_model.rs` (model, park scenarios, mutation-checked) and QEMU `wake_before_block_is_not_lost`, `producer_consumer_loses_no_wakeup` |
| C3b | Blocking waits lose no wakeup: the condition is checked, the thread registered in the wait table (`object_wait`, `channel_call`, a kernel thread's read wait) and put to sleep in one interrupts-off step under the big lock; every registry mutation is logged (`Registry::get_mut` touches the object and its peer, handle removal is a forced touch) and the log is committed before the lock is released (after every syscall and every trap from user mode, and before any such wait sleeps), waking exactly the registered threads whose predicate can have become true, by id. Port waits (`port_wait`) register on the port like any other wait (a port's signal follows its bindings, so registrations on ports are re-evaluated when an object the port binds, or the port itself, was touched (L21a: the table remembers what each port with a waiter binds)); there is no global wait queue any more (OD43 retired). A port wakes one `port_wait` waiter, the first in line, when it becomes ready (waiters that do not poll, an `object_wait` on its READABLE, are all released and take no baton), and the next commit after that waiter's poll (which logs the port; a thread that wakes and cannot poll touches it) wakes the next while a binding is still ready (PW, L21b); `channel_call` registers for its reply (the transaction id on its channel end) and the peer closing, not for READABLE, so an unrelated queued message does not wake it (L21d); a port binding ends with the handle it was made through (L21c: `Registry::handle_gone` notes the removal, `ipc::end_bindings_made_through` ends the bindings, in the commit; `Slot::watchers` counts the bindings that name an object and is given back when a port is destroyed) | QEMU `wait_is_woken_by_a_message`, `channel_call_*`, `replacing_a_handle_ends_a_siblings_wait` (negative control `fault-skip-forced-touch`), `wake_baseline_bystanders_and_counters` (zero spurious wakes, bystanders not woken), `kcore/tests/wait_model.rs` (the random walk with port waiters under PW, the baton, the call registration and the binding lifetime, mutation-checked: wake-all, any-message, handles ignored) and `touch_complete.rs` |
| C4 | Each runnable thread is in exactly one place (a run queue, running, or blocked) | `Sched::audit` after every step of the random model test, for every policy; the core rejects a policy pick that is not runnable (`bad_picks`) (S2); since task 11 the kernel's scheduler is `Sched2`, checked by `Sched2::audit` (GP2) in `sched2_smp_model.rs` and `sched2_kernel_walk.rs` |
| C5 | Atomics and fences live only in `kcore::sync` and the small audited layer; everything else relies on `Send`/`Sync` | The docs check (`scripts/check_docs.py`, `check_atomics`) scans the kernel crates for atomic types: a file outside the allow-list, or with more than its recorded count, fails (each entry carries the layer it belongs to); mutation: a planted `AtomicU64` in `user.rs` fails it |
| C6 | Scheduler state is touched only with the big kernel lock held and interrupts disabled (it was interrupts-off on one hart before S5), and never across a context switch; the kernel heap is interrupt-safe because the tick allocates | `debug_assert` in `thread::kernel()` (K1); heap wrapper (S2); the lock since S5b |
| C7 | Kernel threads do no floating point and thread switches save no FP state, so `sstatus.FS` stays Off and accidental FP use traps | QEMU `fp_unit_is_off` (S2); user threads may use FP since slice A: see FP1-FP3 (the kernel itself still does none) |

### Job and limit rules (S4.5)

| # | Invariant | How checked |
|---|---|---|
| J1 | A charge applies to a job and every ancestor, all or nothing: no job's usage ever exceeds a limit that was in force when it was charged, and a child never uses more than its parent allows; page usage includes the pages an address space has prepaid from a limited job (`kcore::aspace::Reservation`: usage is committed plus prepaid, the reservation holds a use of its job until it is given back, and teardown gives it back) | `kcore::job` unit tests and a random model; QEMU `a_child_job_cannot_exceed_its_parent_or_borrow_from_a_sibling` |
| PR1 | A thread's base priority never exceeds its job's `max_prio`, and a job's `max_prio` and `rt_budget` never exceed its parent's (PR2): no call raises a job's limits above the parent's, lowering one lowers every descendant and clamps the live threads, a new thread's priority is clamped at creation | `kcore/tests/job_sched.rs` (random model), QEMU `thread_priority_is_bounded_by_the_job` (a confined program; lowering clamps a live thread), mutation-checked |
| J2 | Every charge is credited back exactly once: a process at teardown, a thread when it ends (its stack, and its FP and vector state in kernel bytes), a page when its VMO is freed, an object body when the object is destroyed (`user::job_ledger` reads the root job's kernel bytes too), a handle table's growth when the process's teardown credits what `HandleTable::settle_growth` charged. A job record with usage is never freed (`debug_assert` in `Jobs::release`: a leak is a kernel panic in the tests) | QEMU `jobs_do_not_leak`, `job_*_credited_back`; mutation-checked |
| J3 | No ambient job authority: no call returns the caller's own job; `job_root` is refused to every process the kernel did not start; a job handle's rights only shrink (H3) | QEMU `job_syscalls_check_handles_rights_and_arguments` (a child proves it) |
| J4 | A job's memory is charged where the page is committed (`Vmos::page_for`), nowhere else: no path commits a page without the charge | code structure; `committed_pages_are_charged...` |
| J5 | Objects and queued data are charged exactly once and credited exactly once: an object's creator pays for the object, the creator of an endpoint pays for what is queued in it, and a destroyed object's credit is applied before the next charge; a charged object holds a use of its job until then, so a record never goes while it has usage | `kcore/tests/job_ipc_quota.rs` (a random walk compared with the registry's own counts), QEMU `job_quotas_...`, the end-of-session ledger check; mutation-checked |

| # | Invariant | How checked |
|---|---|---|
| SMP1 | In kernel code `tp` holds `&PerHart` of the hart running it. ### Floating-point rules (slice A, OD76)

| # | Invariant | How checked |
|---|---|---|
| FP1 | A user thread starts with the FP unit off (`sstatus.FS` = Off): it cannot read any FP register, so it never sees another thread's or process's values; its first FP instruction traps as an illegal instruction, the kernel enables it from a zeroed register file, and the instruction is retried. A real illegal instruction traps again with the unit on and ends the process | QEMU `fp_state_is_private_to_each_thread_and_process` (a process's first FP use reads zeros while others keep patterns), `vector_state_is_private_to_each_thread_and_process` (the vector twin, VS1) |
| VS1 | The vector unit follows FP1 with `sstatus.VS` for `sstatus.FS`: a user thread starts with it Off, its first vector instruction (or `vlenb`, `vl`, `vtype`, `vcsr` access) traps, the kernel enables it from a zeroed state of `32 * vlenb` bytes plus `vstart`, `vcsr`, `vl` and `vtype`, and a dirty unit is saved at every trap from user mode and reloaded unless the hart already holds the thread's exact state (the same ownership model as FP, `kcore::fp`). The kernel runs with FS and VS Off; every hart has the same `vlenb` or the boot stops | `kcore/tests/vec_model.rs` (mutation-checked), QEMU `vector_state_is_private_to_each_thread_and_process`. **Claims (T166):** each hart records which thread's latest FP and vector state its registers hold (`fs_claim`, `vs_claim`, with the address of that thread's saved copy); a thread whose claim is on this hart returns to user mode with no lock, and the trap paths that take no lock (a `clock_get` or `thread_yield`, the tick, an inter-hart interrupt) save dirty state into the claimed copy. | FP2 | On every trap from user mode the dirty FP registers are saved into the thread before anything else can use the hart's unit, and the kernel runs with the unit off; on every return to user mode a thread with FP state gets exactly that state (loaded unless this hart already holds that exact state, by a unique token) | `kcore/tests/fp_model.rs` (random threads, harts, preemption, migration against a reference; mutation-checked), QEMU test above at one and four harts, mutation: skipping the save fails it |
| FP3 | The kernel does no floating point and runs with `sstatus.FS` Off (C7); the unit is on only inside `kernel/src/arch/riscv64/fp.rs`'s save and load | QEMU `fp_unit_is_off` |

### Memory commit rules (slice V)

| # | Invariant | How checked |
|---|---|---|
| V1 | A VMO charged to a job that is neither the caller's nor the address space owner's is mapped only over a range that is already committed: its *data pages* are paid for, so a touch of a mapping never charges a stranger or fails on the VMO's job's quota. Scope, stated plainly (TIDY-UP T58): it separates *jobs*; a hostile peer in the same job, or in a sibling job under a shared ancestor limit, can still hand over a lazy VMO; and the page-table frames a first touch needs are taken at fault time, so a touch can still fail when frames themselves run out | QEMU `vmo_commit_charges_up_front_and_foreign_maps_need_it` (a mutation that removes the check fails it) |
| M9 | A mapping never has more permissions than the rights of the VMO handle that made it allowed (`max_perms`: read always, write with WRITE, execute with EXECUTE), however `process_protect` is used; no page is ever writable and executable at once; protect changes page-table entries in place (no frame moves) and a permission taken away is dropped by every hart before the call returns (TLB2); a range unmap or protect splits mappings at its edges and neighbours that agree merge, so the regions are always the minimal cover of what is mapped | `kcore/tests/region_ops_model.rs` (a per-page model: permissions, ceilings, frames, references, minimality; mutation-checked: a split that copies the wrong offset, a protect that ignores the ceiling, a merge that skips contiguity, a protect that leaves the page table alone), `ksys/tests/proc_calls.rs`, the suite |
| V4 | `vmo_decommit` and a shrinking `vmo_set_size` are refused (BAD_STATE) over a range that a process of **another job than the VMO's** has mapped, so V1 holds for them too: a stranger's touch never charges the VMO's job, and a stranger is never ended by a VMO it was handed (a shrink under its mapping would fault it, a decommit would make its next touch a charge to the VMO's job). The VMO's own job's processes can take pages away (their mappings and translations go first, then the frames: TLB2) | `ksys/tests/proc_calls.rs` (`a_mapping_in_another_job_stops_a_decommit_and_a_shrink_but_not_a_grow`, mutation-checked) |
| EX2 | An exception is resolved exactly once: retried, passed to the next level (the process's channel, then its job's and each ancestor's) or ended with its process; a level whose channel is absent, closed or full is skipped and leaves nothing behind (no handle, no object); the faulting thread is stopped before anyone can read the message and runs again only after a RETRY (or never, if the process ends); closing the last handle to an exception passes it on; a process with no handler anywhere ends with `-1000 - kind` as before; a process killed with an exception pending leaves no object, handle or charge once the handler has closed the handles it was sent (until then the objects keep the dead process's job record alive, at most one queue of 128 messages); a thread stopped for an exception is released only by its resolution, not by `thread_resume`; a refused offer leaves no message and no decision (its dead object is resolved); the kernel's ends of exception channels are bounded by the object cap | `ksys/tests/exception_calls.rs`, the suite tests `a_handler_thread_can_make_a_faulting_store_succeed_and_retry`, `a_parent_handler_can_kill_a_child_that_took_an_illegal_instruction`, `next_reaches_the_job_channel_and_closing_the_handle_is_next`, `a_process_killed_with_a_pending_exception_leaks_nothing_and_a_closed_channel_is_skipped`, and the fault-kind tests of P3 |

### Lock order

1. **BKL** (`kernel/src/bkl.rs`): protects all shared kernel state. Taken by `irq::without` and by
   every trap handler (except an inter-hart interrupt, an external interrupt carrying only IMSIC message 1, and a parked secondary's timer in S5b); reentrant per hart;
   released on every path that leaves kernel code; released at a context switch and taken again, to the same depth, by the thread that resumes (K3, SCHED-SMP-SPEC G4).
2. **HEAP** (the allocator's spin lock, interrupts off): used inside and outside the BKL, so it
   comes after it.
3. **UART** (reentrant per hart, interrupts off, held for a whole formatted print): last, because
   anything may print.

A hart that holds a class may take a class with a *higher* number, never a lower one; the checker
(`bkl::note_acquire`) panics on a violation in every build and counts it. New locks go into this
list, with the reason for their position, in the change that adds them.

| # | Invariant | How checked |
|---|---|---|
| K1 | Shared kernel state is touched only with the BKL held (**except the scheduler core**, which since L11b is one run queue per hart behind its own lock of class RQ (instance: the hart) and the thread table behind one of class TT, reached through `thread::sched()` with no lock of its own; it is touched with the BKL held or from a tick, a reschedule IPI or a `futex_wake` ecall with only those locks; the futex table, L14, is the other exception: 64 locks of class FUTEX): `thread::kernel()`, `user::state()` and `kmem::get()` assert it (`debug_assert!`: debug builds only, so the release SMP run does not check K1) | the whole suite at -smp 1, 2, 4 in debug builds (a violation panics) |

| NET11 | **Stream integrity.** The bytes delivered to an application are at every moment a prefix of the bytes its peer wrote, in order, nothing repeated or missing; after a clean close they are equal (S9-SPEC N11) | `netsim` lossy-link suite (H16, H17) against a byte model; the slirp-peer tests (echo 200,000 bytes, 300,000 from and 100,000 to a host server, fetch and `httpd` by hash); the same four through the lossy relay (Q30) |
| NET12 | **No stall.** A connection with unsent or unacknowledged data, undelivered data or an unfinished close always has a timer armed, a packet in flight or a wait registered on its client's socket (N12) | the quiescence check of the lossy-link suite; `nettcp` RTO and persist tests; Q30 (a stall shows as a timeout) |
| NET13 | **Reservation.** A connection's send and receive buffers never exceed its reservation; reservations never exceed the account's `stream_bytes` or the pool; a segment from the network never makes `netd` use memory a local client did not reserve (N13) | `netcore/tests/tcp.rs` (accounts, posted accepts, admission gate), `net_stream_quotas_and_bad_handles`, `net_tcp_churn` (capacity after the churn) |
| NET14 | **The client pays for the kernel's buffers.** The stream socket pair and the endpoint channel's queues are charged to the client's job, never to `netd`'s (N14) | `stream_buffers_are_charged_to_the_client`, `a_client_at_quota_stalls_only_itself` |
| NET15 | **The stack never waits for a client and never loses acknowledged data.** A full or over-quota client socket leaves bytes in the receive buffer and closes the window; never an error, never a drop (N15) | `a_client_at_quota_stalls_only_itself`; the stalled-reader schedules of the lossy-link suite; one-shot bindings (`one_socket_two_one_shot_bindings`) |
| NET16 | **The window is honest.** The advertised right edge never moves left; no byte beyond it is accepted; no byte is sent beyond the peer's (N16) | `nettcp` tests (SWS, window update, persist), the flow check of `scripts/net_pcap_check.py` on every QEMU capture |
| NET17 | **No state change from an unacceptable segment.** A failed sequence check, a RST not exactly at `RCV.NXT`, a SYN on a synchronised connection or an ACK for unsent data changes nothing but counters and may cause one rate-limited ACK (N17, RFC 5961) | `nettcp/tests/handshake_close.rs` reset and injection scripts |
| NET18 | **End-of-file means the peer closed.** A clean end-of-file is seen only after the peer's FIN and every byte before it; every other end (reset, timeout, abort, stack death) is an error (N18) | `rt::net` tests, `net_streams_over_loopback`, `net_streams_survive_a_stack_restart`, `c_sockets_over_the_stack` (reset checks) |
| NET19 | **Connections do not outlive the stack, and strangers get a reset.** After a `netd` restart no old connection exists; a segment for an unknown connection gets a correct RST within the rate limit, and a RST never gets one (N19) | `netcore/tests/tcp.rs`, `net_streams_survive_a_stack_restart` |
| NET20 | **Timers.** No timer fires early; the RTO stays within its bounds and only grows between acknowledgements (N20) | `nettcp/tests/buffers.rs` (RTO against a floating-point reference, RFC 6298 examples) |
| NET21 | **Congestion bounds.** `cwnd` is at least one segment; bytes in flight never exceed `min(cwnd, peer window)` by more than the one segment a retransmission or probe adds (N21) | `nettcp/tests/congestion.rs` against a separate RFC 5681/6582 model (300 seeds) |
| NET22 | **Bounded lifetime.** A closed connection's record is freed within TIME-WAIT, an orphan within 20 s, a half-open one within its SYN limit; tables and pools return to their start (N22) | `netcore/tests/tcp.rs`; `net_tcp_churn` (2,000 connections with `bench=full`, the account takes streams again) |
| NET23 | **Loopback stays inside.** A loopback packet never reaches a ring, and no frame from the device is accepted with a 127.0.0.0/8 address (N23) | `netcore/tests/tcp.rs`; the capture of `net_streams_over_loopback` is checked to contain none of it |
| NET24 | **Sequence numbers do not repeat or leak.** For one four-tuple the ISN only moves forward within a boot, across `netd` restarts too; the secret is known only to `netsup` and `netd` and never printed (N24) | `nettcp/tests/isn.rs` (SipHash vectors, monotonic ISNs), `random_service_gives_seeded_distinct_bytes`; **caveat: the secret travels in `netd`'s startup environment, not a read-only VMO (T99)** |


## Filesystem (doofs, FS-SPEC section 10)

| # | Invariant | How it is enforced |
|---|---|---|
| FI1 | The newest valid superblock slot names a tree in which every block verifies, or mount takes the next older slot, or fails closed | `fsfmt::volume::mount` walks the tree (`verify_all`) before it accepts a slot; `a_torn_newest_slot_falls_back_to_the_previous_commit`, `a_block_from_another_volume_is_caught`, the corruption test (`doofs/tests/corruption.rs`: every 61st bit of every used block) |
| FI2 | A block reachable from the last committed root or the live tree is never overwritten or reused before the commit that supersedes it is durable | `Pool` retire/reclaim with the last commit pinned (`Volume::commit`); the free-list checks in `fsfmt/tests/tree.rs`, `volume.rs` and the differential's FI2 check; the crash harness (`doofs/tests/crash.rs`) drops and tears unflushed writes at every point |
| FI3 | After a crash at any point the remounted state is the model state at the last durable commit or at one in flight | `doofs/tests/crash.rs` (every one- and two-operation workload at every crash point, sampled three-operation ones), against `memfs` as the model; mutation-checked (no flush before the slot, no flush after it, free-everything, oldest-slot mount) |
| FI4 | Everything made durable by a returned `commit` (`fsync`) is present after any later crash | the same harness: a commit's end index makes its model the minimum allowed state |
| FI5 | Space is charged to exactly one quota domain and the counters equal the sum of their nodes | `doofs::fsck::check_fs` (counters, link counts, entry counts, orphans, attribute costs and every index entry against the nodes and attributes), run after every sample of the differential and after every crash; **the rights half (rights only shrink, a query stays below its directory) belongs to `fsd`, step 5c** |
| FI6 | Delete and commit succeed on a full volume | the 64-block reserve for the deleting paths (`Pool::set_reserve`, `allow_reserve`) and the retry-after-commit in `Fs::txn_with`; `a_full_volume_refuses_cleanly_keeps_its_data_and_frees_on_delete`, the pool-level reserve test |
| FI7 | A symlink target is relative and stays inside the connection it is read through | `proto::file::check_link_target` in `memfs` and `doofs` (the differential compares the refusals); **the client-side resolution belongs to the libc, T104** |

## Process rules

- No `unsafe` outside the hardware-facing kernel binary; each block has a
  `// SAFETY:` comment. The pure crates `forbid(unsafe_code)`.
- Every change leaves the system booting and the suite green.
