# Decision log (OS track)

Append-only record (`docs/records/`): rows are added, never edited or removed. Moved here from section 17 of
`docs/specs/OS-ARCHITECTURE.md` on 2026-11-18, unchanged; until then a row's status was sometimes updated in place.

From now on: a decision gets the next OD number and a new row at the end. A decision that changes an earlier one says so
in its own row ("supersedes OD43", "amends OD48"); the earlier row stays as it was. "Decided" means the product owner
said so; "Proposed" means a recommendation not yet confirmed (confirming it is a new row). Open questions are
`kind: decision` items in `work/` (`scripts/work.py decisions`).

| OD48 | Sockets and ports (S3c-3). A port is a **level-triggered, stateless wait set**: bindings (object, signal mask, key) hold no references and queue no packets, so there is nothing to overflow or lose; `port_wait` reports a currently-ready binding in rotation, and a port is itself READABLE while any binding is ready (so waiting on a port reuses the one wake path of OD43). | OD78 | **Service directory** (decided 2026-11-14 after design review D10; nothing built). Services are found by name through a **registry service** (not `init`): a service publishes a name by handing the registry a listener channel, and a client opens a name (`/svc/net`) with the file protocol's open-with-endpoint, which the registry forwards to the listener. A service that dies leaves its entry stale, which the registry notices (its listener closes); a client then sees `UNAVAILABLE` and retries (the service runtime supports that); no queueing in the registry. There is no global namespace: a program gets a *view* of the directory with only the names it may use, which is also how access to a service is granted; the startup message's closed `Role` enum gives way to generic named entries with arbitrary prefixes. For now the shell hardcodes what it grants. **Undecided, deliberately** (for later, with Q10): passing a service connection on to another program, and revocation. | OD79 | **Kernel memory comes from frames, and kernel stacks are not heap** (decided 2026-11-14 after design review D9; amends OD29; nothing built). The fixed 8 MiB `.bss` kernel heap (a first-slice simplicity choice, T13) is the reason every kernel cap (OD50) is hand-tuned to fit it and the reason 128 threads of 32 KiB stacks take half of it.
