# Review: S8 steps 3 to 5, the user-mode network driver and the stack (PR #139, branch `s8-device`)

Independent review with fresh context of `git diff main...s8-device` against `NET-SPEC.md`, `NET-DESIGN.md`,
`INVARIANTS.md` (NET1 to NET10) and OD98 to OD101. Scope: `netring/`, `init/src/bin/{netdrv,netd,netsup,devmgr}.rs`,
`proto/src/{net,devmgr}.rs`, `rt/src/{net,service}.rs`, `init/src/net_tests.rs`, `scripts/os_boot_test.py`.

What was run: `cargo test -p netring -p supervise -p proto` (green), and one scratch shuttle model outside the repo
(finding 4). Nothing was booted: every other finding comes from reading the code and none was reproduced in QEMU.
No file was changed except this one.

## Verdict

The data path itself is sound against a hostile peer: every slot number, length and index read from shared memory is
bounded before use, received frames are copied before they are parsed, the stack's pool handles really lack DMA and
WRITE, and class checks in `netd` cannot be bypassed through flags or ops. The supervision around it is not. Two bugs
in `netsup` defeat the restart contract (findings 1 and 2), `netd` spins a hart whenever it is detached (3), and the
doorbell's "ring was empty" rule loses wakeups that the loom model cannot see (4). Findings 1 to 3 should be fixed
before merge; 4 to 9 fixed or recorded in `TIDY-UP.md`; the test gaps in 15 explain why none of this was caught.

## Findings

1. **High. After one restart of `netd`, a later restart of the driver leaves the stack detached for good.**
   `netsup` sends a restarted driver's control channel to the stack on `sup_end` (`netsup.rs:402`), the channel made
   once at `netsup.rs:314`. `restart_both` makes a new supervisor channel for the new `netd` and throws its own end
   away (`let _ = pair.a1`, `netsup.rs:670-681`, "leaked on purpose"); `sup_end` still names the dead `netd`'s channel.
   Scenario: `Restart{netd}` (or a `netd` crash), then any driver exit (`Restart{netdrv}`, a ring violation, the
   bad-slot fault). The write at 402 fails (result discarded), the new control end stays open in `netsup`, the new
   driver sends READY into it and waits for ATTACH forever, `netd` has `ctl = None` and never attaches. `Status`
   reports everything running and not down. Each `netd` restart also leaks one channel handle.
   `net_children_restart` kills driver, then dhcpc, then stack, the one order that cannot show it.
   Fix: keep the supervisor channel in mutable state, replace (and close) it in `restart_both`; treat a failed write
   at 402 as a failure. Add a test: restart `netd`, then the driver, then ping.

2. **High. The restart intensity windows are a million times too long.** `supervise` counts time in nanoseconds
   (`supervise/src/lib.rs:14-15`, `Policy::NET` windows `30 * SEC`, `60 * SEC`), but `netsup` passes
   `sys::clock_get()` ticks of 1 ms (`netsup.rs:372`, `452`), while it converts the returned delay as nanoseconds
   (`delay / 1_000_000`, `netsup.rs:455`). The 30 s window is therefore about 347 days.
   Scenario: the driver is restarted four times over a month (or seven restarts of anything): `on_exit` returns
   `Down` and the network stays down until reboot. The delay table also never resets (every restart after the
   second waits 1 s). Q14 passes either way because its crashes are seconds apart.
   Fix: `sup.on_exit(idx, now2 * supervise::MS, ..)`. Add a host test of the `netsup` glue or a QEMU case with
   restarts spaced past a (test-shortened) window.

3. **Medium. `netd` busy-loops whenever it is not attached.** `next_deadline` returns `now` while `self.more` is set
   (`netd.rs:765-769`); `more` starts true (`netd.rs:848`), is set by every `other_event` and client request
   (`netd.rs:762`, `572`, `661`) and is cleared only at the end of `pump` (`netd.rs:376`), which returns early when
   detached (`netd.rs:263-268`). A core timer already due has the same effect, since `egress`/`poll` never run.
   Scenario: the driver's control channel closes (driver restart, or the driver exits 20 to 24 and the network is
   marked down): the PEER_CLOSED event sets `more`, and `service::run` then calls `port_wait(deadline = now)` in a
   tight loop until the next attach; with the network down that is forever, one hart at 100%.
   Fix: set `self.more = false` on the detached return (the 10 ms poll then applies), and run `net.poll` there.

4. **Medium. The doorbell's "ring was empty before this publish" rule loses wakeups; the loom/shuttle model starts
   from an empty ring and cannot see it.** `must_signal` signals only if `was_empty` (`netring/src/lib.rs:200-203`).
   Interleaving: ring holds A; producer samples `was_empty = false`; consumer pops A, `announce_waiting` finds the
   ring empty and sleeps; producer pushes B and does not signal. Reproduced with the committed helpers under
   shuttle by pre-filling one entry (scratch crate, not in the repo). The real callers widen the window:
   `netdrv` samples at the top of `work()` over two rings (`netdrv.rs:171`), `netd` before up to 32 ingresses
   (`netd.rs:295`, `343`). `netd`'s `TxDev` updates a `was_empty` copy that nobody reads (`netd.rs:121-123`, `359`).
   The cost is bounded by the 10 ms safety poll, so this is latency, but `doorbell_concurrency.rs` and NET-SPEC 5.5
   claim a lost wakeup is impossible. Also the model exercises `announce_waiting` on one ring, while `netdrv::sleep`
   hand-rolls the handshake over two rings and the device (`netdrv.rs:325-334`).
   Fix: drop the `was_empty` condition (signal whenever the waiting flag reads 1 after the fence; the consumer
   clears the flag on waking, so suppression still works). Add the pre-filled case and a two-ring case to the model.

5. **Medium. `netd` is handed the registry root with every right.** The suite gives `netsup`
   `root.clone_conn(prt::ALL)` (`net_tests.rs:529`) and `netsup` clones it with `rights::ALL` for each `netd`
   (`netsup.rs:577`). NET-SPEC 4.1 gives `netd` "PUBLISH for the three names". `netd` parses hostile packets; if it
   is compromised it can open every service and publish over any stale name. T87 (8) records only that the
   connection is cloned. Fix: give `netd` a connection limited to `net`, `net-priv`, `net-config` with PUBLISH (a
   view, if the registry can publish through one), or record the ambient authority in `TIDY-UP.md`.

6. **Medium. A released claim revokes nothing, and N3 is not enforced by rights.**
   (a) `Net::release` resets the device and closes `devmgr`'s own DMA handles (`devmgr.rs:132-140`), but the
   claimant's duplicates of the MMIO VMO, the interrupt and the DMA VMOs (`Rights::SAME`, `devmgr.rs:343-354`) stay
   valid. Scenario: `netsup` is killed without its children (the suite does exactly this, `net_tests.rs:209`, `598`):
   until they notice, `netdrv` still holds the register page while a second claimant gets the same device with new
   DMA memory; an ex-claimant that keeps its handles can reprogram the device or acknowledge the new driver's
   interrupts. A holder of a `devmgr` connection can also claim, keep the handles, drop the connection and claim
   again: 130 DMA pages stay pinned each round, charged to `devmgr` (T84), and the 1024-page budget is gone after
   seven rounds.
   (b) `netdrv` gets the pool VMOs with `Rights::SAME` (`netsup.rs:124-125`), so it can map both pools; NET3 is
   listed as holding "by construction" and the spec's check (inspect the driver's address space) is not written.
   `vmo_phys_addr` needs only DMA. Fix (b): duplicate the pools for the driver with DMA and TRANSFER only, and test
   that a map is refused. Fix (a): `devmgr` keeps no way to revoke today; record it in `TIDY-UP.md`, and have
   `netsup` put its children in a job it kills on exit.

7. **Medium. One client can exhaust the stack's 256-connection pool.** Every forwarded open becomes a new account
   of 32 connections under the root (`netd.rs:722-738`). A program whose view holds `/svc/net` opens eight service
   connections and fills each: all 256 pool places are taken and `dhcpc`, the configure class and every other
   client get `Quota` or a silently closed connection. NET7 ("one account cannot exhaust another's") holds per
   account only. Fix: one parent account per class with its own limit (so `net` cannot starve `net-priv` and
   `net-config`), and a cap on service connections per listener; record the missing client identity.

8. **Medium. The generation is read from memory the stack can write.** A new driver computes
   `load64(GENERATION) + 1` from the ring VMO (`netdrv.rs:497`), which `netd` maps read-write and which outlives
   both. Scenario: a compromised `netd` stores `u64::MAX` (or any huge value) and dies; the next driver wraps to 0
   (or panics on overflow in a checked build), the new `netd` refuses READY{0} as not newer (`netd.rs:193`) and
   never attaches, across every later restart. Fix: `netsup` owns the generation and passes it in the driver's
   startup message; the header copy is informational.

9. **Medium. Restart accounting counts exits that are consequences, and "down" is partial.**
   (a) When `netd` dies the driver exits by itself with 31 (`netdrv.rs:317`) and `dhcpc` with 8 (`dhcpc.rs`, last
   loop). `dhcpc`'s exit always counts as its own restart; the driver's counts too if its event is dequeued before
   `netd`'s (`netsup.rs:417-452`). One stack crash costs two or three of the overall six.
   (b) A `netd` restart ignores the delay (`netsup.rs:456-481`), so the 250 ms and 1 s steps never apply to it.
   (c) `pending` restarts still run after `down` is set (`netsup.rs:383-409`).
   (d) Down closes nothing: `netd` keeps its listeners, so the registry never answers UNAVAILABLE (NET-SPEC 9.1,
   Q14's "for good" is not checked). A failed `spawn_dhcpc` sets `down` without printing `##NETSUP down`.
   Fix: do not count exits 31 and 8 that follow a `netd` death; apply the delay; clear `pending` on down; kill
   `netd` (or document the deviation in T87).

10. **Low. Control-channel violations in `netd` detach without telling the driver.** A second READY, a stale
    generation or an undecodable message calls `detach()` only (`netd.rs:193-198`, `215-218`); only ring violations
    send DETACH (`netd.rs:379-387`). The driver stays up believing it is attached, nobody restarts it, and a driver
    that never sends READY is never noticed either. Fix: use `violation()` in those branches; have `netsup` time out
    an attach.

11. **Low. A driver-only restart can race a stack that is mid-pass.** `netd` checks `STATE` and the generation once
    at the top of `pump` (`netd.rs:262`) and then writes ring indices; the new driver stores `STATE = NONE` and later
    zeroes the indices (`netdrv.rs:469`, `494`). If `netd` is preempted in between for the length of the driver's
    start, its stale store (a consumer index, or a push) lands after the reset; the next generation then sees
    nonsense indices and ends in another violation restart. Recovers, but spends restart budget. Fix: `netsup` starts
    the new driver only after `netd` acknowledged the new control channel.

12. **Low. `netsup`'s control channel and error paths.** The message length is never checked (`netsup.rs:491-509`:
    a short message is executed with the previous message's bytes); a message over 32 bytes or with a handle is never
    read, the level-triggered binding stays ready and the loop spins; any `child` other than 0 or 1 means `dhcpc`.
    `claim` indexes `hs[4]` on the flag alone (`netsup.rs:220`). `spawn_netd`, `stack_handles`, `spawn_dhcpc` and
    `restart_both` leak the handles made so far on their early returns (`netsup.rs:171-185`, `573-605`, `629-644`,
    `670-672`). Only the launcher and resource exhaustion reach these.

13. **Low. `netdrv` robustness.** The three `vmo_phys_addr` results and the `port_bind`s are used unchecked
    (`netdrv.rs:460-464`, `507-511`): a handle without DMA would program the device with address 0. `tx_ready` has
    no minimum length, so a 0-byte frame is handed to the device (`validate`, `netring/src/lib.rs:219-230`).
    `num_buffers` is not checked (T87 (1)).

14. **Low. Protocol details that differ from NET-SPEC 7.** Any non-zero `oflags` makes the endpoint fully privileged
    (`netd.rs:506`), so BROADCAST alone also grants source 0.0.0.0; the request header's `flags` are ignored
    (`netd.rs:462`); a send of the wrong kind is a `SendFailed` notice, not a violation (`netcore` `NoSuchEndpoint`);
    `Echo::ping` fails on a `SendFailed` notice for any cookie, so a late NoRoute for an earlier ping fails the
    current one (`rt/src/net.rs:364-368`). No escalation between classes follows from any of these.

15. **Test quality.**
    * The harness passes when the network tests skip: every test returns Ok on "no network device", and
      `net_problems` only looks if `s8: udpecho ready` was printed (`os_boot_test.py:407-425`). Unlike the disk,
      nothing requires the marker when `OS_NET` is on. A lost `-device` flag turns all eight tests into passes.
    * The capture check is skipped if the file is missing and checks checksums only. Q5's presence and count checks,
      "no frame over 1514, no fragment", and the "no new DISCOVER" checks of Q12 and Q13 are not written. Q12's
      in-guest check (`configured` after reconnect, `net_tests.rs:1157-1162`) cannot tell the blob from a restarted
      `dhcpc`.
    * `Net::close` and `Full::close` discard `job_use_settles` (`net_tests.rs:227-228`, `607`): the "nothing left
      behind" check cannot fail there.
    * Marked covered but not: NET1 in QEMU (no slot accounting anywhere), NET3 (finding 6b), NET4 for the driver
      side (no `fault-bad-slot-tx`; `netdrv`'s validation runs in no test), NET6 "or dying" (only a clean close),
      Q13's renewal. `netd`'s receive state check is vacuous (`DeviceHas` to `StackHas` always succeeds,
      `netd.rs:309`). None of these is in T87 (6).
    * `start_full_opts` waits a fixed 1.5 s for `netsup` not to exit (`net_tests.rs:554`), seven times per boot:
      about 10 s of the smoke budget. `free_udp_port` can collide between parallel boots.
    * Independence is good where it exists: slirp's ARP, ICMP and DHCP, the host's UDP stack with a same-address
      check, the checksum checker with its self-test.

## Checked and found sound

* **Ring arithmetic.** Indices only wrap through `wrapping_sub`; every entry address is reduced modulo 128; a
  count above the capacity is `BadIndices` on pop and `RingOverflow` on push; a peer rewriting either index gets a
  violation or a drop, never an out-of-range access. `pop` clamps a length word above 16 bits so it fails
  `validate`. `is_empty` treats nonsense indices as non-empty, so the consumer drains and reports them.
* **TOCTOU.** `netd` copies a frame out of the receive slot once and parses the copy; each ring entry is read
  once; the driver never reads packet memory. Slot and length bounds keep every access inside its 2048-byte slot.
* **Driver against the stack.** `rx_free` accepts only a slot the driver published; `tx_ready` only a slot the
  stack owns; `tx_done` is produced once per completion; descriptors per slot are static, so outstanding transmits
  cannot exceed the queue. Device ids from the used rings are bounded and state-checked.
* **Pool rights.** The stack's receive pool duplicate is READ, MAP, TRANSFER; the transmit pool adds WRITE; neither
  has DMA or DUPLICATE; the loopback test checks a writable map and `vmo_phys_addr` are refused. Event rights match
  NET-SPEC 5.5.
* **Classes.** The class comes only from the listener a forwarded open arrived on; `Open` is refused for the
  configure class, flags and ports below 1024 for the normal class, configuration and the ARP table for the other
  two. The source address is always the interface's (0.0.0.0 only for a privileged endpoint, unconfigured, to the
  limited broadcast); `local_addr` is never used as a source.
* **Handles and accounts in `netd`.** Every error path of `Open` closes the received handle; the binding is made
  before `add_conn` and undone on `Quota`; `add_conn` leaves the handle to the caller on failure, consistently
  used. Accounts are reaped when their last connection ends (`service.rs:236-247`). Connection keys and endpoint
  ids are not reused while live; echo identifiers are unique among live endpoints.
* **Datagram drop rule.** `send_datagram` never holds; `dropped` saturates and resets on the next delivery.
* **`devmgr` claim.** One claim per device, tied to the connection key; released on close, on a failed reply and at
  exit; the device is reset before the DMA handles are closed and before a new claim.
* **Stale exit events in `netsup`.** The incarnation number in the port key makes a killed predecessor's event
  harmless; the driver kill in the `netd` path is synchronous.
* **`netring::msg` and `proto::net`/`proto::devmgr` decoders.** Total, exact lengths, padding checked.
